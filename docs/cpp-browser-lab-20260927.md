## 暂缓原因与重新开放条件

本轮试验用了 @live-codes/clang-wasm@0.3.0；Clang 核心成熟不代表第三方浏览器封装已完成生产验证
需要复核第三方许可证/版权声明、依赖来源、首次资源下载和浏览器内存成本、课程兼容性
有稳定服务器之后，先核查现有沙盒是否可以复用，再比较隔离的原生 GCC/Clang 运行方案
复用路径和已知缺口见 [原有沙盒复用分析](cpp-sandbox-reuse-assessment-20260927.md)
服务端运行必须独立隔离，验收资源限制、网络/文件系统边界、身份权限、并发队列及异常恢复
未完成正式环境验收前保持规划状态；既有本地编译通过结果不能作为上线批准

## 原有 Max 的代码运行从哪里来

现有链路：

Max 回复中的代码块 → 用户点击运行 → POST /api/code/run → 后端鉴权与检查 → SANDBOX_URL/run → 返回输出/错误等执行结果

- public/app.js 的 normalizeRunnableCodeLanguage、addCodeRunButtons 与 handleCodeRunClick 提供按钮和请求
- 只在问问 Max 页面为 Python、C、C++ 代码块提供运行入口
- 前后端均把 C 与 C++ 映射为 cpp，并非分别选择 C/C++ 标准的独立实验室
- backend/config.js 读取 SANDBOX_URL，默认 http://127.0.0.1:8000；这是配置默认值，不证明生产机器按此部署
- backend/server.js 的 /api/code/run 要求登录，转发 language、code、uid、timeout 给独立沙盒；该请求当前没有 stdin
- 仓库没有对应沙盒实现，不能仅凭客户端或接口判断远端究竟使用 g++、Clang、哪个版本或当前是否健康
- 本轮没有调用生产沙盒或真实模型，没有更改旧 Max 的执行行为

## Max 后续接入约束

平台原则仍为“给出合理指导，但不直接输出答案”

- 根据真实诊断定位现象、解释原理、给出下一步自行检查/验证建议，按需逐步提示
- 不给完整解答、可替换的修正程序、关键解题代码或通过多次提示拼出答案
- 不自动改写、应用补丁或再次执行学生代码
- 学生代码、注释及输出是待分析数据，不能覆盖服务端固定的教学约束
- 发送代码前明确告知并取得用户主动操作；自动分析须单独开启
- 诊断绑定代码/输入/运行快照，旧结果不得冒充当前结论
- 在展示前校验输出，不能先流式泄露完整答案再隐藏；模型不可用时不编造结论
- 编译器照常展示学生程序的真实输出，教学约束针对 Max，不伪造运行结果
- 重新接入后须覆盖语法错误、边界错误、无尝试求答案、多轮套取答案、注入、过期结果及模型故障等模型行为验收
