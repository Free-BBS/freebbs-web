# 监管 Agent 的独立 API 设置

管理员进入 **系统设置 → 模型与密钥 → 监管 Agent**，可以修改 API Base URL、API Key、文字模型和图片模型。上方的“问问 MAX”仍使用原有设置，两套配置与密钥分别保存。

## 本次更换无问 Key

部署本次代码后，在监管区域填写：

| 字段         | 值                                    |
| ------------ | ------------------------------------- |
| API Base URL | `https://cloud.infini-ai.com/maas/v1` |
| 文字审核模型 | `qwen3.6-27b`                         |
| 图片审核模型 | `kimi-k2.6`                           |
| 新 API Key   | 在网页输入新的无问 Key                |

保存后，新领取的审核任务使用新配置，不需要重启后端。正在处理的任务继续使用开始时的配置版本，文字和图片不会混用不同版本。

首次部署不会复制 MAX 密钥。没有填写监管 Key 时不会调用 MAX 渠道，也不能在工作台新开启自动审核；内容仍可人工处理。若原自动审核已在运行，请在部署前暂停，并在填写新配置、用虚构内容验证后恢复。原有审核总开关、私有目录、负责人权限和工作台暂停状态继续生效；保存 API 设置不会开启审核或更改这些开关。

已配置后，Key 留空表示保留原监管 Key；输入新 Key 表示替换。清除按钮只删除监管 Key。已保存的 Key 不回显，仅显示是否配置和尾号。更换地址时必须同时填写该地址对应的新 Key，防止旧凭据被发送给其他平台。不要把 Key 提交到 Git、截图或聊天记录。

## 以后更换平台或模型

地址填写平台提供的 HTTPS 基础地址（通常以 `/v1` 结束），不要填写完整的 `/chat/completions` 路径。服务会在基础地址后追加 `/chat/completions`。模型填写平台提供的准确模型 ID。

支持兼容 Chat Completions 的接口：文字和图片请求均为非流式 JSON，图片使用 `image_url` data URL，响应须满足现有审核结构和证据校验。无问现有模型保留对应请求参数；其他平台采用通用 `json_object` 参数，不发送无问专属的思考参数。地址可配置不代表任意平台都兼容；供应商要求不同协议或特殊参数时，仍需扩展适配器。新模型投入自动审核前，使用虚构样例检查普通文字、需人工处理的内容、正常与不可读图片、超时及错误响应。网络和格式错误不会自动放行内容。

仅接受公网 HTTPS 地址；禁止本地/私网地址、内嵌凭据、查询参数和重定向，连接时再次验证并固定 DNS 结果。已有供应商核对要求保持生效，换平台时需重新核对实际数据处理安排。

## 维护说明

- 设置复用已有 `app_settings` 和 `system_secret_settings` 表，使用独立的 `moderation_*` 键，无新增数据库表。密钥使用已有服务器加密密钥，但认证上下文与 MAX 密钥分离。
- `GET/PATCH /api/admin/system-settings/moderation` 读取/更新独立设置；`DELETE /api/admin/system-settings/moderation/api-key` 清除监管 Key。全部要求管理员权限，响应只返回公开配置及密钥状态。
- `DISCUSSION_MODERATION_AUTO_MODEL` 与 `DISCUSSION_MODERATION_IMAGE_MODEL` 仅在尚未保存对应网页设置时作为默认值。原 `DISCUSSION_MODERATION_BACKUP_MODEL` 不会触发自动备用调用；工作台显示实际独立文字/图片模型。
- 独立设置有自己的版本号。自动任务领取时记录文字/图片模型和版本，完成时根据该任务记录重新验证结果，配置更换不会改变已领取任务的模型依据。
- 预检查新增 `moderationApiConfigured`，只检查独立 Key 记录是否存在，不读取明文、不调用供应商。自动审核就绪要求此项为 `true`；它不能证明 Key 有效或模型已通过验收。
- 回退前暂停自动审核。旧版本会读取 MAX 的共享渠道，不能将代码回退视为继续使用新监管 Key；需要人工确认后再恢复。
