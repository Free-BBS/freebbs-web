# 输出结构与规则应用约定 v2

当前输出约定为 `freebbs-moderation-contract-2026-10-11-v2`，规则版本仍为 `freebbs-policy-2026-10-09-v3`。本次不修改规则库、样例预期、模型选择或自动发布权限。

## 已确认的问题

2026-10-11 的 4 条样例、2 个模型复测完成 8 次请求：5 个结果通过本地校验，3 个结果与预期标签一致，2 个标签差异，3 个校验失败。固定样例结果不是模型总体准确率。

- GLM 的隐私样例为 `high_risk_without_block`：输出高风险，但所选规则中没有允许拦截的禁止项。失败的完整判断未保留，不能断言它具体引用了哪条规则。
- Kimi 的隐私样例识别了公开他人学号及宿舍信息的风险，已建议人工复核，但漏列规则和类别。`隐私-001` 本身将授权及公开必要性不明列为需核查条件，不能因尚未证明违法而不列该规则。
- GLM 的非即时求助选择了紧急关怀，级别偏高；它仍正确区分了心理求助与违规。
- Kimi 的正常性健康教育和非即时求助均出现顶层字段校验失败，旧批测诊断不足以指出具体字段。

随后以相同客户端、请求参数和两个固定虚构样例再请求 Kimi：性健康样例通过结构与规则关系校验，耗时 2678 ms；非即时求助仍失败，耗时 1646 ms。失败响应为 HTTP 200、正常结束、完整且可解析的 JSON，但七个必需顶层字段全部缺失，另外出现五个未知顶层字段。

这只能证明本次响应没有遵守输出结构。诊断没有保存未知字段名、字段值或模型正文，不能推断它翻译了字段、回显了输入或返回了某个特定对象。性健康样例此次成功也不能恢复上次失败原因；这次诊断不提供完整语义准确性评价。

## 修订方式

1. 对 `json_object` 模型，在规则目录之后追加与客户端 `SCHEMA` 同源的完整 JSON Schema，明确固定字段名、嵌套对象、类型、枚举和数量限制。说明它是输出约束，不是需要回显的输入或规则文本。不提供容易被照抄的“默认通过”模板。
2. Kimi K2.6 仍使用 `response_format.type=json_object`；GLM 等原有 `json_schema` 型号继续使用原请求参数，不因本次问题猜测接口能力、切换模式或自动重试。[无问结构化输出说明](https://docs.infini-ai.com/gen-studio/api/text-generation/tutorial-structured-output.html)区分 JSON 可解析、结构合规和业务正确，并要求应用侧校验。
3. 明确人工复核规则可以描述“需要核实的风险情形”。若规则条件本就包含授权不明，满足条件时应列出该规则、对应类别和具体不确定项，而非等待负责人证明违规后才列规则。仅有要求人工复核的规则时不能输出高风险。
4. 按现有规则区分需关注与紧急关怀：非即时自伤想法不能单独替代明确近期实施、正在行动或已经受伤的线索；同时不能因一句“没有计划”忽略同帖独立存在的紧急线索。此处仅说明审核规则应用，不诊断或断言医学安全。
5. 失败报告可保留七个固定字段中缺少哪些、未知额外字段的数量；不保存未知字段名、值、模型正文、原始异常或密钥。报告用中文展示，并兼容已知 v1 诊断版本。未知诊断版本仍不接受。

严格校验不变。多字段、少字段、非法规则、无效证据和矛盾标签仍失败；不根据中文别名猜字段、不自动补值、不改变模型结论、不修补 JSON。心理关怀不计违规，异常结果不作为通过，所有发布仍由负责人决定。

## 更新与验证

本次修改后端代码，工作台需要重启测试后端才能使用新约定；CLI 每次启动读取当前文件。没有依赖安装、配置修改或数据库迁移。

安装更新包后，先预览包内的 `moderation-contract-check.json`。它与上一轮使用相同四条虚构样例：第三方隐私、性健康教育、关注关怀、紧急关怀。预览应显示新约定版本、4 条样例、默认 GLM/Kimi 共 8 次计划请求。

添加 `--run` 才调用模型。比较仍使用原样例预期，不把修改后的标签当作改善。新增 Schema 提示会增加部分模型的输入长度；实际成功率、语义表现和耗时需要在台式机重新验证，离线测试不能证明真实模型已经稳定。

批测产生新目录与 `comparison.json`。若出现字段错误，新报告直接包含缺失字段与额外字段数，不必先重跑旧独立诊断包。旧诊断脚本固定检查 v1 提交与输出版本，不适用于更新后的代码。
