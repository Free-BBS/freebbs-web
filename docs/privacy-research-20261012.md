# FreeBBS 全站隐私政策调研与数据处理清单

调研日期：2026 年 10 月 12 日。用途：供网站运营方确定隐私政策范围、补齐处理规则和安排实现；本文件是内部调研，不是已生效的对外政策，也不代表正式环境合规验收。

FreeBBS 的政策需要覆盖社区、AI 服务、学习工作台和发展板块，而不只是讨论区审核。优先解决的问题是：运营主体与联系渠道、管理员访问 AI 对话的范围、外部模型及其下游服务、删除与保存期限、校内账号授权、动态问卷和跨模块身份关联。审核 Agent 按用户决定保留当前版本，待隐私政策及配套功能完成后再上线。

配套文件：[审核工作保存记录](moderation-handoff-privacy-first-20261012.md)、[需要确认的事项和实施任务](privacy-decisions-20261012.md)。

## 优先处理的问题

### 管理员能够导出 AI 聊天记录

`GET /api/admin/ai-dialogs/export` 在管理员鉴权后读取全部用户与对话，将姓名、学号、账号和完整消息关联输出。这是代码已确认的权限能力，不代表有人已经使用或发生泄漏。当前路由未显示单独的导出理由、二次审批或持久化导出审计步骤。

建议优先确认这项能力的目的。若日常运营不需要，可关闭全量实名导出；确有支持需要时，改为范围受限、单独权限、操作留痕和导出文件期限控制。隐私政策应如实描述保留的访问安排，不能用“只有本人可见”掩盖后台能力。

### 身份传入内部 Agent 与传入供应商是两段流程

Web 的 `buildAgentUserContext` 会把 UID、用户名、姓名、学号等交给本地 Agent；可信请求头也包含 UID、学号。Info bridge 将认证上下文作为隐藏于模型的内部身份传递。不能仅看到这些内部字段就断言全部外发给模型，也不能断言绝不外发。

Agent 的模型客户端发送 messages 和视觉图片，图像生成还支持独立 base URL。后续应使用虚构数据检查每条实际调用链的最终请求：普通问答、课程 RAG、评论回复、日程规划、文件逐页视觉、图像生成、Info 查询。原则是内部鉴权使用稳定 ID，模型不需要的实名字段不进入提示内容。

### 无问芯穹有存储与下游处理安排

现行官方政策的 MaaS 部分说明，输入输出加密隔离存储，并接入阿里云、网易内容安全服务；合作方部分也列出输入、输出和请求标识。这是供应商公开规则，不等于已经核实本站套餐的具体执行方式。[无问芯穹隐私政策第二部分及合作方部分](https://docs.infini-ai.com/legal/privacy.html)

上线前向供应商核实：签约主体、处理角色、API 适用条款、输入输出及日志保留期、训练使用、调试访问、下游受托方、数据地域和删除申请方式。Qwen/Kimi/GLM 的模型名称不能直接当作数据接收方清单；由谁实际托管和转发决定接收方。供应商控制台的验证码等功能也不能直接写成本网站向学生收集的数据。

### 30 天清理不等于全站或全部审核数据消失

审核代码到期清除原稿证据、部分理由与任务结果，并清理相应 AI 记录；提交 ID、作者关联、状态等骨架字段可能仍在表中。正常发布内容和仍在使用的图片不随证据到期删除。导出的回归文件、备份和供应商副本也不由站内清理函数统一控制。

学习分析已有独立 180 天事件清理。AI 对话、完成上传的私有文档、软删除帖子、问卷、白名单与发展板块数据尚不能统一宣称固定到期自动删除。政策需按类别给期限或确定方法，并落实清理路径。

### 软删除、注销和跨库清理需要统一设计

当前可确认管理员删除账号接口；本次检索未发现全站自助注销流程。帖子删除是状态更新，通常不立即擦除数据库正文。主库外键级联不覆盖所有文件、development 数据库、邮件、备份、供应商副本及已导出的文件。

需要一张关联删除清单，并提供可实际使用的申请渠道。短期可先建立人工处理流程，不必为了发布政策仓促实现“一键删除全部”，但不能承诺代码尚未支持的结果。恢复备份后也应重新应用已完成的删除或撤回记录。

### 图片上传的告知时点早于最终发布

讨论图片通常在最终提交帖子前已上传；Max 附件也可能在点击发送前进入服务器。当前审核确认框控制最终提交和送审，不能代替上传阶段的告知。全站政策和必要的场景提示应在第一次收集之前可查阅，后续再根据外发或公开展示发生的时点处理相应确认。

普通上传路由静态提供文件，课程文件和 Max 私有文档有特定拦截，审核图片采用另一套私有访问路径。应专门检查“帖子已隐藏/删除，但旧图片链接仍可访问”的边界，不把随机文件名当作权限控制。

### 心理与政治话题只用于内容处理

心理表述可能包含健康、就诊、药物、自伤风险等敏感信息；一般情绪表达不应自动成为诊断。政治话题命中是审核路由信号，不应据此建立个人立场标签。建议限定负责人访问、通知只给必要信息，不将这些分类复用于成绩、评优、组织选拔或其他个人画像。

明确自伤危险的紧急处置另设流程，限定触发条件、接收人、披露范围和记录；不能把所有“心理问题”都默认转发给教师、家长或学校部门。一般人工复核与紧急保护属于不同场景。

### 未成年人和被帖子提及的人仍在政策范围内

用户已说明主要是高校学生、可能有少量未成年人，且不面向未满 14 周岁用户。无需为了模板强行新增儿童注册流程，但仍要处理 14—17 岁用户和误收更低年龄信息的情况，不能写“全体用户均为成年人”。帖子、图片、名单和问卷可能包含没有本站账号的其他人；白名单注册不排除这些人的权益。

### 社区公约已有审核描述但与新机制不完全一致

注册页现有公约写明前台昵称、后台实名，并描述 Agent 提示及人工处理。它没有替代全站数据政策，且“仅建议”的说法需要与自动放行、转人工、撤回行为同步更新。不能把旧版公约的接受记录直接迁移为用户已同意新的外部模型处理。

## 法律依据与落地要求

下表列出与这次政策最相关的核对点；具体处理的法律基础仍需结合实际用途和协议确定。

| 官方依据 | 对本站的直接工作要求 |
| --- | --- |
| [个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)，第 13—17、21、23、24、28—31、44—57 条 | 按场景确定处理基础；说明目的、字段、期限、权利渠道；区分委托与对外提供，处理敏感信息和必要的单独同意；保留人工复核、影响评估与事件处置安排 |
| 同法第 55—56 条 | 审核外部委托、敏感信息及自动化决策等适用情形，应事先开展影响评估；评估报告和处理情况记录至少保存三年。这不表示所有帖子原稿必须保存三年 |
| [网络数据安全管理条例](https://app.www.gov.cn/govdata/gov/202409/30/520076/article.html)，第 20—24 条 | 政策应醒目、易查，收集和提供情况采用清单；列明期限或确定方法、退出及权利途径；不以误导或频繁催促获取同意 |
| [网络安全法现行修正版](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)，第 23 条 | 相关网络安全日志按规定留存不少于六个月，应与 30 天审核证据分开设计。不能据此把全部聊天正文当成必需安全日志长期保存 |

全站政策可以作为主要告知载体，发布框采用用户选定的简短句子并提供明显入口。但把详细信息放进长文不自动满足所有场景的同意要求。对于已有用户新增的数据用途、敏感处理或依法需单独同意的情形，要设计对应机制。不要照搬其他平台“继续使用即同意所有处理”的文字。
