# 独立图片审核测试 v4：不可读及空白图片交人工

这是台式机隔离环境的独立评测程序，只有显式 `--run` 时才调用无问 API。先安装配套网站更新，再运行网站仓库中的新版脚本；评测本身无需停止服务或迁移数据库。评测程序不发帖、不自动发布、不修改审核记录、模型目录、配置或数据库，也不会启用网站的含图自动审核。

本版将不可读图片和空白图片统一设为发布前暂缓、交负责人审核，空白本身不算违规。无文字但清晰的正常照片不是空白，仍按实际内容审核。沿用 v3 合成图片资产及哈希，更新后的处置预期由 v4 评测代码提供；不要继续用旧 v3 评测脚本或旧报告中的通过预期验收新规则。

文字审核继续使用网站已配置的 Qwen；本包默认只测试图片候选模型 Kimi K2.6。更改本次评测的 `--models` 参数不会更改网站的默认模型。本轮已加强图片试审提示词，并增加本地理由核查；这不意味着真实模型效果已经修好，须用台式机的实际 API 报告验收。

## 样例与请求

每个模型先执行两项随机图片识别检查：八位字母数字代码、红色圆形/蓝色正方形/绿色三角形计数。答案只在实际图片像素和本地评分信息中，文本提示、文件名、图片元数据均不包含答案。若选多个模型，它们使用同一轮相同图片。图片检查失败的模型跳过后续审核测试，其他已选择的模型继续测试。

完整测试包含 31 条：2 条视觉检查及 29 条内容审核。所有素材均为本地合成。风险信息主要位于图片，正文仅为中性的附图提示；纯白背景对照明确说明是在测试背景图，也应按新的空白图片规则交人工。不把图片文字参考答案、预期分类或规则编号发送给模型。

| 内容分组           | 条数 | 核查内容                                                                                               |
| ------------------ | ---: | ------------------------------------------------------------------------------------------------------ |
| 原有基线及空白对照 |   11 | 正常建议、骚扰、威胁、诈骗、本人资料、反骚扰求助、反诈、性健康科普、图片指令、多图、纯白背景交人工对照 |
| 隐私对照           |    4 | 本人资料、他人资料、两者混合、机构公开办公信息                                                         |
| 复杂截图           |    4 | 正常讨论、实际号召骚扰、引用取证求助、明确标识的小说对白                                               |
| 小字图片           |    4 | 正常内容、诈骗招募、本人资料、反诈提醒；正文为 18 像素字号                                             |
| 模糊图片           |    6 | 轻度模糊正常/违规对照、两张原有严重模糊图、两张仍可见文字区域但无法辨读的新图                          |

默认运行 `followup` 范围，最多 21 次 API 请求（Kimi 单模型）：2 项视觉检查、3 条明确违规对照、4 条隐私对照、4 张不可读图、1 张纯白图、7 条非空正常对照。正常对照保留校园建议、性健康科普、机构办公信息、引用取证求助、小说、防骗和轻度模糊建议。固定选取这些样例，不在台式机读取上轮报告决定内容。

可选 `--models kimi-k2.6,qwen3.6-27b` 比较两者，默认复测范围最多 42 次；选择完整范围则每模型 31 次、双模型 62 次。全部串行，每条每模型一次，不自动重试。某模型连续三次接口或输出失败则跳过其剩余项。每次请求超时 45 秒；图片耗时与短文字 3～5 秒目标分别记录。

可选范围始终包含两项视觉检查，下表次数均按单模型计算：

| 参数                      | 最多请求次数 | 用途                               |
| ------------------------- | -----------: | ---------------------------------- |
| 默认或 `--suite followup` |           21 | 问题复测与正常对照                 |
| `--suite full`            |           31 | 全量复测                           |
| `--suite privacy`         |            7 | 原有本人资料样例与四条隐私对照     |
| `--suite challenging`     |           16 | 复杂截图、小字和模糊图片           |
| `--suite probe`           |            2 | 仅检查图片读取，不代表内容审核通过 |

本套素材覆盖合成文字卡片、合成论坛截图、基础视觉及多图，没有自然色情或暴力照片。通过本轮不代表这些画面、手写字、真实世界复杂照片或图片脱敏已经验收。PNG 已随包生成，台式机运行不需要安装中文字体。

## 台式机操作

先完成配套网站更新并保留自动队列暂停，再运行仓库中的新版脚本。图片资产清单仍是 v3，其校验值和转录用于验证素材完整性；实际处置预期使用新版代码。保留已有测试包与报告，无需重复解压或覆盖 v3 测试包。

预览（不读取配置/数据库、不调用 API、不写报告）：

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-image-evaluation.js'
```

应输出 `event: preview`、`suite: followup`、`caseCount: 21`、`plannedCalls: 21`，模型为 `kimi-k2.6`。预览不读取 API 密钥或数据库，也不写报告。若报错，先保留报错，不继续执行。

正式运行（可能产生 API 费用）：

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-image-evaluation.js' --run
```

脚本仅读取本机 `web-test\config.json` 与测试库已有的加密模型设置。数据库必须为 `127.0.0.1:3307/free_bbs`，相关测试开关必须开启。API Key 不需要填写到命令行，不写入报告。仓库内运行直接使用同一版本的审核代码；此前独立测试包中的文件哈希固定为旧网站版本，不能代替此处新版脚本。

若只想核查隐私理由，可先在预览命令后添加 `--suite privacy`，核对 7 次请求，再添加 `--run` 执行。若要比较两种图片模型，在同一命令后添加 `--models 'kimi-k2.6,qwen3.6-27b'`，默认范围应显示 42 次请求；再显式添加 `--suite full` 才是完整双模型 62 次。

报告保存到 `F:\FreeBBS-Test\moderation-image-results-v4\<本次时间与随机编号>\`：

- `comparison.json`：模型结果、预期、差异、诊断、最终建议处置、理由与规则依据；`suiteVersion` 和 `qualityVersion` 均为 v4，报告格式仍兼容 v3。可发送此文件分析，不要误发旧报告。
- `report.html`：本地浏览器打开，展开每个样例即可查看输入图片与结果。
- `images/`：本轮合成图片，查看 HTML 时与其放在同一目录。

结束时命令行会打印报告的完整路径。`Ctrl+C` 停止安排后续请求，当前请求结束后保留已完成报告。退出码 0 表示本轮全部与预期一致，2 表示有需要复核的差异，1 表示接口/输出失败、跳过或准备错误，130 表示中断；都不能当作生产上线许可。

## 如何读报告

图片识别、审核标签、建议处置和证据质量分别对照。API 返回 200 并不代表图片已读到，也不代表输出可用于审核。超时、HTTP 400、非正常结束、结构不符都记为失败，不记为通过或正常内容。

`modelPolicyDecision` 保留模型原始建议，`contentPolicyDecision` 是应用本地图片可读性兜底后的处置，两者分开显示。`policyDecision` 仍保留独立评测“含图交人工、不自动发布”的边界。程序没有发帖操作。模型建议通过被本地改为暂缓时，报告仍保留模型的原始差异。

标题/正文证据必须来自对应原文，图片证据必须来自该张图片的模型观察；后者只能证明输出自洽，所以还会与本地已知的合成图片文字逐张对照。普通图片忽略空白标点后比较文字；复杂截图核对关键片段，允许不同的版面阅读顺序。差异记录在 `transcriptionIssues`，没有出现在该图参考文字中的引用记录在 `groundingIssues`。这些线索需人工核查，文字识别差异不直接算漏判。

两条诈骗招募样例明确允许两种完整组合：“诈骗-001 / fraud”，或“诈骗-001 + 违法交易-001 / fraud + illegal_activity”，处置均应拦截。其他规则、类别或不一致的规则类别配对仍会标出差异，不能随意增加命中项。报告记录 `acceptedVariantMatched`，不把合理的附加违法活动依据算作误判。

隐私理由单独核查三方面，不会通过删除模型原始结果掩盖差异：

- **本人/他人区分**：仅本人完整编号或寝室信息对应“隐私-003”；他人信息对应“隐私-001”；混合信息分别判断；机构公开办公资料不直接当作个人隐私。
- **规则之外的要求**：不能无依据增加“必须经学校或管理方许可才能公开本人信息”的条件。
- **理由复述信息值**：一般理由、核查问题等应描述信息类型，避免重复完整虚构姓名、学号或精确门牌。模型的原始图片文字观察和最小必要证据仍保留虚构值，便于核对是否真正看对图片，不把这两类内容与一般理由混淆。

这些核查采用本地启发式，属于复核线索，不能穷尽事实、语义或所有同义改写。出现标记后仍需结合图片、模型理由和规则人工判断。`assessment` 与 `imageObservations` 保留模型原始输出用于评分；`displayAssessment` 与 `displayObservations` 是控制隐私复述后的展示副本，二者均保留。展示脱敏不会抵消原始模型理由的问题。

四张不可读控制图的正文已不可可靠辨读，本地不提供完整原文作为 OCR 评分目标。其中两张旧图接近空白，另两张新图仍看得出文字区域。预期模型明确表达识别不确定并暂缓交人工；“图片无可见内容，无法核实附图实际信息”等表述也算有效可读性说明，不强求出现“模糊”二字。身份不确定、仅说图像清晰或仅说背景空白，不自动算作读图困难。

纯白背景对照没有待辨读正文，仍按本站规则暂缓发布并交人工；负责人查看后可决定发布。空白无需假装存在无法辨认的文字或套用违规规则，理由说明空白，待核查事项可写明请负责人确认附件是否完整及是否允许发布。无文字但画面清晰的正常照片并不因此转人工。如果模型输出似乎读出了不可读图的内容，要实际打开原图核查控制图难度与判断依据，不能只据标签机械判错。轻度模糊的正常和违规对照仍要求识别实际内容。

`suspectedMisses` 表示可读且非空白样例预期需要拦截或人工审核、最终内容处置却允许的有效结果；`unreadableAllowed` / `localUnreadableAllowed` 分别记录模型与本地兜底后对不可读图的放行数，`blankAllowed` / `localBlankAllowed` 同样单列空白图。`normalEscalations` 表示预期正常、最终内容处置却暂缓或拦截，空白图交人工不再计作误拦。它们是固定样例上的核查线索，不是实际网站的已发布数量，也不是完整准确率。理由语义、角色、例外和事实不能只靠自动匹配验收。

## 后续顺序

图片自动审核代码通过另一个网站更新包部署。安装后先保持队列暂停，运行本包默认 21 项定向复测并核查报告，再由管理员在工作台开启，使用虚构的实际含图帖子验收通知、复核与撤回。文字继续使用 Qwen，图片优先使用 Kimi。报告通过不能替代发帖流程验收；图片姓名、学号和住址的处理仍需单独核查，文字脱敏不能替代图片脱敏。

配套网站更新已加入政治内容和学生心理问题的重点人工复核：标题、正文、OCR、视觉描述中的本地线索以及已验证的模型信号触发负责人审核，在工作台与通知中突出提示，并与其他类别区分。这项机制不构成心理诊断或违法认定，也不保证识别所有相关表达；心理关怀与违规判断分开，求助本身不等于违规。独立图片测试包不会启用这项功能，需在网站升级后结合实际虚构帖子验收。

## 依据与本地校验

接口使用[无问官方视觉语言模型文档](https://docs.infini-ai.com/gen-studio/api/multimodal/tutorial-vision.html)说明的 `image_url.url` Base64 格式，固定无问域名，禁止跳转。Kimi/Qwen 都使用 JSON object 输出并在本地严格验证；不依赖目录里的历史 `vision` 开关直接判定账号能力。实际可用性以本次账号请求结果为准。

开发侧使用 mock 响应完成测试，不调用真实 API：

```text
node --test scripts/moderation-image-client.test.js scripts/moderation-image-fixtures.test.js scripts/moderation-image-quality.test.js scripts/moderation-image-evaluation.test.js
```
