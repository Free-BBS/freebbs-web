# 校验失败的模型提示进入人工复核

模型输出高风险、其他已知类别或关怀信号，即使未满足字段间的一致性要求，也应作为待核实提示供负责人查看。程序继续把它认定为失败，不转换为有效审核结论，不据此自动发布、拒绝或处罚。

## 工作台行为

- 已发起模型请求后出现 502/504，重新检查负责人权限、稿件版本、待审状态、内容摘要和材料到期时间，再将失败记录保存到原稿试审历史。请求仍返回原失败状态，同时附带独立 `reviewResult`。
- 只有完整响应正常结束、assistant 消息无拒绝或工具调用、正文能直接解析为 JSON 对象时，才抽取可识别的等级、已知风险类别、当前规则编号及关怀等级。它们均标注“尚未核实”，包括模型声称无风险的情况。
- 只保留白名单枚举，不保留失败模型的理由、证据引文、任意额外字段、未知类别、未知规则、推理文本或供应商错误正文。未知信息不会自动扩充规则库。负责人结合原稿与当前规则独立判断。
- 超时、无效 JSON、非正常结束等没有可提取提示时，显示未取得可用判断，仍保留人工审核。不会修补 JSON、改写高风险标签、重试其他模型或新增外发信息。
- 失败记录的 `assessment` 固定为空，`policyEvidence` 为空，处置固定 `hold`，`canAutomaticallyPublish` 与 `automaticPublication` 均为 `false`。待审稿本就在人工队列；本次补充失败记录的展示和留存，不新增自动通知或队列排序。
- 历史提供“记录独立人工判断”和“升级人工核查”，不能“同意机器判断”。没有人工反馈时风险判断初值为空，必须由负责人主动选择；后端同样拒绝直接同意。人工反馈不会改写原模型失败记录，也不会代替单独的通过/驳回操作。
- 沿用每稿 50 次试审、每条 20 次人工反馈的上限，以及原稿创建后 30 天到期规则；失败记录不会延长保存期限。无需数据库迁移、依赖安装或配置修改。

## 批测与验证

失败仍计入 `failed`，不纳入有效结果、标签一致率、最终处置一致率或有效结果耗时。报告将可提取的提示单列 `failedWithReviewSignal`，所有失败结果都要求人工核查。空类别、空规则或缺失等级不代表无风险。

旧报告已丢弃的模型原始内容无法离线恢复。安装本更新后发起的新测试才能保留这些提示；无需为了填补旧报告立即重复全量收费调用。本次未调整规则库、模型输出合同或测试预期，也不解决此前识别出的宿舍别称漏判、角色混淆等模型质量问题。

本地验证使用合成模型响应，不使用真实 API 密钥。覆盖信号筛选、异常仍失败、权限撤销、稿件编辑/到期/人工决定、存储失败、历史与人工纠正，以及报告统计和页面绑定。MySQL 隔离测试使用关闭网络的临时实例；浏览器测试只连接本机合成接口。
