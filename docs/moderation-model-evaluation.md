# 审核规则多模型自动化测试

用同一组虚构文字测试不同模型对 v3 规则的理解，输出中文对比报告。脚本复用工作台的审核客户端、模型目录、规则提示词和结果校验，读取台式机测试库中已保存的渠道设置和密钥，不需要再次填写 API Key。

这是离线批测工具，不更改网站审核流程。安装本次更新不需要重启网站，不新增数据库迁移、依赖或配置。

## 测试内容

- 固定规则版本：`freebbs-policy-2026-10-09-v3`。
- 完整样例 100 条：保留原有 96 条文字及标签，增加 4 条关怀语境、公共地点与个人住址、混合风险等对照样例。覆盖 28 条禁止项和 2 条关怀提示。
- 每条规则覆盖适用情形、正常表达和边界情况；保留正常批评、求助、性健康、新闻学术引用等例外。
- 小批检查（`smoke`）24 条；完整测试（`full`）100 条。保留原 12 条小批样例并增加覆盖。
- 默认模型 `glm-5.1`、`kimi-k2.6`。默认小批最多 48 次调用，完整测试最多 200 次调用。每次重新运行都是新调用，不复用上轮结果；先跑小批再跑完整会合计最多 248 次调用，可直接预览并执行完整测试。
- 全部为编造文字，预期标签为待负责人复核的初稿。模型理由仍需人工查看，标签一致不能直接当作真实审核准确率。

内置样例在 `test/fixtures/moderation-policy-v3.json`，分组、允许的替代规则组合、处置和理由核查标注在 `test/fixtures/moderation-policy-v3-manifest.json`。样例标题、正文会送审；预期答案、标注理由、分组、替代组合、处置预期、证据锚点和核查问题不会发送。虚构确认保存在元数据中，不在正文中添加“只是测试”等可能改变判断的提示。理由核查不增加裁判模型调用。

只测试文字审核，不自动发帖、改审核状态或处罚用户。图片审核、真实用户样本、脱敏识别效果及网站完整发布链路需要另外验证。

## 台式机执行

在台式机任意 PowerShell 文件夹执行以下命令。需要 MySQL 测试实例在运行，配置仍为 `F:\FreeBBS-Test\web-test\config.json`。

### 1. 先预览

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-model-evaluation.js'
```

应显示 `event: preview`、`caseCount: 24`、`plannedCalls: 48`、`qualityAnnotatedCases: 24`。这一步只验证样例，不读配置或数据库、不调用 API、不写报告。

### 2. 执行 24 条小批检查（可选）

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-model-evaluation.js' --run
```

`--run` 才会调用供应商 API，并按渠道实际计费。全程串行，每个样例每个模型只请求一次，不自动重试；可继续使用测试网站，但测试期间保持渠道设置不变。一次调用最多等待约 15 秒，连续失败会提前停止；实际时长以进度为准。

结束后末尾显示 `reportHtml` 和 `comparisonJson` 的完整路径。用资源管理器打开该目录，双击 `report.html` 查看。报告默认只显示差异和失败，可切换为“全部结果”。

### 3. 预览并运行完整测试

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-model-evaluation.js' --suite full
```

应显示 100 条样例、最多 200 次调用、100 条处置与理由标注，`qualityVersion: freebbs-evaluation-quality-2026-10-11-v1`。确认计划后执行：

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-model-evaluation.js' --suite full --run
```

建议先检查小批报告中的接口失败及明显标签问题，再花费完整测试预算。完整测试覆盖小批样例，因此会重新调用。

### 4. 选择其他模型

读取测试网站当前渠道的模型目录：

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-model-evaluation.js' --list-models
```

这一步只读本机测试库设置和网站模型目录，不解密密钥、不调用供应商。它列出网站支持选择的模型，不保证供应商账户当时具有调用权限。

将返回的模型 **ID** 用英文逗号连接传给 `--models`。一次支持 1 至 6 个不同模型；执行前统一验证所有 ID，发现无效 ID 时不会先调用其他模型。示例：

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-model-evaluation.js' --models glm-5.1,kimi-k2.6 --suite smoke --run
```

## 如何读报告

当前输出约定和安全错误诊断见[模型输出约定 v2](moderation-contract-v2.md)，[v1 文档](moderation-contract-v1.md)保留历史依据。新报告保存输出约定版本，并在失败详情中展示可用的具体错误原因、固定字段缺失和额外字段数量；不输出未知字段名或值。已知 v1 诊断保留其实际版本，旧报告没有诊断字段时仍能读取。

每次执行会在 `F:\FreeBBS-Test\moderation-model-results` 下建立新目录：

| 文件                         | 用途                                                     |
| ---------------------------- | -------------------------------------------------------- |
| `report.html`                | 无外部资源的中文交互报告，可离线打开、按模型和结果筛选   |
| `comparison.json`            | 完整对比数据，包含预期、模型输出及差异，可交给开发者分析 |
| `progress.jsonl`             | 全程逐条进度                                             |
| `model-01/report.json` 等    | 每个模型原有严格比较报告，保留原始比较口径               |
| `model-01/progress.jsonl` 等 | 每个模型进度                                             |

报告分别统计：

- **标签一致、需核查**：决定、类别集合、规则集合、关怀级别是否符合预期。合法规则重叠的完整替代组合单独计数，不改变原始严格报告；替代组合不能降低风险决定或关怀级别。
- **最终处置比较**：比较本地程序实际给出的 `allow`、`hold`、`block` 与预先标注的动作。报告中的动作只是建议，不代表真实发帖。原始标签一致但处置不同的结果仍进入默认待核查列表。
- **理由依据线索**：检查规则引文是否来自对应的标题或正文，对照关键原文锚点，并标出理由、关怀说明、待核实项和规则解释提及的预标缺失事实。词语命中只提示人工核查，不能直接判为编造；未发现线索也不代表理由语义正确。
- **正常内容被升级、风险被放过、高风险降级**：与初拟预期相比的差异提示，负责人确认前不称为已证实误报或漏报。
- **关怀级别偏低**：单独标出心理支持遗漏，避免与违规判定混淆。
- **调用失败与未完成**：独立统计，不算作模型对内容的错误判断。
- **耗时中位数、P95、5 秒内数量**：只统计获得有效结果的调用；失败次数同时展示，小样本 P95 不能代表线上性能承诺。

每条可展开正文、预期理由、预期与实际处置、触发原因、模型理由、引用证据、不确定项、关键原文和人工核查问题。语境、发言主体、否定、引用和规则例外仍需人工检查。默认列表同时显示标签差异、处置差异、理由线索、未标注和失败；不会因标签一致而隐藏另外两类问题。一次运行不能证明模型的稳定性；若需重复测量，另开一轮并保留两个报告。

三类自动差异可能重叠，`reviewRequiredResults` 对同一结果去重统计。所有有效结果仍需人工复核理由语义，此要求不等于每条都有机器发现的错误。旧自定义样例没有 `quality` 标注时显示未标注，不能视为处置和理由通过。

报告保存规则版本、样例集 SHA-256、模型 ID、时间和渠道设置修订号；若模型间设置修订号不同，会提示比较条件发生变化。分享 `comparison.json` 即可分析，不要分享 `config.json` 或密钥。报告不含密钥，但包含测试正文与模型理由；按既定一个月留存约定管理，本地报告不会由网站自动清理。

## 中断与错误

按一次 Ctrl+C 后停止安排新调用，等待当前请求结束并保存已有结果。单模型连续 3 次 API 或格式错误时停止该模型，再尝试剩余模型；配置、规则版本、报告写入及请求边界错误会停止整轮。没有自动续跑，重新执行会创建新目录并重新计费。

| 退出码 | 含义                                                     |
| ------ | -------------------------------------------------------- |
| `0`    | 完成，未发现标签、处置或理由自动核查差异；不表示语义全对 |
| `2`    | 完成，有标签、处置差异或理由线索待核查；不是脚本崩溃     |
| `1`    | 有调用或执行失败，请查看报告                             |
| `130`  | 用户中断，查看已有结果                                   |

## 规则和样例维护

修改规则后，应同步更新规则版本、样例预期和覆盖说明，再运行本地自检。脚本拒绝旧版本样例；不要只改版本号以绕过检查。先由负责人确认差异，再调整预期，不能为了提高一致比例而直接照抄模型输出。

工作台导出的自定义虚构样例可通过 `--input` 绝对路径导入；最多 100 条。指定外部 `--input` 后不自动套用内置说明文件；没有 `--manifest` 时，会测试该文件中全部样例，`smoke` 不再自动挑选 24 条。需要分组、替代预期或处置与理由核查时，另传与所有样例逐项对应的 `--manifest` 绝对路径。最大预算为 100 条 × 6 模型 = 600 次。

每条说明可包含 `quality`，其中 `expectedAction`、`actionRationale` 是预先标注的处置和理由；`evidenceAnchors` 是带 `field`、`quote`、`rationale` 的逐字原文片段；`absentFacts` 包含缺失事实的编号、说明和待核查用语；`reviewQuestions` 给出人工审查问题。新增标注严格校验，错字锚点会在读取配置和外呼之前报错。模型输出约定与业务规则版本不变；评估方法另存 `qualityVersion`，样例摘要包括这些标注。
