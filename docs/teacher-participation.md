# 教师参与入口

本轮提供教师身份、管理员分配的多门课程与正文意见入口，不增加教师专用 AI 适配，也不改变现有学生学习流程。“我管理的课程”用于查看、提出意见与阅读回复，不授予改稿或审核权。

## 老师如何进入

1. 在“关于 FREE BBS”点击“我是老师”，或直接打开 `/teachers`。
2. 已有账号：登录后查看身份信息，已核实的教师无需重复申请。尚未核实的账号可通过“申请或查看教师认证”补充机构等信息，等待管理员核实；申请表会说明认证姓名将公开显示。
3. 没有账号：联系工作人员，由管理员核实后开通教师账号。管理员可沿用用户管理中的教师账号创建流程，不要求提供学生学号，不经过本科生注册白名单。
4. 管理员在用户管理中通过独立的“分配课程”入口，为教师分配最多 20 门课程。教师页显示课程数量和全部课程，可从各课程卡片定位本人意见，或按课程筛选近期意见。

教师认证、课程分配、资料管理权限是三个不同概念。分配课程不修改角色，不授予正文编辑、课程审核或查看他人私人笔记的权限。原有课程负责人权限仍由原有管理渠道授权。

## 身份信息与历史教育经历

使用已经核实并绑定的学号注册或完成学号绑定后，认证页直接显示相应教育身份和入学年份，不再要求对同一身份重复申请。识别不等于证明已经毕业、获得学位或当前仍在读，也不自动公开个人历史。

教师账号直接显示已核实的账号身份；已有人工认证可保留学校等详情。页面默认只显示紧凑身份卡。老师、校友或研究生需要补充其他本科、硕士或博士经历时，点击“补充教育经历”填写并申请；学校和年份不会从当前学号擅自复制。

旧版 `teaching-courses` API、表名与 DOM 兼容保留，用户界面统一使用“分配课程”。这次命名调整不改变权限边界。

### 邮箱与学号绑定

邮箱仍须验证当前密码及邮箱验证码，验证后立即绑定，不增加人工邮箱审核。学校邮箱不能跳过验证码。

学号自动补绑仅在以下条件同时成立时生效：账号尚无学号；邮箱已验证且域为 `tsinghua.edu.cn` 或 `mails.tsinghua.edu.cn`；当前有效白名单的同一条记录明确包含并精确匹配该邮箱和申请学号，有姓名限制时也匹配；记录未被别人认领，学号未被别的账号绑定。

白名单允许空字段通配，但通配行不能证明邮箱与学号的对应关系。只有学号、只有姓名、任意清华邮箱、猜测邮箱用户名，均不会自动通过。已有不同学号的更改继续人工核验；不改 UID、教师角色或管理权限。

可以先验证邮箱再申请学号，也可以先提交学号申请，再验证配对邮箱。后者会重新核验当前待处理申请，符合条件即自动完成。名单认领、学号绑定、申请状态更新同事务处理；失败全部回滚，自动处理不伪造管理员审核人。页面在实际绑定后刷新账号与教育身份，无需退出重登。

## 体验课程与提出意见

- 从“我管理的课程”或学习世界进入章节与知识点，以学习者视角体验现有阅读、资料和学习流程。
- 正文或知识起源的私人批注不会自动发给课程组。需要反馈时，明确选择“提交课程组”，检查内容后提交；也可以从“参与共建”直接填写建议。
- 继续复用现有 `kind=contribution` 共建队列，保留原文定位和版本检查。教师页汇总最近 20 条本人提交及课程组回复，不显示他人的笔记或反思。
- 意见不直接改动已发布正文。课程组仍按现有课程管理权限核查、回复和维护资料。

## 部署与接口

新增迁移：`database/migrations/074_teacher_participation.sql`。只有 `course_teaching_memberships` 关联表；不批量变更历史用户，不导入或自动认领教师课程。

后端启动在现有课程表、认证表初始化之后执行同一幂等建表函数。标准迁移部署与启动初始化可以重复执行。

| 接口                                        | 访问者     | 作用                                                                       |
| ------------------------------------------- | ---------- | -------------------------------------------------------------------------- |
| `GET /api/teacher/workspace`                | 已登录用户 | 实时核实教师身份，返回本人任教课程及共建提交；未核实返回空数据             |
| `GET /api/admin/users/:id/teaching-courses` | 管理员     | 获取可关联课程与当前关联                                                   |
| `PUT /api/admin/users/:id/teaching-courses` | 管理员     | 提交 `{courseSlugs, identityConfirmed:true}`，事务内重新核实身份并替换关联 |

接口沿用现有登录及当前隐私政策校验，响应为 `private, no-store`。教师资格撤销后，下次读取不再返回教师工作区数据；管理员仍可清空其旧关联。任教关系记录分配管理员和时间，但不是内容编辑授权。

前端会在账号切换、退出、跨标签身份变更时清空本人数据，并忽略旧请求结果。网络失败保留明确重试入口，不把失败显示成“暂无课程”。
