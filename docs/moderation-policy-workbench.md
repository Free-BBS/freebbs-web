# 规则审核工作台：中文禁止清单

本版在 FreeBBS 的讨论审核工作台中吸收 PolicyAgent 展示稿的规则卡、证据解释、审计与人工反馈布局。保留网站原有账号、负责人库、待审图片权限和人工发布流程，没有引入第二套 Streamlit 服务或向量数据库。

负责人使用统一的“禁止内容清单”：每条都说明禁止范围、成立条件、例外、禁止示例和不应据此禁止的情况，编号使用中文，例如“隐私-001”“骚扰-001”。正常表达保护、普通求助和引用不再作为可匹配的禁止条目；这些边界纳入全局审核原则和对应条目的例外。两条关怀提示单独展示，不计入禁止清单。

当前是本机、虚构内容的文字试审版本。自动发布、机器拒绝后的负责人确认、已发布内容撤回、图片机器审核和真实用户数据外发上线不在本次实现范围。机器建议只展示，实际通过／驳回仍使用现有人工按钮。

## 已落地的五项

| 项目               | 本版行为                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 版本化规则库       | 28 条禁止项、11 类风险，另有 2 条关怀提示；使用中文编号，显示条件、例外、处理示例和来源。版本 `freebbs-policy-2026-10-09-v3`。 |
| 判断与证据解释     | 每条模型匹配包含有效规则编号、本次发送文本中的逐字片段和解释；展示不确定项与可信来源链接。                                     |
| 本地约束模型建议   | 根据已维护规则、图片是否未审、脱敏情况和不确定项生成建议；模型不能调用发布、删除、封禁或消息发送工具。                         |
| 机器记录与人工纠错 | 成功试审持久化，刷新后可查。负责人可以同意、纠正或标记待核实；追加历史而非覆盖旧反馈。                                         |
| 纠错变成回归测试   | 先保存人工标签，再手动改写成虚构样例；导出 JSON 后使用脚本比较模型结果。默认只预览，明确加 `--run` 才调用 API。                |

规则条目少、条件需要完整阅读，本版把受控禁止项、关怀提示及全局原则直接提供给模型，没有语义检索。这样避免首轮检索漏掉例外。规则数量增长后可再引入检索，并分别测试召回与判断。

v3 将政治条款细化为 9 条，把敏感个人信息和性内容限制改为不以年龄为前提；保留正常健康知识、求助与必要引用。旧未成年保护编号和类别仅保留历史显示。

规则来源及逐条边界见[规则库与官方来源](moderation-policy-sources.md)。规则匹配不等于证明违法，证据字符串通过校验也不保证模型解释正确。

## 页面操作

1. 负责人从现有讨论区入口打开审核工作台。普通作者仍只能查看自己的提交；规则与审计接口由后端重新验证负责人身份。
2. 左侧选择待审稿，阅读原稿和图片；右侧保留明确的人工通过／驳回操作。顶部“返回讨论区”保持醒目。
3. 查看禁止内容清单，生成本地脱敏预览，选择试审模型和输入模式，手动调用无问芯穹。页面显示中文条目编号、版本、证据、来源、建议动作与独立的关怀优先级。
4. 在历史记录中展开“人工复核与回归样例”，保存同意、纠正或待核实结果。这里的反馈不等于通过／驳回帖子。
5. 需要回归时，重新编写虚构标题、正文和预期说明。表单不会自动复制原稿；最新人工反馈须已经保存，预期标签须一致。“待核实”的记录不能直接成为标准答案。
6. 确认内容确属虚构后保存样例，再点击“导出回归样例”。人工检查下载文件中没有真实信息后运行脚本。

清单说明禁止范围，不表示出现相关话题就已经违反。仍需核实条件和例外；复杂政治疑点、授权不明或事实争议继续交人工判断。普通批评、投诉、引用和正常求助不得仅因主题被禁止；模型没有具体禁止依据时可返回空条目列表，有具体待核实事项时保留人工复核。

自动审核另外采用严格政治与心理关键词人工复核规则：原稿标题、正文命中词库后，本地直接转人工，不调用模型；图片在模型读出 OCR 与图片说明后执行同样的检查。课程、学术、引用和否定表达也不自动豁免，模型建议通过不能覆盖这一要求。两类在自动审核记录中分别醒目显示，同时触发就同时显示，并展示固定词库中的触发词；负责人通过前不发布。该规则决定的是由谁审核，不会把政治话题或心理求助直接加入禁止清单，也不作心理诊断。实际流程与验收见[自动审核测试说明](moderation-automation-test.md)。

心理痛苦与即时危险在单独的“关怀提示”中分别显示“关注”和“紧急”；关怀标签不是违规或疾病诊断，也不会自动通知学校、家长或其他机构。即时危险提示目前没有独立外部通知或值班升级机制，不能把页面标签当作已经完成救助。

## 本地约束

- 模型只返回受限 JSON：`decision`、`categories`、`reason`、`ruleMatches`、`uncertainties`、`supportPriority`、`supportReason`。
- 最多六条匹配；编号来自当前中文禁止项或关怀提示，证据是当前发送字段中的确切片段。类别和关怀级别必须一致。旧版英文编号不能作为新版模型响应通过校验。
- 普通表达无需返回旧版 EXP-001 等允许条目。信息不足时说明具体不确定项，可以不列禁止条目而要求人工复核，不能捏造一个“其他违规”。
- `high_risk` 至少需要一条可建议拦截的非支持规则；政治复核、普通心理支持不能凭模型一句“高风险”升级为机器拒绝。
- 有图片未审、已识别并替换隐私、适用人工复核规则或存在不确定项时，程序不能建议直接放行原稿。
- 每个结果的 `canAutomaticallyPublish` 固定为 `false`。建议不修改实际审核状态。真实自动化流程需要另行实现、验收。
- 不保存或展示模型内部推理。可展开 JSON 是通过校验的业务结果，不是供应商原始响应或密钥。

模型能力、外发字段、超时和格式兼容说明见[文字试审](moderation-ai-test.md)。规则提示和输出较旧版增加，15 秒硬超时仍保留；短文本 p95 3–5 秒需要新版真实样本测试，不能沿用旧版单次耗时。

## 数据、保留与权限

新增迁移 `068_moderation_policy_audit.sql`，后端启动时幂等创建三张表：

- `moderation_ai_runs`：稿件版本和摘要、发送内容摘要、受控模型结果、证据片段、对应规则与来源、模型与规则版本、到期时间。
- `moderation_ai_feedback`：人工标签、意见、当时规则版本及幂等请求标识。
- `moderation_regression_cases`：显式编写的虚构样例，与对应人工反馈关联。

不另存完整外发请求、身份替换映射、补充词目录、API Key、原始供应商响应或推理。因此可追踪依据和版本，但不能完整重放历史请求。规则更新不改写已存机器判断；旧版本人工反馈须重新复核才能建立当前规则的回归样例。

各版本升级均不重写旧审计 JSON。历史界面提供中文解释并标明旧版记录；旧版表达保护、指令隔离、普通求助和通用核查项不是当前禁止项。旧机器结果不能直接点击“同意”充当新版复核，需要选择纠正并按当前清单重新判断。新反馈追加保存，原判断仍可追溯。历史编号对应关系仅用于阅读，不授权模型沿用旧编号，也不自动把旧样例改成新版标准答案。

导出只包含当前规则版本的有效样例，并显示本次跳过的旧版样例数量；旧版记录保留至原到期时间。需要继续使用某个旧案例时，按当前清单重新人工复核、重新编写虚构样例，不自动迁移旧预期标签。文件中的 `skippedLegacyCount` 仅记录跳过数量，不包含旧正文；命令行预览和报告也会说明这一数量。

上述记录继承稿件原有到期时间，最多到创建后 30 天；到期立即停止通过接口读取，定时清理删除记录，外键级联清理关联项。新试审、人工反馈不延长期限。下载的 JSON、批测报告、备份与供应商留存不受此数据库定时任务控制，须另行管理。不能据此承诺所有法定记录都仅保存一个月。

“确认虚构”和拒绝整段照搬原文只是人工流程与基本检查，不是自动匿名化。改写得不充分仍可能带出真实信息；导出前必须检查，不能把勾选框当作合规证明。

每稿最多 50 次成功试审，每次试审最多 20 条反馈、10 个回归样例。一次导出最多 100 个有效样例；超出明确失败，不静默截断。普通用户不能读取这些记录；移除负责人后旧登录状态不能继续使用接口。

## 配置与更新

继续复用现有 `DISCUSSION_MODERATION_ENABLED`、`DISCUSSION_MODERATION_AI_TEST_ENABLED`、回环地址、系统模型目录和测试库密钥。新增功能没有额外软件依赖，不要求 Docker、GPU、重启 Windows 或修改现有 API Key。

更新前备份测试配置与数据库，确认 Git 工作区干净并以 `--ff-only` 更新。只重启经进程信息确认的测试后端；首次启动会创建审计表。浏览器强制刷新后验收，不对生产网站部署。数据库启动账号需要现有建表权限；初始化失败时检查测试后端日志，不重复启动多个后端。

已经安装融合版 `2153701` 的测试环境更新到中文禁止清单时，没有新增迁移或配置修改；更新代码并重启一次后端以加载新版规则，再强制刷新页面。无需先安装中间的“规则示例说明”小包。

已经安装中文禁止清单 v2（`582fcdc`）的测试环境升级 v3：没有新增迁移、配置或依赖；快进更新代码，重启测试后端并强制刷新浏览器。新旧规则版本不同，旧样例须重新确认预期，不能直接改版本后批测。

没有开启试审的环境中，规则库和已有历史可供负责人只读；人工反馈写入、样例写入与导出入口停用。本版不通过放宽回环限制来处理真实公开用户内容。

## 回归执行

需要用同一组固定样例比较多个模型时，使用[多模型自动化测试](moderation-model-evaluation.md)。内置 96 条 v3 虚构样例，默认先运行其中 12 条，生成中文对比报告。下面的单模型命令仍适用于工作台导出的样例。

以下命令在测试台式机 PowerShell 中执行。假设下载文件已放到 `F:\FreeBBS-Test\freebbs-policy-regressions.json`。必须使用与导出文件相同的规则版本；旧版本文件不自动升级。

先预览：不会读取数据库或密钥，不调用模型，不写报告。

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-policy-regression.js' --input 'F:\FreeBBS-Test\freebbs-policy-regressions.json' --model kimi-k2.6
```

检查无误后明确执行，产生供应商调用费用：

```powershell
& 'F:\FreeBBS-Test\tools\node-v24.21.0-win-x64\node.exe' 'F:\FreeBBS-Test\freebbs-web\scripts\moderation-policy-regression.js' --input 'F:\FreeBBS-Test\freebbs-policy-regressions.json' --model kimi-k2.6 --run
```

默认只读取 `F:\FreeBBS-Test\web-test\config.json`，要求双开关、回环应用地址和测试数据库 `127.0.0.1:3307/free_bbs`。复用测试库内系统模型设置；不把密钥写到报告。可通过 `--config` 与 `--output` 显式指定绝对路径，但不能绕过隔离检查。

每个样例调用一次，串行执行，不自动重试；连续三次失败即停止。最多 100 个样例。每次在 `F:\FreeBBS-Test\moderation-policy-results` 下生成独立目录及 `report.json`、`progress.jsonl`，不会覆盖旧报告。Ctrl+C 等待当前调用结束后保存进度并停止，不自动续跑。

比较机器决定、类别集合、规则编号集合、关怀优先级；模型理由是否合理仍由人工检查。退出码：0 全部标签一致，2 有差异，1 执行或模型失败，130 中断。若多个规则都可合理适用，精确编号比较也可能报告差异，需要人工复核预期样例。

## 开发验证

相关单元与页面测试：

```text
npm run test:moderation-policy
```

真实 MySQL 隔离测试：设置 `MYSQLD_BIN` 为可用的 MySQL 8.4 `mysqld` 路径，再运行以下命令。runner 创建独立临时库与命名管道／socket，不读取网站测试库配置；Windows 下禁用 TCP。

```text
node scripts/test-mysql-isolated.js --moderation-only
```

本轮验证包含权限、快照一致性、规则合同、无自动动作、数据审计、并发幂等、真实外键及到期清理，以及 Edge 桌面／手机和明／暗主题。浏览器及模型响应使用合成数据，不代表真实模型准确率。新版真实 GLM/Kimi 调用、完整业务 CI 与真实用户上线尚需后续验证。

政治与心理采用“关键词强制人工＋整句语义判断补充”。用户确认词库位于 `backend/moderation-review-keywords.json`，不是禁止清单。自动审核的独立 `reviewTopics` 证据经本地校验后参与发布事务内重算；不以违规类别、自伤紧迫程度替代话题判断。模型建议无风险仍可转人工。运行与验收见 `moderation-automation-test.md`。
