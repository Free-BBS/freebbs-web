## 追加功能

- 全站顶栏统一两行三列：签到、仓库、商店 / 电元、磁元、热力。移动端保留完整入口并预留顶栏空间。
- 问 Max 默认收起模型、思考和图片工具；摘要保留所选模型与附件数量。两侧面板上下对齐并扩展至视口边缘。
- 普通鱼骨只从仓库卡片隐藏，不改变资产、牧场数量或成就条件。
- Max 脸部改为暖米色，饥饿时哭脸；茅草屋和显示主页主人用户名的木牌替代旧 MAX 标牌。
- 管理员系统设置 → 奖励方案：搜索/多选同学，批量追加电元、磁元，确认名单和总额后发放。
- 仓库 → 钱包账本：统一显示新收支与奖励，支持币种筛选与分页；没有单独的奖励记录区，也不补旧流水。

### 奖励规则与可追溯性

预设 5/10/20/50 电元，支持自定义电元、磁元或两者同时奖励。
每批 1–100 人，每币每人 0–1000000 整数，至少一项大于零。追加余额，不覆盖原余额，不占用日常奖励上限，不增加热力。
每批保存管理员、名单快照、原因、前后余额。奖励、账本和站内通知同事务提交或回滚；不发送额外邮件。
网络结果不明确时保存原请求，可刷新后重试；同管理员同请求键只发一次，换载荷会拒绝。
账户删除后保留管理员发放名单快照用于审核，用户钱包账本随账户删除。

### 数据库上线前提（需部署人员确认）

040 新建奖励批次和名单表。041 新建 wallet_ledger；后端启动时初始化两个
AFTER INSERT/UPDATE users 触发器 freebbs_wallet_after_insert / freebbs_wallet_after_update。
需要部署数据库账号拥有 CREATE、TRIGGER 等所需权限；缺少权限时启动会报错，不静默漏记。
触发器随余额事务原子记录前后余额，覆盖签到、互动、购物、转换、充值、奖励和旧管理员调余额入口。
余额不变（例如仅更新热力）不入账。账本仅记录启用后的变化，不通过旧库存或余额反推历史。
普通变动显示余额变动与增减额，管理员奖励另有名称、原因；不猜测未关联业务的具体用途。
部署前备份数据库，低流量时部署并用测试账号验证一笔收入/支出与权限隔离。
触发器属于数据库对象，回退应用代码不会自动移除；回退时须由部署人员评估保留记账或停写后移除两个明确命名的触发器，保留已有账本。
