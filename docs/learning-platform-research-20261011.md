# 平台学习支持与发展研究：实现说明

2026-10-11。本地开发和预览，不代表线上已部署，也不是已证明的教育成效。

## 分工与已经实现的功能

| 对象           | 实际功能与数据                                                                                        | 不能据此推断                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 同学本人       | 既有过程记录、正式作答；自愿填写平台体验反馈，参加独立研究并查看本人阶段结果                          | 不把浏览、手工标签或自报起点当能力等级                          |
| 本人 Max       | 主动提问时读取当前账号、课程、知识点近期保存的笔记、批注、复盘与作答，配合公开课程材料辅助教学        | 不读取全站私人内容，不判正式题，不获得评分答案                  |
| 课程部         | 既有教学材料、题目与人工复核；为平台研究核查测量目标和题目质量                                        | 不能把同题订正当迁移，不能从时间补造掌握                        |
| 战略部研究视图 | 去标识化模块/目的/障碍/帮助与自报变化；研究四阶段结果、前后配对、间隔保持、辅助方式、按目的分层与缺测 | 观察性变化不是平台因果效果；少于 5 人均值不显示不等于充分匿名化 |

研究管理复用已有管理员鉴权，没有新增或自动授予“战略部”角色。课程复核与全站原有管理权限并未因研究模块而改变；这里限制的是研究 API/视图输出，不是宣称既有全站管理员完全没有其他管理权限。

## 本人 Max 的资料链路

公开课程内容仍为唯一作者正文。`loadCompanionContext` 在认证后读取本人当前知识点的保存记录，最多 12 条、合计 9,000 字符，私人渠道并行读取，最长 3 秒后降级。缺失、失败、历史版本、节选均区分显示；旧作答不借用当前题干解释其能力。正文与知识起源采用各自版本哈希。

来源清单只返回条目 ID、类型、区域、版本、修订和时间，不返回正文、答案、标题或评分依据。本人原文在主动发送 Max 问题时加入服务端可信范围的教学上下文，作为不可信资料，不作为系统命令。未保存草稿不自动读取；不将其写入公共 RAG 索引、管理员研究表或其他人的上下文。每次重新读取，修改/删除下一次生效；已有对话中引用过的内容、模型已经处理的旧请求不会随删除笔记自动消失。

本轮实际场景复核补齐了两处教学语境：当前已发布、已审核版本的客观题，提供公开选项 ID 与文字，避免只传“A”而不能解释选项含义；历史或未知版本不套用新选项，答案和评分依据仍不传。当前已发布知识起源经同一套课程分区解析与评分围栏清洗后提供最多 6,000 字符，附独立起源版本及节选标记。执行生产真实聊天 handler 与 payload builder 的 canary 已核对这些资料进入实际外发请求构建；外发传输替换为测试接口，没有调用真实模型，不宣称回答一定正确或完全抵抗提示注入。

同页面板在来源清单收起时仍说明读取本人本知识点已保存材料；来源版本、数量可展开查看。切换账号或课程的迟到回包不会复原旧清单。

## 自愿反馈：体验而非能力测量

入口为本人资料页，以及“继续学习”的折叠区。模块覆盖学习世界、讨论区、工作台、实验室、Max、创意工坊、PBL 和发展端。可报告目的、帮助程度、遇阻原因，以及可选的感受变化（理解、独立推进、下一步、探索、协作）。自由备注仅本人可查看；管理员得到受控分类统计，不收到原文。

反馈必须本人主动确认；必要过程记录依然默认开启，不增加“不记录”开关。反馈和研究自愿性与默认业务记录是不同事情。帮助程度按每人先平均再合并，避免多次反馈者压过其他人；统计提供实际人数、条数与覆盖分母。未填变化字段属于未知，不补成“没有变化”。没有反馈不等于没有帮助，选了“能独立推进”也不等于通过客观能力测量。

## 研究任务：固定题与可解释的证据

管理员登记标题、知识目标、涉及模块、版本、阶段题、等价性说明、抽样/比较限制与至少 24 小时的复查间隔。第一版支持每阶段 1–8 道单选题，答案在服务端固定评分，不接受客户端分数；不向参与者暴露正确答案或未来阶段题。发布不等于题目已完成效度验证。

参与者自愿报名后按“学习前 → 学习后 → 间隔复查 → 新情境应用”顺序，每阶段一次；复查以服务端学习后提交时间为基准。各阶段申报“独立完成 / 借助 Max / 借助其他帮助”。这里的“独立”仅为自报，不是监考结论。

管理端展示前测到后测的同一参与者配对差异，及后测到间隔复查的配对差异，分开列辅助、目的和缺测。窗口前的基线保留用于配对，不因选择近 7/30 天丢弃。窗口视图选择近期报名或研究作答者；它不是完整招募队列的流失率，应结合全部记录与单独队列设计解释。新情境任务得分只说明这次任务的表现，不自动生成“掌握分”、课程成绩、星标或个人排名。

阶段未提交进一步分为“已可提交但未交、未到开放时间、前置任务未完成”，以服务端 UTC 时间和真实阶段记录判定；已交与已可提交未交共同组成已满足条件人数。当前窗口和保留期完整队列采用同一规则；研究记录读取截断时分类返回未知，不补零、不把未到期当失访。模块与目的当前是分别汇总，不是模块×目的交叉比较。

课程部可使用[四阶段研究任务模板](course-authoring/templates/平台研究任务-四阶段.md)，与实际登记接口字段一致，独立于知识点正文与正式自测。当前管理员可新建研究，没有强制课程部审批、在线修订或停止招募功能；改题需另建新版本任务，旧任务不会自动关闭。固定答案评分只证明判分可复核，不证明目标效度或题目等价。

## 数据与工程边界

- 新 MySQL 表持久保存研究定义、反馈、报名、阶段答案/评分、幂等回执与限流；时间使用 UTC，查询强制日期字符串，防本地时区误解 24 小时限制。
- 个人反馈和研究作答保留 180 天；本人可删除反馈、退出并删除对应研究记录，聚合按现存来源重新计算。删除保留无原文的幂等墓碑，旧请求不能复活数据；账号删除级联清理本人研究数据。
- 提交、退出与删除在同一用户锁下串行化；旧账号、撤权、迟到响应不能重现私人或管理员视图。研究 API 不读取私人笔记、聊天或正式题答案。
- 报名提交失败后，同一目标重试保留幂等键，换目标时生成新键。本人及管理员的原有过程报表在切时间窗时立即清除旧数据；请求失败不把旧窗口报告标成新窗口，重试成功恢复所选范围。本人重新挂载的迟到错误不能盖掉新报告状态，前端资源版本已同步更新。
- 统计查询有 10,000 条上限；截断明确显示不完整，不假装全量。小样本抑制均值不是差分隐私；对外发布还需要重新审查可识别风险。
- 预览使用本地合成账号、内存数据与模拟 Max；现有实际 MySQL 部署迁移和真实模型教学效果仍需上线前验证。不能把内存/SQL 契约测试写成真实数据库运行证明。

## 研究解释与后续需要

战略部要回答“有没有帮助”，需三类证据相互核对：同学感到哪里有用/遇阻，实际工具与路径选择，课程部核查的任务表现及保持/迁移。只比较自愿使用 Max 与未使用者，会混入原有起点、任务难度、动机与求助差异。正式效果研究仍需预先明确假设、样本、基线等价、比较条件、失访、辅助条件和评分效度，不由 Agent 补出结论。[WWC 官方研究标准](https://ies.ed.gov/ncee/wwc/standardsbriefs)提供相关质量检查；[学习看板研究系统综述](https://arxiv.org/abs/2312.15042)也提示参与提升不能自动等同成绩提升。

尚未实现：全站跨模块自动任务追踪、私人文字的战略部语义汇总、随机对照/因果估计、作品与协作的量规评分、学习发展长期随访、独立作答监考认证。不要用本次基础研究功能宣称这些已经具备。

没有记录邀请或是否看过入口，所以注册人数是反馈覆盖的粗分母，不是实际使用者分母。研究登记的目标未连接过程分析里的自述起点，不能自动把人分成新手、熟练者、专家或科研人；只可描述其本次前测与申报目标。高基线者分数不变可能是天花板，明确自报无帮助者也可能表现提高，二者必须分开解释。小组均分隐藏仍可能通过全体与其他组均分的减法推断，不是严格匿名；原有管理员过程视图仍有实名的最小过程信息，未新建课程部/战略部独立权限。

下一步宜由课程部与战略部共同选择一个小目标试测：课程部复核任务与真实 Max 回答中的引用、条件和误解；战略部预先约定体验、表现、保持和应用的判据，登记比较方式与未完成原因。应报告结果与不确定性，而不是让 Agent 自动给平台打“有效/无效”标签。[WWC 对起点可比性、样本流失和混杂的说明](https://ies.ed.gov/ncee/wwc/standardsbriefs)可作为设计核查依据，不能据功能测试替代实际研究。

## 本地验证与复现

`npm run test:learning-research` 检查后端、身份/时区/删除边界、前端状态与完整 HTTP 接线；`npm run test:learning-companion` 检查本人 Max 上下文；`npm run test:learning-human:unit` 包含新研究模块并回归原有学习功能。`npm run test:learning-research:browser` 用真实 Chrome 验证原生提交、失败重试、批注与 Max 资料传递、主题/尺寸；仍不连接实际 AI 或数据库。

`npm run preview:learning:research` 在一个本地端口同时提供同页 Max、本人反馈/研究、管理员研究。演示统计全部为合成数据，不使用线上账号。

提交前补齐知识点加载失败的手动重载与安全返回，并同步资源版本。最终学习与共享 UI 去重回归共 1,259 项：1,257 项通过、0 项失败、2 项跳过（真实 MySQL，以及另一个字体预设专用 Chrome 测试）。修复后的研究功能真实 Chrome 流程连续两轮各 30 项通过，提交前独立复跑仍为 30 项通过、未捕获 JavaScript 错误，每轮保留 13 张截图，覆盖桌面/手机、明/暗模式，以及报名目标更改、阶段开放分类、报表窗口失败与重试；不应把这项浏览器验证误写为前述跳过的字体预设测试已运行。当前图标批注、完整学习链和加载恢复另有独立 Chrome 验收，见[实际任务与验收记录](human-learning-scenarios-20261010.md)。本次修改文件的 ESLint、Prettier 与 diff 检查通过；全仓 ESLint 仍有本次范围外的报错，未借此任务批量改动其他模块。
