# 发展端主站管理员首次配置入口设计

## 目标

在不登录或改动服务器的前提下，让经过主站后端验证的学习端管理员进入发展端，完成发展端独立白名单和角色的首次配置。发展端一旦由系统设置明确配置至少一名负责人，学习端管理员的自动兜底权限立即停止；之后只有发展端自己的访问授权生效。

## 信任边界

- 管理员身份只取自主站后端加载的用户记录。浏览器提交的角色、请求头或本地存储字段不能授予管理员权限。
- 主站适配器只向发展端内部身份增加 `mainSiteAdmin` 布尔值；发展端仍使用自己的角色、标签和访问白名单。
- 普通主站用户若没有发展端授权，继续得到 `403 preview_access_denied` 并留在施工页。

## 首次配置状态

迁移 `014_development_access.sql` 中由 `system` 写入的负责人记录属于初始种子，不视为已经通过发展端系统设置完成配置。发展端把“存在 `status=active`、`accessLevel=lead` 且 `ownerUid != system` 的访问记录”视为已经配置负责人。

当尚未配置负责人时：

1. 主站管理员可以进入发展端，并在本次请求的授权上下文中获得临时 `platform.super_admin` 能力。
2. 临时能力不写入发展端访问白名单或永久角色分配，避免兜底身份残留。
3. 后端自动补齐内置角色、权限、标签和模块定义，使系统设置保存负责人时不依赖服务器上的手工 bootstrap 命令。
4. 已有的系统种子负责人仍按其发展端记录获得永久负责人能力。

当管理员在系统设置中保存任意一名负责人后，该记录的 `ownerUid` 会变为实际操作者 UID。随后的请求检测到已配置负责人，主站管理员自动兜底关闭；未列入发展端白名单的主站管理员重新看到施工页。

## 授权实现

- `UserContext` 增加只读可选字段 `mainSiteAdmin`。
- 集成式主站身份适配器从 `toUserProfile(row).isAdmin` 映射该字段；远程主站身份适配器只接受 JSON 中严格布尔值 `isAdmin === true`。
- 发展端鉴权先解析自己的访问授权，再判断首次配置兜底。
- 临时超级管理员上下文使用现有权限目录生成 allow policy，同时保留现有的未知权限拒绝规则。
- 内置定义初始化抽成幂等事务函数，不创建超级管理员分配；现有 `bootstrapPlatform` 继续复用它。
- 非身份服务错误不再伪装成 `identity_provider_unavailable`，而返回独立的 `development_backend_unavailable`。

## 页面反馈

施工页入口在 `403` 时保持原页面；在 `503` 或网络异常时显示可重试的中文状态，避免点击后毫无反应。成功仍跳转到 `/development/`。

## 验证

- 主站适配器仅从可信服务端用户资料传递管理员布尔值。
- 未配置负责人时，主站管理员可进入并管理发展端，普通用户被拒绝。
- 通过系统设置配置负责人后，未在发展端白名单中的主站管理员被拒绝。
- 系统种子负责人可以自动补齐定义并获得持久发展端负责人权限。
- 身份提供方故障与发展端数据故障返回不同错误码。
- 施工页对拒绝、暂时不可用和成功跳转分别有测试。
