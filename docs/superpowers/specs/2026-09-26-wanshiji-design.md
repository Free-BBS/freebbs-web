# 「萬事集」设计

## 目标

在发展端新增「萬事集」，把学习端现有活动报名、发展端「無活动」报名和新的通用收集能力统一呈现。学习端 `/surveys` 页面保持不变，发展端现有活动数据不迁移；「萬事集」通过来源适配器读取并操作旧系统，同时为以后创建的报名、问卷、投稿和材料收集提供新的通用数据结构。

当前继续沿用发展端白名单。未来发展端向所有主站用户开放时，「萬事集」不需要更换数据模型或页面结构：普通登录用户可报名、查看内容橱窗和自己的报名；具有社工组织身份的用户额外获得创建收集的入口。

完成本阶段后只启动本地预览，不创建或更新功能 PR。

## 方案选择

考虑过三种方式：

1. **统一展示、保留旧系统、增量建设（采用）**：学习端活动、发展端活动和「萬事集」原生收集通过三个适配器转为统一卡片；报名写回各自来源。优点是学习端页面不变、旧数据零迁移、可以逐步替换。代价是适配层需要保留不同报名结果的差异。
2. **复制学习端活动报名到发展端后独立演化**：首版较快，但会立即产生两份活动、报名回执和抽签逻辑，后续难以确认真实数据源。
3. **一次性迁移全部活动到新模型**：最终模型最整齐，但迁移学习端报名记录、匿名回执、抽签状态和发展端组织范围的风险过高，也会迫使学习端页面同步改造。

采用方案 1。新功能只在明确需要时扩展旧接口，不复制或改写旧报名记录。

## 信息架构

侧栏新增「萬事集」，使用中性内部标识 `collections`，展示名称以后可以独立修改。路由如下：

- `/collections`：萬事集首页。
- `/collections/registrations`：报名入口，展示全部可见活动与收集。
- `/collections/registrations/:source/:id`：活动或收集详情与填写页。
- `/collections/showcase`：内容橱窗文章流。
- `/collections/showcase/:articleId`：文章详情。
- `/collections/mine`：我的报名。
- `/collections/workbench/new`：创建收集。
- `/collections/workbench/:collectionId`：继续编辑草稿。

首頁告示板放大后，普通同学看到“报名入口”和“内容橱窗”；社工组织成员及发展端负责人再看到“创建收集”。右下角钱包图标始终进入“我的报名”。

## 身份与访问边界

当前阶段，进入「萬事集」仍要求用户已通过发展端访问检查。未来放开发展端时，以下规则保持不变：

- 普通登录用户：浏览活动、提交允许自己填写的收集、查看内容橱窗、点赞和查看自己的报名。
- 社工组织成员：在普通用户能力基础上创建和管理本组织的收集。
- 发展端负责人：可以创建收集并处理异常数据。
- 仅有平台管理员身份、仅有代表队队长身份的用户不会自动获得创建收集能力；如果同时拥有组织身份，则按组织身份处理。

社工组织身份来自共享身份目录，包括辅导员、电子系学生会、电子系团委、TMS 电子系分会、电子系科协和电子系学生媒体中心。创建者必须选择自己所属的一个组织作为归属；跨组织身份可以选择其中任意一个，但一次收集只有一个主归属组织。

收集结果默认只对创建者、本组织具有负责人层级的成员及显式加入的协作者可见。填写者只能查看自己的回应。前端隐藏入口不能替代服务端校验。

## 活动来源整合

统一的展示模型称为 `CollectionListing`，至少包含：

- `source`: `learning_survey | development_activity | native_collection`
- `id`、`title`、`summary`、`coverUrl`
- `opensAt`、`closesAt`、`location`
- `status`: `upcoming | open | closed | finished`
- `organizerLabel`、`capacityLabel`
- `featured`、`viewerState`

三个适配器分别负责：

### 学习端活动适配器

读取现有 `/api/surveys` 和 `/api/surveys/:id`，不修改 `/surveys` 页面。提交继续调用 `/api/surveys/:id/entries`，沿用联系邮箱、题目校验、登录限制、随机回执、抽签和幂等重试规则。

「萬事集」使用与学习端相同的回执存储键和生命周期，因此同一浏览器会话内可以从两个入口查询结果。匿名旧报名无法可靠绑定主站账号，只在当前浏览器存在有效回执时显示于“我的报名”。登录限制活动可以通过新增的只读“我的活动报名”接口按当前账号返回；该接口不会改变学习端页面。

### 发展端活动适配器

读取现有 `/api/development/v1/events/activities`。详情和报名继续调用现有发展端活动接口，保留组织范围、报名截止、容量和取消报名规则。「無活动」页面保持不变。

### 原生收集适配器

读取「萬事集」自己的已发布版本，使用通用模块 schema 渲染填写页。提交、附件和结果均保存在发展端数据层。

任一旧来源暂时不可用时，其他来源仍正常展示；失败来源显示一张克制的状态卡和重试按钮，不能使整个报名入口空白。

## 首页视觉与交互

### 活动传送带

页面顶部是一条横向传送带，展示正在报名和即将开放的精选卡片。卡片从左向右持续循环，左右边缘用遮罩、轻微缩放和模糊形成进入与离场效果。鼠标悬停、键盘聚焦、触摸拖动时暂停自动滚动；用户开启 `prefers-reduced-motion` 时取消循环动画，改为可手动横向滚动的吸附列表。

每张卡片保持同一尺寸，只显示活动名称、来源、主办方、时间和报名状态。点击进入统一详情页。循环所需的视觉副本从辅助技术树中隐藏，避免读屏重复朗读。

### 酒保小羊与告示板

下半区沿用「無限机会」的小羊酒保角色，但生成一张新的独立素材。小羊站在告示板旁，告示板贴满纸张、图钉、线条和符号；纸张上只有不可辨认的示意笔画，不在位图内绘制真正的功能文字。

点击告示板后，原场景缩暗并虚化，告示板平滑放大到页面中央。功能按钮使用真实 DOM 元素覆盖在纸张位置，保证清晰文字、键盘操作和响应式布局。关闭方式包括关闭按钮、遮罩点击和 Escape。

### 我的报名钱包

右下角固定一个简洁的小钱包图标，带“我的报名”可访问名称。桌面端悬停展开文字，移动端保持圆形按钮；不能遮挡底部导航、安全区或主要提交按钮。

## 报名入口

报名入口按“报名中、即将开始、已结束”分组，可按来源和组织筛选。所有来源使用统一卡片尺寸和状态标签。

点击卡片后在当前页面展开详情；窄屏使用整页详情。详情包括完整说明、时间地点、主办方、剩余状态、原始来源和报名字段。用户可直接填写并提交，不跳回学习端或「無活动」，但提交请求仍由来源适配器写回原系统。

学习端活动继续提供报名回执下载和抽签结果查询；发展端活动继续提供报名与取消；原生收集按发布版本渲染。来源差异通过详情中的小型状态区表达，不暴露 API 或数据库实现。

## 我的报名

“我的报名”按时间倒序汇总：

- 发展端活动中当前 UID 的有效和已取消报名。
- 原生收集中当前 UID 的回应及处理状态。
- 学习端需要登录活动中当前账号的报名。
- 当前浏览器仍保存回执的匿名学习端报名，标记为“本机回执”。

每项显示活动、提交时间、当前状态和可用操作。匿名回执不会上传到新的数据表，也不会以明文写入服务端。学习端历史匿名报名若回执已经丢失，无法自动恢复，页面应明确说明这一边界。

## 内容橱窗

内容橱窗使用类似公众号的文章流：封面、标题、摘要、来源组织、发布时间和点赞数。文章详情支持经过清洗的 Markdown、图片、视频链接和外部推送链接。

登录用户可以点赞或取消点赞，同一用户对同一文章最多一个赞。首版由具备创建收集能力的用户为自己的组织创建草稿和发布文章；作者和组织负责人可以编辑或下架。外部公众号、B 站和推送链接先使用人工录入，自动同步留给后续连接器。

## 仿真式创建工作台

工作台采用三栏结构：

1. 左侧是零件库，分为“展示模块”和“规则零件”。
2. 中央是纵向仿真画布，模拟同学最终看到的收集页面。
3. 右侧是当前选中模块的属性面板和发布检查。

窄屏改为底部零件抽屉、中央画布和侧滑属性面板，不允许横向溢出。

### 展示模块

首版支持：

- 说明与分节标题。
- 基本信息收集：姓名、学号、用户名等字段来自主站登录状态，可配置显示、隐藏和是否允许修改；姓名和学号默认只读。
- 简短文本、长文本。
- 单选、多选。
- 日期与时间。
- 普通文件、图片、视频、音频上传。

每个展示模块是一块纵向卡件，顶部有兼容插槽，主体展示真实预览。卡件可以拖动排序，也提供键盘“上移/下移”操作。点击卡件后在右侧编辑标题、说明、占位文字、选项和上传提示。

### 规则零件

规则零件不直接出现在填写页面，以较小的机械零件形态呈现。首版支持：

- 可见范围：全部发展端用户、指定组织、指定 UID/学号名单。
- 必填规则。
- 单人提交次数。
- 上传数量：单文件或批量上传、最大文件数。
- 文件类型白名单。
- 单文件大小和总大小限制。
- 文件名/标题审核：禁用字符、正则表达式、前后缀和示例。
- 开放时间、截止时间与容量。

表单级规则吸附到画布顶端的总控插槽，字段级规则吸附到对应展示模块的插槽。插槽声明兼容类型；例如文件格式零件只能吸附到文件、图片、视频或音频模块，不能吸附到单选题。

### 拖动与磁力吸附

工作台使用支持鼠标、触摸和键盘的拖动方案。拖动零件进入兼容插槽附近 28 CSS 像素时，插槽高亮并显示落点预览；松开后以短促弹性动画吸附。进入不兼容插槽时不吸附，并在属性面板给出原因。用户开启减少动态效果后，吸附改为无弹性淡入。

选中模块后显示清晰描边，不使用高饱和亮蓝。删除、复制、上移、下移和解除规则必须有可点击按钮，所有拖动操作都有键盘等价操作。

### 草稿、预览与发布

工作台自动保存草稿，并显示“已保存/正在保存/保存失败”。提供真实填写预览，不需要发布即可验证条件和上传限制。发布前执行完整检查：至少一个展示模块、标题完整、规则兼容、开放截止时间合法、上传限制处于平台上限内。

每次发布生成不可变版本。已经收到回应的发布版本不能被原地修改；编辑会生成下一草稿版本，避免填写期间规则变化。状态包括 `draft`、`published`、`closed` 和 `archived`。

## 数据结构

新增以下逻辑实体，内存存储和 MySQL 存储保持相同接口：

- `collection_forms`：收集基本信息、所属组织、状态和当前草稿版本。
- `collection_versions`：不可变的模块树、规则配置、开放时间和发布版本号。
- `collection_responses`：填写者、版本、答案摘要、提交状态和时间。
- `collection_assets`：上传文件元数据、用途、所有者和存储位置。
- `collection_collaborators`：显式协作者及可执行操作。
- `showcase_articles`：橱窗文章、组织、封面、正文、外链和状态。
- `showcase_likes`：文章与用户的唯一点赞关系。

模块树使用有版本号的 JSON schema 存入 `collection_versions`，但访问范围、状态、组织归属、响应所有者和文件元数据保留为可索引列，不能全部塞入 JSON。

## API 边界

发展端新增 `/api/development/v1/collections` 路由族：

- 发现与详情：统一返回原生收集，并由前端来源适配层与两个旧来源合并。
- 草稿与版本：创建、更新草稿、预览校验、发布和关闭。
- 回应：提交、读取自己的回应、组织管理者读取与导出。
- 上传：先创建受限上传会话，再按模块规则校验并绑定回应。
- 橱窗：文章列表、详情、草稿、发布、下架和点赞。

学习端后端仅新增必要的只读“我的登录报名”能力；现有列表、详情、提交、抽签和管理接口保持兼容。发展端活动接口只补充统一展示缺失的只读字段，不改变现有状态机。

## 文件与媒体安全

上传不能只信任文件扩展名或浏览器 MIME。服务端同时检查文件头、允许类型、单文件大小、总大小和文件数量；失败上传立即清理。文件名审核作用于显示标题和原始文件名的安全副本，不直接使用用户文件名作为磁盘路径。

未发布草稿和未提交回应的临时文件有过期清理机制。下载接口按收集、回应所有者和组织范围重新鉴权。首版使用现有本地存储模式，不接入清华云盘；外部存储通过后续适配器接入。

## 错误处理

- 聚合来源独立失败，不影响其他来源。
- 报名提交超时后按来源幂等键重试，不能重复报名。
- 自动保存失败时保留本地工作台状态，阻止用户误以为已经保存。
- 发布校验在画布对应模块和发布检查区同时标出问题。
- 上传失败保留已经填写的文本和其他成功附件。
- 文章点赞使用幂等写入，重复点击不会产生重复记录。
- 路由直接访问时，前后端都验证查看、创建和管理范围。

## 明暗主题、响应式与无障碍

页面继续使用发展端语义颜色变量，不建立独立黑色主题。传送带和告示板使用暖棕木色，小羊保持现有角色风格；工作台使用克制的深青、暖白、铜色插槽和低饱和选中状态。

320px 宽度下所有模块、属性字段和按钮不得横向溢出。传送带支持手动触摸滚动；告示板按钮保持至少 44px 点击高度；钱包避开安全区。所有拖动、展开、点赞、关闭和发布操作有键盘支持、可见焦点与读屏名称。

## 测试范围

- 三来源适配器的状态、时间、报名和错误转换。
- 学习端页面与旧 API 回归保持不变。
- 活动详情内完成报名、取消或保存回执。
- 我的报名按 UID 与本机回执正确聚合且不泄露他人数据。
- 橱窗文章可见性、唯一点赞、下架和外链清洗。
- 组织身份才能创建，普通用户和仅平台管理员/队长身份不能越权。
- 模块 schema 版本、兼容插槽、非法组合和发布前校验。
- 拖动排序、磁吸、属性编辑、键盘替代操作和自动保存失败恢复。
- 上传真实字节校验、数量/大小/文件名规则、失败清理和下载鉴权。
- 明暗主题、减少动态效果、窄屏无溢出和来源故障降级。

## 交付顺序

本设计分为四个可独立验收的实现阶段，但在同一功能分支上连续完成：

1. **聚合基础与首页**：模块入口、统一来源模型、传送带、酒保告示板、钱包入口和新小羊素材。
2. **报名与我的报名**：统一报名入口、展开详情、三来源提交适配、回执兼容和报名汇总。
3. **内容橱窗**：文章流、详情、发布管理和点赞。
4. **仿真工作台**：模块 schema、拖动与吸附、规则零件、上传、预览、版本发布和结果读取。

四个阶段完成并通过检查后启动本地网页与 API 预览。不会自动推送分支或创建 PR。

## 本阶段不包含

- 修改或删除学习端 `/surveys` 页面。
- 迁移既有学习端或发展端活动记录。
- 清华云盘、秀米、微信公众号自动同步。
- 实时多人同时编辑同一张收集。
- 自动创建微信群。
- 在完成本地验收前提交 PR。
