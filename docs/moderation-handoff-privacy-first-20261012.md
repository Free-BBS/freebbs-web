## 保留的功能约定

- 文字主模型 Qwen，图片优先 Kimi；GLM 为备选，不自动切换。
- 政治话题和心理问题采用关键词强制转人工加语义补充，发布前人工处理；心理求助不等于违规或医学诊断。
- 文字与图片都通过的含图帖子可以先发布，并通知负责人单独复核；空白或无法可靠读取的图片转人工。
- 异常、未知类别、隐私疑点保留人工审核，不因调用失败自动发布。
- 30 天是站内审核证据的清理设计，不是全站数据、正常帖子、备份或模型供应商数据的统一保存期限。
- 正式环境开关、私有图片目录、上线前检查和首次暂停机制已实现；外部服务数据安排仍需运营方确认。

## 尚未实施的隐私界面调整

当前版本仍在每次提交时展示说明并要求主动确认，记录提交对应的说明版本。尚未实现首次按账号确认、全站隐私政策或政策变更重新确认流程。

用户希望发布界面的主要文案精简为：

> 为维护友好的校园交流环境，平台会检查帖子、评论及图片是否符合社区规则。

外部处理、人工查看、保存与删除等详细安排应纳入全站隐私政策，并保留醒目的查阅入口和适用的告知同意机制。不可先删除现有告知再等政策补齐。

## 下一阶段和恢复顺序

1. 形成其他平台政策比较、FreeBBS 数据清单、代码证据和待确认问题。
2. 确定运营主体、联系渠道、实际启用功能、供应商安排、保存与删除规则。
3. 编写全站政策，补齐页面入口、同意记录和必要的技术调整，并在台式机验收。
4. 重新核对正式 main 与部署状态，检查新的冲突和全量 CI，完成服务器备份及配置检查。
5. 按上线文档先人工验收，再开启自动审核；当时再执行正式上线操作。

恢复工作时优先读取本记录和隐私调研文档，通过 git show 查看检查点。不要在有新工作时执行 reset --hard，也不要用测试数据库、测试配置或管理员恢复工具覆盖正式环境。
