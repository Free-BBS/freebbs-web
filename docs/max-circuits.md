# Max 读取电路

Max 会读取本站保存电路的结构和参数。无需在 AI 服务安装工具，也不要求模型具备图片识别能力。

## 使用

- 讨论区：把电路原理图、动态图或波形图引用插入帖子/评论，在评论中 `@max` 提问。Max 会读取触发评论、帖子正文和近期评论里的电路。
- 问问 Max：粘贴电路链接并提问，也可以在同一对话后续追问该电路。
- 课程知识点聊天复用相同的后端请求通道，因此问题或历史消息中的电路链接同样可读。

例如：

```markdown
@max 分析这个电路的工作原理与输出电压：
[电路原理图](/circuit?cid=c_0123456789abcdef01234567&revision=1&view=schematic)
```

支持本站 `/circuit`、`/circuit-embed` 的 Markdown 链接和裸链接。省略 `revision` 时读取当前最新版，并把实际版本号交给 Max；指定版本不存在时说明失败，不会改读最新版。外站链接、HTML、代码块和内联代码中的引用不读取。

## 传给模型的数据

`backend/agent-circuits.js` 在 `postAgentChat` 发送请求前，通过既有的公开电路读取函数查询数据库，将结果加入当前用户消息和 `context.circuits`。它保留会话原始消息，不把展开后的资料保存进用户的聊天记录。

资料包括 CID、固定版本、标题与说明、元件型号和 SI 单位参数、引脚编号与名称、节点归属、导线连接、未接导线的引脚、参考地和保存的分析设置。节点使用与仿真引擎相同的计算规则：所有地共地，只有导线端点/junction 建立连接，几何交叉不会自动连通。

每轮最多读取 6 个不同电路版本，优先本轮问题和触发评论；重复视图只读取一次。电路结构上下文限制为 60,000 字符，超出和读取失败均通过 `context.circuitNotices` 告知模型。源文本扫描也有长度上限。所有读取直接查询本站数据库，不请求用户提供的网络地址。

此功能读取的是保存的电路结构，不解析上传的 PNG/JPEG 截图，不执行仿真，也不读取浏览器内正在播放的波形采样。模型收到明确提示，不把估算当作实际仿真结果。当前独立 `freebbs-agent` 的消息合约只接受文本；图像识别需要另行扩展其多模态合约及模型支持。

## 验证

```sh
node --test backend/agent-circuits.test.js
RUN_CIRCUITS_INTEGRATION=1 node --test backend/circuits.integration.test.js
```

单元测试覆盖 Markdown/裸链接识别、过滤、固定版本、历史消息、节点关系、失败提示与限额。集成测试启动隔离数据库和模拟 Agent HTTP 服务，实际发起直接聊天、创建带电路的帖子并 `@max`，验证发送给 Agent 的元件参数以及自动生成的回复。
