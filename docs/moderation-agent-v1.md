# 讨论区监管 Agent：首版实施与验收清单

状态：人工审核流程、入口、提示显示和本地脱敏预览已由测试电脑操作者确认可用。本轮加强姓名和宿舍地址识别，并增加负责人手动触发的无问芯穹文字试审，见 [隐私预览说明](moderation-privacy-preview.md) 和 [文字试审说明](moderation-ai-test.md)。试审仅在显式启用的本机测试环境使用虚构内容，支持本地脱敏和虚构原文两种模式；不自动发布。机器队列、图片 OCR/遮挡及正文编辑重审仍未实现。

验证边界：以下记录保留人工批次的设计和范围；新增能力的验证记录另见上述说明。普通奖励和回复通知回调在数据库测试中使用测试替身。文字试审的接口、权限、供应商异常和页面已本机验证，测试电脑的模型配置及真实请求仍待验证；测试替身不作为可启用的业务审核模式。

## 当前可测试的功能

- 设置 `DISCUSSION_MODERATION_ENABLED=true` 后，新帖子与评论进入独立的 `moderation_submissions`，批准前不写入现有公开内容表。因此原有搜索、个人主页、统计、通知和 Max 上下文都读不到待审正文。
- 页面 `/moderation?mine=1` 显示作者提交记录，`/moderation` 是负责人审核工作台。通知链接 `/moderation?id=<id>` 对负责人打开工作台详情，对普通作者打开自己的提交详情；数据访问仍由后端校验。管理员在同页管理负责人，初始负责人为首次初始化时的网站管理员。
- 可见入口位于讨论区的“全部帖子 / 我的帖子”下方：登录用户显示“我的提交”，只有负责人显示“审核工作台”。管理员若不在负责人库中，同样不显示审核入口；仍可通过“我的提交”页面的“审核负责人”区域管理名单。
- 通过、驳回、负责人撤销、同稿重试和并发决定均在服务端验证。正式内容、奖励与普通通知在批准事务中一次性生成。
- 讨论区新上传图片保存到公开上传目录之外，通过 `/api/moderation/attachments/:id` 按作者、负责人或已批准内容的当前访问权限读取。独立电路报告上传沿用原有路径；其公开图片不能直接作为新的讨论待审附件。
- 首批拒绝外链图片、原始 HTML 与可变的电路/工具/实验嵌入；普通 Markdown、代码示例和普通链接可用。
- 审核提醒与提交在同一事务写入站内收件箱。负责人已打开的普通网站页面每 3 秒刷新未读数；没有实现离线推送或即时邮件。
- 提交与未发布附件的证据期限按创建时起 30 天计算；每分钟尝试清理到期审核正文副本、理由及未发布附件。未处理稿件到期后转为 `expired` 并继续不公开，不能延长期限后静默放行。已批准且仍用于业务内容的图片保留，并继续遵守内容读取权限。
- 当前所有新稿件由人工作最终决定，不启动讨论区 Max 自动模型回复。负责人可以生成本地脱敏预览；显式启用本机试审后，还可手动请求外部模型的文字建议。没有自动审核队列或 OCR；3–5 秒目标尚未实测。没有新增正文编辑接口。

### Windows 测试环境启用

1. 保留现有已验证环境，备份测试库后再应用测试更新。当前 GitHub 连接创建分支返回 403，代码通过本地 Git bundle 更新包交付；更新包以下述 Web 基线为前提，先检查工作区干净并执行 `git bundle verify`，随后从文件获取提交并快进合并到测试分支。不要执行生产部署或生产迁移工作流。
2. 在仓库外的测试配置加入字符串字段 `DISCUSSION_MODERATION_ENABLED`，值为 `true`。现有数据库账号、密钥和上传路径保持不变。
3. `DISCUSSION_MODERATION_DIR` 可省略，默认在上传目录旁创建 `moderation-private`；不能与公开上传目录、`public`、`development/apps/web/dist` 或经 `/vendor` 提供的 `node_modules` 互相包含。目录符号链接也需要通过相同检查。
4. 启动会以幂等方式初始化 `067_discussion_moderation.sql` 的新表。历史帖子与评论不搬移，不重新审核。
5. 重启测试前后端后，先以管理员发文字和图片稿件，确认讨论区尚未公开；再在审核工作台通过，刷新确认正式帖子及图片可读。用另一账号检查待审图片直链不可读。
6. 再测试驳回、两位负责人同时处理、撤销负责人权限、网络失败后重试和无人负责提示。不要仅因页面打开就将本批标为验收完成。

此配置只用于隔离测试阶段。关闭开关不会把既有待审稿发布出去，但会让后续新提交走原有发布流程；不能把它当作审核故障时的自动降级方式。

## 2. 当前人工批次与后续目标

- 当前范围为讨论区新帖子、评论、回复和图片，新增内容先审后发。提交快照不可编辑；尚未新增正文编辑或图片替换接口。以后增加编辑时，必须同时实现版本化重审，不能沿用旧批准结果。
- 范围包含所有发言者；管理员或教师身份不能绕过审核。白名单注册和身份认证沿用现有功能。
- 内容的现有可见范围不改变审核标准。原有隐藏、删除、登录可见规则仍然有效，审核通过不覆盖这些规则。
- 当前每条新稿件都持久化待办和负责人站内提醒，由人工作决定。服务错误、无负责人或未处理时保持不公开；当前没有自动风险分类或“机器暂拦”状态。
- 负责人库由管理员增删指定用户，初始从网站管理员填充一次。不新增回避规则，也不把版主权限等同于审核权限。
- 当前审核证据保留期限为固定 30 天。普通已发布帖子、评论及仍被引用的正式图片不因审核证据到期而删除。
- 不自动补审全部历史内容，也不把历史内容标为经过机器审核。资料、用户名、简介等讨论正文以外的用户内容不属于本批完整覆盖范围。

后续模型批次的目标是使用本机隐私处理程序和已有外部 API 渠道；正文、必要上下文和图片均先在本机处理。普通短文本 95% 在 3–5 秒内得到首轮机器结果是待实测目标，当前人工批次不具备该能力，也不提供该耗时承诺。模型结果只作辅助，人工作最终决定。

## 4. 实施批次

### 第一批：已实现并通过测试电脑人工验收

1. 新增审核表，保存独立稿件快照、附件绑定、负责人及人工决定信息；不建立机器队列和租约。
2. 新提交原子保存稿件、内容摘要和人工待办提醒；同稿请求通过请求编号去重。尚无提交后的正文编辑接口。
3. 使用私有图片目录与鉴权读取；前端通过 Bearer 请求转 blob 预览，切换账号时撤销缓存。
4. 批准前不写入讨论业务表，避免现有列表、搜索、个人主页、统计和 Agent 资料读取等旁路；本批拒绝未经固化的动态嵌入。
5. 提供人工工作台、作者状态页、负责人管理、版本校验、同稿重试和决定幂等；负责人撤销后的权限由服务端重新验证。
6. 负责人提醒和作者结果提醒使用站内通知。站内未读数轮询不能等同于离线推送或即时邮件送达。
7. 实现 30 天证据清理和到期状态。功能测试使用测试替身，浏览器测试使用合成 API；没有实现可切换的模拟审核器。

### 第二批：本地预览和手动文字试审已实现，完整机器审核待实现

当前预览覆盖以下第 2 项的一部分，固定 `externalReady: false`。目录命中、格式规则和人工补充词不能替代完整姓名识别；模型调用不会因预览成功自动启用。用户已授权使用虚构内容进行真实 API 测试，当前文字试审按该范围实现一致模型配置、严格结果校验、超时和迟到结果保护。下列清单保留完整生产流程的目标，图片处理和持久机器队列仍待实现。

1. 定义内部审核输入、脱敏产物及模型结果结构，绑定案件、版本、规则版本、脱敏器版本和内容摘要。
2. 在本机识别并替换姓名、学号、手机号、邮箱等信息，覆盖必要上下文；映射不进入外部请求。
3. 图片在本机解码、OCR、定位和遮挡隐私，处理后重新编码，移除元数据；检查图片内二维码等风险。
4. 图片、OCR 或文本识别失败时进入人工待审。未验证的产物不得带上“已脱敏”标记并放行。
5. 限制外部请求字段与图片来源，禁止自动上传原图、任意 URL 抓取和原文失败回退。
6. 从现有模型渠道选定可用模型，核实能力、数据处理条款和配置方式后再进行真实调用。
7. 使用独立的总超时与有界重试，严格校验模型 JSON；模型输出仅作建议，无权直接操作数据库、账号或发布接口。
8. 内容中的“忽略规则”等指令作为待审数据，不作为执行指令。不能把“未检出风险”仅凭单一置信分数等同于批准。
9. 增加机器队列、租约、过期任务恢复和迟到结果保护。正文编辑如进入此阶段，需同步引入不可变内容修订和旧结果失效机制。

### 第三批：完整 Agent 的后续验收目标

1. 重启恢复、网络故障、重复提交、迟到结果、编辑重审、双人同时复核和撤销权限测试。
2. 为正常校园讨论、批评投诉、引用、学术讨论及真实违规建立带人工标注的测试集，分别统计误拦和漏检。
3. 文本、图片分别测量排队和处理耗时；从并发 1–2 起测，调整限流和队列容量。
4. 验证审核证据到期、临时文件清理、图片引用保护以及待审证据到期后的行为。
5. 在第二台电脑应用新迁移与功能分支，重新执行基础功能和审核完整流程验收。
6. 功能开关切换必须维持已存在待审内容不公开；停用 worker 只暂停处理，不能变成放行。

## 5. 当前人工契约与后续机器契约

当前实现：

- 提交以 `(author_id, request_id)` 唯一约束去重，并校验内容摘要；同一请求编号不能替换稿件内容。
- 当前业务状态为 `pending`、`approved`、`rejected`、`expired`，没有 worker 执行状态。不可编辑的稿件快照与状态版本分开理解，`version` 用于审核决定的并发校验。
- 人工请求携带 `requestId` 和 `expectedVersion`。事务中重新校验当前负责人、稿件状态、证据有效期和附件；同一决定重试返回已有结果，冲突决定不会再次发布。
- 批准时原子写入正式帖子或评论、发布关联、奖励和通知。建表与变更字段在初始化阶段执行。
- 管理员管理负责人库，审核权限以有效负责人记录为准。没有负责人时页面提示添加负责人，稿件继续待审。

后续机器队列规范（尚未实现）：

- 编辑重审引入内容修订号及唯一约束，旧修订结果不能批准新内容。
- 分离机器执行状态与审核状态；如新增 `held`、`needs_review`、`superseded` 等状态，需配套迁移和界面。`held` 仅表示机器暂拦，不能冒充人工驳回。
- 任务使用随机租约令牌和到期时间。模型调用在事务外执行；心跳、结果写回均比较令牌、期限和内容修订。
- 只回收过期租约，过期执行者或人工决定后返回的机器结果不能改变发布状态。

## 6. 证据与清理

- 当前存放的是原始稿件快照、附件及人工决定理由；提交和未发布附件按创建时起固定 30 天过期。新增预览和占位映射仅在请求内存中生成，不另存数据库、文件或浏览器存储，没有持久化的脱敏副本或模型输出。
- 到期后读取接口不再返回审核原文与理由；待审稿件转为 `expired`，仍不公开。需要作者重新提交，不能静默延长原证据期限。
- 清理会删除审核正文副本、理由及到期未发布图片，保留用于状态和幂等判断的最小记录。这不是删除整条正常帖子或评论的任务。
- 已批准正文和仍被引用的正式图片属于业务内容，不随审核副本删除；图片读取继续检查业务内容当前权限。
- 受控目录与文件标识限制删除范围，文件占用等失败可在后续轮次重试。真实数据库和测试电脑上的清理、故障恢复仍需验收。
- 第二批产生的脱敏副本、映射和模型输出必须另行纳入到期字段与清理策略。运行日志、通知邮件和备份也需单独约束；当前代码没有修改服务器备份策略，不能据此宣称备份中的旧证据已删除。
