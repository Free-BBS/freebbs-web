## 规则与实现

1. 姓名在个人设置只读。`PATCH /api/profile` 不再写入姓名；试图提交不同姓名返回 403。管理员继续在原用户管理入口修改姓名。旧客户端提交未变化的姓名仍可保存简介。
2. 昵称继续使用现有 `username` 字段及 3–64 位字母、数字、下划线规则，同时改变登录用户名；邮箱登录和用户 ID 不变。不新建独立中文昵称字段。
3. 初次自愿改名免费。每次免费改名后，从该次时间起满 **3 个自然月** 恢复一次免费机会，次数不累计。由数据库按 UTC 计算，月底按目标月最后一天处理，不按固定 90 天或浏览器时钟计算。
4. 免费机会不可用时，每次支付 10 磁元。需明确勾选支付确认；付费改名不延后免费时间。原本不合规的历史用户名强制修复仍免费，不消耗自愿改名机会。
5. 同一事务锁定用户行，检查当前昵称、免费资格及余额，更新昵称与余额并写入改名流水。重复昵称、余额不足及写入失败均不应消耗磁元或免费机会；相同昵称重试不重复扣费。并发不同目标通过原昵称校验拒绝过期请求。
6. 改名不保存或清空未提交的个人简介、个人网页。接口结果不确定时先刷新改名信息核对，不自动重试扣费。
7. 课程讨论返回按钮在长帖滚动容器中吸顶，返回时保留帖子列表位置和键盘焦点。面板打开时隐藏右下角悬浮按钮，顶部关闭按钮保留 44px 点击区域，支持 Escape。
8. 参考《FREE BBS平台定位与V1.0规划-20260728》“官方知识正文”说明，新增“我们为什么要学习这个知识点？”框，副标题为“为了解决什么问题，出现了这个知识？”。**内容仅显示“正在开发”**，未填充课程历史、未新增内容编辑接口，后续课程组内容维护另行实施。

## 接口及数据库部署

- `GET /api/profile/username`：读取当前昵称、免费资格、下次免费时间、费用及余额，响应禁止缓存。
- `PATCH /api/profile/username`：正常改名提交 `{ username, expectedUsername, allowPaid }`。`expectedUsername` 必须匹配当前值；`allowPaid` 必须为布尔 true 才允许付费。用户身份始终取认证结果，不接受请求体覆盖用户 ID 或费用。
- 新增 `database/migrations/034_username_changes.sql`：仅创建 `username_change_log`，不修改现有用户表。迁移可重复运行；服务启动也会执行同样的建表检查。需部署后端并确认新表存在，再验收改名入口。
- 新表记录用户 ID、旧/新昵称、改名种类、磁元费用和 UTC 时间。它不提供公开历史查询接口。
- 回退时保留已写入的改名记录和余额，不删除新表；若需撤销扣费，应根据流水由管理员核对处理，不自动倒扣或覆盖余额。

## 尚需真实数据库联调

本轮未连接真实 MySQL。模拟事务测试不能替代真实行锁、唯一约束、月底日期算法、迁移权限及故障恢复验证；涉及扣费，正式发布前应完成该项。

已提供显式开启的隔离集成测试：为专用测试 MySQL 配置 `USERNAME_TEST_MYSQL_HOST`、`USERNAME_TEST_MYSQL_PORT`、`USERNAME_TEST_MYSQL_USER`、`USERNAME_TEST_MYSQL_PASSWORD`，然后设置 `RUN_USERNAME_INTEGRATION=1` 执行 `node --test backend/username-changes.test.js`。

此测试只会创建随机命名的 `freebbs_username_test_<随机值>` 数据库，结束后删除它自己创建的库。使用具备创建/删除测试库权限的专用账号，**不要使用生产数据库账号**。它验证重复迁移、并发免费资格、扣费/重复提交、唯一约束回滚、月末及闰年边界。

正式环境还应验证：改名后新昵称和邮箱登录、管理员修改姓名、普通用户无法绕过限制，以及两台设备同时改名时只执行有效的一次。
