# PR #97：购买与赠送重试修复

## 行为

- 旧微分器购买入口使用固定请求编号识别购买意图；回放回执在读取当前购买次数之前完成。新版商城仍要求报价和购买次数校验。
- 赠送使用现有 user_profile_actions 表记录回执，包含物品、接收者输入与操作类型。回执与双方库存变更在同一个事务中提交；同编号更改目标或物品返回 409。
- 赠送重试优先返回原回执，即使最后一件已经送出，或接收者随后改名，也不会再次转出。
- 前端在同一登录会话、同一页面内保留失败操作编号，关闭并重新打开弹窗仍可重试；确认成功后再次赠送才生成新编号。整页刷新不保留这个内存中的编号，结果不明时应在当前页面重试原操作。
- 事务提交后立即释放连接，再查询最新资产，避免并发请求占满连接池后相互等待。

## 兼容与范围

- 旧微分器入口和赠送接口均要求 UUID requestKey；缺少编号时返回 400，不扣款、不转出。上线时前后端一起更新，旧页面用户需刷新。
- 复用 PR #97 的 038 迁移表，不增加数据库迁移。保持迁移初始化先于接口开放。
- 不涉及学习区、商品价格、装扮样式或发布操作。
