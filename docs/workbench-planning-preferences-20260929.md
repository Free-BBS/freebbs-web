# 工作台：课程保留、规划偏好与 Max 小伙伴

## 本次范围

- 已同步课程作为本地用户的个人安排保留。清华授权过期、解除连接、重连不会让课程或个人修改消失；删除过的课程事件不因重新授权而复活。
- 校历和节次是全站统一配置，使用用户提供的 2026–2027 校历与已确认节次，不再提供个人“保存校历”表单。秋季从 2026-09-14、春季从 2027-02-22 起算，各使用 16 个教学周；只跳过校历写明的假期，不推测调休补课。
- 新课程首次展示接入预览，用户确认后保存。普通同步只更新网络学堂快照，不能改动个人课表；“重新接入课程”主动同步、重新预览、再次确认后才更新副本。个人编辑和删除保留，不回写网络学堂。未知学期、不完整同步或零可识别安排不覆盖旧副本。
- 计划表不增加离线、缓存或断连徽标，连接状态只显示在账号连接区。
- Max 自动找空档时支持星期、起止时段、单次最长时长、任务间隔、每日规划总量和最多 4 段保留时间。手动指定时间的普通事件不受偏好限制。
- “看看今天空档 / 看看未来七天”为只读计算；普通事件、同步课程、休息时段和缓冲会被避开，DDL 不作为忙碌区间。
- 透明背景 Max 悬浮形象和可收起对话气泡。按日程冲突、临近 DDL、忙碌、连续安排、晚间、空闲和数据未就绪提供鼓励性文案。提示可关闭恢复；不推断情绪，不自动更改安排，不调用模型。
- 仍沿用逐项/全部确认预览。本次没有实现完整多轮聊天历史或自动重排已有事件。

## 数据与权限

课程快照仍按 FREE BBS `user_id` 查询，排除没有有效导入 generation 的旧快照；generation 用于来源修订，不再作为已保存个人课程的阅读授权。课程发生项 ID 包含学期、课程、周次和节次，个人修改按用户和发生项保留。跨用户无法读写。

“本地保存”指保存在 FREE BBS 账号下，而不是仅存浏览器缓存；跨设备仍可读取。新增 `calendar_copy_json` 保存已确认课程及其事件投影，普通同步不会写这个字段。重新接入要求有效的当前连接，确认时锁定连接与源快照并校验预览修订，避免多个窗口或同步期间用旧预览覆盖新数据。旧版已有课程在迁移时一次性保留，后续启动和迁移重跑均不自动接入新数据。

账号撤销、凭据销毁、后台同步作业取消、过期授权检查均保持原样。作业正文/附件和实时校园请求仍要求有效授权；没有放宽其服务边界。旧课程公告仍遵循原连接范围，不将新的课程保留策略推广到远端私有操作。

个人偏好存于 `workbench_planning_preferences`，API 登录后按当前用户读写。默认建议值在界面明确显示：09:00–21:00、每次最多 60 分钟、间隔 15 分钟、每天最多规划 120 分钟、午间 12:00–13:00 和晚间 18:00–19:00 保留，可修改或停用。每日上限在同批多个规划之间共享，已确认的 Agent 安排亦计入，不会通过重复生成绕开。

提示关闭状态按用户保存在本浏览器；未登录、换账号或请求失败时，不使用上一用户的日程给出提示。空档结果仅基于已记录日程，不代表真实生活中所有可用时间。

## 部署与验证

新增幂等迁移 `059_workbench_planning_preferences.sql` 与 `060_confirmed_course_import.sql`；启动初始化亦确保表和副本字段存在。060 仅在首次添加字段时将旧课程与原个人校历复制到新字段，不删除来源数据，也不更改个人事件覆盖记录。后续新增同步必须由用户确认。老客户端的个人校历 PUT 返回明确提示，不再改动统一配置。

- `npm run test:workbench`
- `node scripts/test-mysql-isolated.js --workbench-only`：只使用新建的隔离数据库，不触及生产数据。
- `npm run test:workbench:planning:browser`：内存模拟，检查偏好保存/刷新、只读空档、预览不自动保存、Max 气泡与关闭恢复、桌面/手机亮暗色布局。

- `npm run test:editable-calendar:browser`：统一校历、假期跳过、连续课合并、课程手动编辑与桌面/手机亮暗色布局。
- `npm run preview:editable-calendar`：本地内存预览；支持 `EDITABLE_CALENDAR_PREVIEW_PORT` 指定端口。不调用真实清华账号、邮件或模型。
