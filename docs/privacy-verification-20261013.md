# FreeBBS 隐私安排与无问芯穹数据处理核对

核对日期：2026 年 10 月 13 日。本文补充[全站数据清单](privacy-research-20261012.md)，供隐私政策起草和后续实现使用。当前保留所有管理员的 AI 对话导出权限，运营用途限定为必要调查；代码尚未强制落实这一用途限制。审核 Agent 继续保存在开发分支，待全站隐私政策及配套功能完成后上线。

## 已确定的运营安排

| 项目 | 当前安排 | 仍需落实的部分 |
| --- | --- | --- |
| 运营名称 | 按用户要求，草案暂写“FreeBBS 工作组” | 对外发布前明确实际负责个人信息处理及响应请求的人或组织，不推定学校为运营主体 |
| 隐私联系渠道 | 用户希望沿用网站现有的 `feedback@free-bbs.cn` | 仓库登录页有此邮箱；实际网页的新版页脚未显示。先列为拟采用渠道，确认收信及维护人员后补入政策和公开入口 |
| AI 对话导出权限 | 保留所有网站管理员的权限 | 管理员身份与具体导出用途分别控制；不新增其他角色的访问权限 |
| AI 对话导出用途 | 仅在必要调查时使用，例如调查明确的公约违规事件 | 把调查理由、有关用户、时间范围、操作记录及导出副本处置落实到流程与代码 |
| 供应商安排 | 由本站代码和供应商官方材料共同确定 | 公开文件未明确的事项形成询问清单，不能用本站的 30 天清理替代供应商承诺 |

“保留导出权限”不等于批准每次调查都导出全站所有用户的聊天。建议保留所有管理员的使用资格，同时让一次导出只包含与调查有关的用户、会话和时间段。此处是后续方案，尚未改动导出功能。

## 主站数据如何处理

以下是代码能力；正式服务器启用哪些功能、使用哪个云服务和备份多久，仍需部署信息确认。全站的 22 类数据场景见[原调研清单](privacy-research-20261012.md#全站数据清单)，本轮重点复核下列环节。

| 环节 | 已核实的处理方式 | 对政策的影响 |
| --- | --- | --- |
| 白名单与账号 | 白名单解析后的姓名、学号、邮箱等进入数据库；账号另有身份资料、密码哈希和角色 | 包括未注册白名单人员；不能称所有资料都仅在浏览器中保存 |
| AI 对话保存 | `ai_dialogs` 保存所属用户、标题、完整消息 JSON 和时间；管理员导出时与姓名、学号等关联 | 需要说明对话留存和管理员在必要情况下的访问，不能承诺只有聊天本人可读 |
| AI 对话读取 | 普通用户读取对话的路由校验所属用户；管理员另有导出接口 | 普通用户之间的隔离与管理员访问是不同权限边界 |
| Max 调用模型 | Web 先向内部 Agent 传递内容和用户上下文；模型客户端再形成请求，图片、历史及任务上下文可能参与处理 | 内部身份字段不能直接等同于外发字段；实际外发内容需按功能核查 |
| Max 文档 | 完成文件存为私有 PDF 和所有者元数据，逐页读取校验所有者；未完成分片有十分钟超时清理 | 分片清理不是完整文档的保存期限；本轮未发现完成文档统一到期清理逻辑 |
| 帖子与图片 | 主站支持隐藏或软删除；附件有单独路径和访问逻辑 | 页面不显示不等于正文、旧图片链接和缓存都已删除 |
| 通知与邮件 | 通知可包含内容摘录，并经配置的 SMTP 服务发送 | 需列明实际邮件服务商；已送达邮件不会随站内撤回而消失 |
| 学习分析 | 代码中有偏好控制、个人清除与 180 天事件清理 | 这是分析事件的安排，不涵盖所有笔记、答题和课程数据 |
| 发展板块 | 从主站映射 UID、学号、显示身份等，使用独立数据库及业务权限 | 个人信息请求和注销需要覆盖这一数据库及附件 |
| 待上线审核 | 文字尝试本地替换隐私字段，仍可能遗漏；图片处理不自动遮挡个人信息；审核证据按 30 天机制清理 | 必须说明实际外发范围；正常发布内容、残留元数据、备份及供应商副本另行处理 |

本轮读取的白名单、Max 文档、分片上传、通知、讨论区可见性、发展集成和 AI 对话建表文件，与本地上轮调研版本的 Git blob 一致。主服务和配置则按上述最新 main 直接读取；没有把最新 main 合入审核分支，也没有修改生产数据。

## AI 导出的现状与改进

[当前导出接口](https://github.com/Free-BBS/freebbs-web/blob/dd729c21732572fed83371b496b557bc20caa258/backend/server.js#L6008)经过 `requireAdmin` 检查后，查询全部用户及全部对话。没有按指定用户、会话或时间限制查询，也没有要求填写调查原因。

[导出文件结构](https://github.com/Free-BBS/freebbs-web/blob/dd729c21732572fed83371b496b557bc20caa258/backend/ai-dialog-export.js#L50)包含：用户标识、用户名、姓名、学号、角色、会话标题和完整消息，以及导出人和导出时间。消息解析失败时还会保留原始消息字段。

文件中的 `exportedBy`、`exportedAt` 不能代替服务器审计：文件可以被删除或修改，服务器无法仅靠它核实导出历史。在已核对的路由与构造函数中未发现专门持久化导出审计；生产代理或运维系统是否另有访问日志尚未核实。

在保留所有管理员使用资格的前提下，后续建议：

1. 导出前填写具体调查原因或事件编号，并选择有关用户、会话和时间范围。
2. 服务器记录操作者、原因、范围、数量、时间和结果；审计不再复制完整聊天正文。
3. 导出结果只供该次调查使用，明确副本存放位置、可访问人员和结束后的清理办法。
4. 全站导出不作为默认按钮；确有必要时另行说明范围和理由。调查单个用户不能默认携带其他人的记录。
5. 隐私政策如实说明必要调查中的管理员访问；“按范围导出”“每次留痕”等文字只能在功能实现后写成现行保障。

上述事项均是待实施任务，本轮没有修改权限、接口或数据库。

## 无问芯穹公开说明

官方材料提供了这些直接相关的事实：

- [隐私政策](https://docs.infini-ai.com/legal/privacy.html)列示服务主体为上海无问芯穹智能科技股份有限公司及北京无问芯穹科技有限公司；本站账号实际适用的合同主体仍需与订单或协议核对。
- [隐私政策](https://docs.infini-ai.com/legal/privacy.html)第 2.2 节称输入输出加密、隔离保存，调试解密需授权，并接入阿里云及网易内容安全服务；合作方清单列出网易接收请求、响应和请求标识。
- 同一政策第四部分原则上将境内产生的个人信息存于境内，并保留合同等例外；没有给出适用于本站 API 正文的固定天数。
- [FAQ 的会话历史问题](https://docs.infini-ai.com/support/faq.html)又称体验中心和 API 不保存会话历史。这与加密留存说明的范围关系不清，不能据此承诺零留存。
- [服务协议](https://docs.infini-ai.com/legal/terms-of-service.html)要求客户保护其处理的数据，允许必要的关联方或第三方服务。数据权属条款并不能证明不用作训练。
- 隐私政策第八部分限制未成年人使用其平台账号；其是否涵盖本站 API 下游的 14—17 岁学生，需要供应商明确适用范围。

在本次阅读的材料中，没有找到明确覆盖本站所用 API 输入输出的“不用于训练”承诺。也没有取得本站租户的专属合同或数据处理协议。公开文档页还有可能未反映最新信息的提示，最终应以适用条款和供应商确认衔接。

据此，政策起草应把“FreeBBS 自己保存的数据”“发送给模型服务的数据”“供应商及其下游保存的数据”分开。Qwen、Kimi、GLM 是模型名称，不能仅据名称认定请求还发给了各模型原厂；实际托管和转发路径决定接收方。

## 需要供应商明确的问题

以下是可交给客服的询问提纲；尚未发送邮件或联系供应商。其[隐私政策联系章节](https://docs.infini-ai.com/legal/privacy.html)提供的官方邮箱为 `privacy@infini-ai.com`。

1. 针对本站使用的 MaaS Chat Completions 文字及视觉接口，输入、输出、图片、内容安全记录和备份分别保存多久？FAQ 所说会话历史与隐私政策所说存储有什么区别？
2. 上述数据是否用于模型训练、微调、人工标注或服务改进？如可关闭，哪些开关或合同条款适用于本站租户及下游处理方？
3. Qwen、Kimi、GLM 对应服务由谁托管，是否转发原厂？阿里云、网易各接收什么、保存多久、在哪里处理，能否提供适用于本站服务的处理方清单？
4. 本站学生申请删除、撤回或注销时，运营方如何定位供应商记录并申请处理？是否支持按请求标识删除，例外保留和备份到期如何执行？
5. 本站面向高校学生且可能有少量 14—17 岁用户。贵方的平台账号年龄限制是否影响这些用户通过本站间接使用 API，是否有相应条件？
6. 本站账号适用的签约主体、数据处理协议、数据地域及调试授权方式分别是什么？

这些问题只需要服务名称、条款和处理安排，不需要提供 API Key 或真实学生对话。供应商答复前，不写“供应商不存储”“绝不训练”“本站删除后供应商同步删除”等保证。
