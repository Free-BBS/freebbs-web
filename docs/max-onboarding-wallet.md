## 用 Git Bash 拉取并隔离开发

Git Bash 中，Windows 的 `D:` 写作 `/d`；带空格的路径用双引号包住。先进入已有仓库，检查状态、工作区，再拉取远端引用：

```bash
cd "/d/E For Study/Doctor/101 团委辅导员/电子系自主学习平台建设/99 CodeX/100 Code/freebbs-web"
git status --short --branch
git worktree list
git fetch origin --prune
```

`git fetch` 更新远端分支信息，不会切换当前学习区的分支，也不会覆盖未提交文件。首次创建本次独立实验区时，使用：

```bash
git worktree add ../freebbs-web-onboarding -b feat/max-onboarding-wallet origin/main
cd ../freebbs-web-onboarding
npm ci
```

当前任务已经创建了这份 worktree，不要重复执行 `worktree add`。再次打开时直接进入：

```bash

git status --short --branch
npm run preview:onboarding
```

如果需要跟进已经推送的同名分支，在该独立目录没有未提交改动时使用 `git pull --ff-only`。它只允许快进更新；遇到分叉会停止，不会自动制造合并。不要为了运行预览，在学习区里切换分支或合并本次改动。

## 以后如何发布新版短游

发布清单位于 `public/max-guide-releases.js`，完整站点位于 `public/max-guide-stations.js`。已有发布进度使用稳定 release ID 保存，不要复用旧 ID 冒充新发布：

`guide-depth-2026-09` 已正式发布，包含开发阶段追加的 `profile-ranch` 与 `profile-wool`，共 9 步；后续不可再以开发阶段为由重排该发布记录。已发布版本按以下约定保持稳定。

1. 在站点配置中定义真实可用、带稳定 ID 的新步骤；实质改变旧步骤含义时新增步骤 ID，不挪用旧 ID。
2. 在 `RELEASES` 尾部追加新记录，填写新的 `id`、标题、说明、日期、亮点，以及该版显式且固定顺序的 `stepIds`。当前 `guide-depth-2026-09` 已固定自己的 9 个 ID，不再依赖以后可能变化的通用 `RELEASE_STEP_IDS`。
3. 保留旧记录和旧版引用的步骤；不要删除、重排已经发布的 `stepIds`，否则已保存的数字步骤位置会指向其他内容。冻结数组只是运行时保护，仍需代码审查遵守这个约定。
4. 前后端共用发布清单；服务端版本白名单随清单生成，现有 `(user_id, guide_version)` 表支持新的 release，不需要为每次发布清空任务或改造表结构。发布数组最后一项是当前推荐短游。
5. 运行导览与预览相关测试，确认每个 ID 存在，并人工检查新账号、已看过旧版账号、新版仅邀请一次、跳过后不重复自动弹出和主动重看。不要只验证最新版本而破坏旧版续看路径。

## 鱼骨出售与账本规则

| 物品     | 服务端标识          | 出售单价                           |
| -------- | ------------------- | ---------------------------------- |
| 普通鱼骨 | `ordinary_fishbone` | 1 磁元                             |
| 黄金鱼骨 | `golden_fishbone`   | 10 磁元                            |
| 坚硬鱼骨 | `fishbone`          | 本次不增加出售能力，原购买价格不变 |

普通鱼骨与黄金鱼骨统一在仓库的“鱼骨回收小站”展示持有量、单价和出售入口，不重复放入普通商品库存网格。出售前确认数量与收入；服务端只接受正整数数量和允许出售的鱼骨种类。库存扣减、磁元入账、账本和请求回执在同一事务提交；重复提交同一请求不重复出售，并发请求不能超卖。出售收入不产生消费热力。已有资格的“鱼骨达人”成就在卖出前补齐，已获得铭牌保留。

出售接口：`POST /api/shop/sell`，请求体 `{ itemKey, quantity, requestKey }`，其中 `requestKey` 是 UUID。响应的 `receipt` 包含数量、服务端单价、磁元收入、剩余物品数量和余额快照；网络不确定时应保留原请求编号重试。成功后重新读取账户与仓库，不能把重放回执中的旧余额当作实时余额。

账本由仓库按钮打开，可在窗口内滚动、筛选电元或磁元、刷新并继续加载旧记录。每条展示收入/支出、原因、发生时间和“此笔后资产”。电元与磁元分别展示，避免把两种单位相加为无依据的单一总额。

本轮追加的账本视觉调整仅放大说明、收支和余额等文字，保留原有窗口、滚动区域、筛选/分页结构和数据语义，没有另做一套布局或改变交易规则。导览将筛选栏与首条收支分别讲解，不把整个长窗口当作一个巨大聚光目标。

账本接口沿用 `GET /api/wallet/ledger?currency=all|electric|magnetic&before=<id>`，每页最多 30 条。`electric_before`、`electric_after`、`magnetic_before`、`magnetic_after` 是十进制字符串：

- 本次收支分别由 `after - before` 计算。
- “此笔后资产”必须来自该条的 `electric_after` 与 `magnetic_after`，不能反复使用当前钱包余额。
- `title` 与 `reason` 用于说明原因。旧记录没有附加原因时如实显示未附加说明，不猜测或伪造历史。
- `nextCursor` 非空时可以读取更早记录。切换账号或筛选条件后旧请求不得混入新列表。

## 新增牧场羊毛玩法

商城「伙伴」分类新增橡胶棒 `rubber_rod`：7 磁元，累计限购 1 根，不可赠送，永久持有且可反复使用；摩擦不会消耗橡胶棒。代码原生图标位于 `public/assets/icons/rubber-rod.svg`，沿用现有商品图标风格，不使用外部图片或 ImageGen。

在现有 Max 喂养规则上，每累计 5 次有效喂养增加 1 份待剪羊毛。喂养仍会消耗小鱼，并遵守运势与饱腹容量条件；已有鱼骨产出规则保留。按北京时间每天最多剪 1 份，其余待剪量继续保留，次日 00:00 恢复剪取机会；当天第二次剪取返回「Max 被薅秃了，明天再来吧。」并保留羊毛。用户在牧场手动剪下后得到 1 份已存羊毛，再用橡胶棒摩擦：羊毛摩擦后橡胶棒带负电，每份羊毛换 2 电元。每日限制针对剪毛，已剪库存可逐份摩擦；待剪与已存数量属于牧场状态，不创建羊毛商品或仓库条目。

沿用 `POST /api/profile/extras`，提交 `{ action: 'shear' | 'rub_wool', requestKey: UUID }`；每次处理 1 份。响应和后续读取通过 `ranch.feedProgress`、`ranch.woolReady`、`ranch.woolStored` 表示进度、待剪和已存量；`ranch.shearedToday` 表示当天是否已剪，已剪时 `nextShearAtMs` 为下一北京时间 00:00 的 UTC 毫秒，否则为0。自己的状态另含 `rubberRod` 布尔值。同日重复剪取返回 HTTP 400；原成功 UUID 重放只返回原回执，跨日重放也不占新一天次数。摩擦收入进入余额快照账本，不增加花费热力；不把羊毛收入与出售鱼骨混为同一条记录。

本地导览预览保留已入住的 Max，初始给 10 条小鱼、不预送橡胶棒。可先从今日运势读取本地演示运势，再自行购买橡胶棒；两轮喂养可以在同日完成，但第二份剪毛须等到下一个北京时间自然日。HTTP 自动测试通过注入时间跨过北京时间午夜，先验证同日拒绝且待剪量保留，再验证第二次剪毛和工具复用，没有关闭每日限制。浏览器预览使用实际时间。这些操作仍只改变本地内存；重启后还原演示账户。新增玩法的自动化和真实浏览器验收必须另记本轮结果，不能沿用前一版完成记录。

## 数据库变更与兼容性

新增迁移 `database/migrations/045_user_onboarding.sql`，仅建立 `user_onboarding` 表，以 `(user_id, guide_version)` 为主键。保存导览状态、当前步骤、探索任务和首次看见/跳过/完成/更新时间。外键随用户删除清理对应进度；不修改已有用户资料、课程记录或资产。

`backend/onboarding.js` 通过 `ensureOnboardingTable` 幂等建立表，正式运行需具备现有迁移流程所要求的建表权限。`GET`、`PATCH`/`POST /api/onboarding` 只操作当前登录用户；任务进度在行锁下合并，旧标签页不覆盖已完成任务，重开导览不会生成奖励。

羊毛玩法另新增 `database/migrations/046_ranch_wool.sql`，独立保存牧场喂养进度、待剪与已存羊毛，初始均为0，并记录初始为空的最后剪毛日期；不从历史喂养、鱼骨或库存反推补发羊毛或剪毛次数，不创建羊毛资产。剪毛与摩擦沿用账号事务和幂等回执；摩擦入账仍需现有余额触发器生成账本快照。正式发布须执行并验证该迁移，本地纯内存测试不等于真实 MySQL 联验。

鱼骨出售复用既有 `037_shop_purchase_progress.sql` 的计数与幂等回执，以及 `041_wallet_ledger.sql` 的账本。余额触发器仍须存在；本次没有重写历史余额或伪造历史账本。正式发布应沿现有环境的迁移流程执行并验证，内存预览不会执行数据库迁移。

## PR 简介

新用户进入 FREE BBS 后，可以从首页打开 Max 探索手册，并通过 43 步/12 站、可暂停、跳过、跳站和继续的聚光导览认识现有功能。五项访问任务独立保留；9步新功能短游按稳定 release ID 保存每账号一次的邀请与独立进度。尚未开放的知识工具、发展端与学习闭环按现状和未来规划说明。导览依赖并行加载并设超时，桌面历史侧栏避免重复等待。

仓库增加普通鱼骨与黄金鱼骨出售，分别收入 1/10 磁元；交易具备库存校验、幂等和原子账本记录。钱包账本改为可点击、可滚动的窗口，逐笔展示收支、原因和交易后的两种资产余额；本轮仅追加文字放大。设置保留实际编辑表单，并在标题右侧提供当前账号的主页入口。新增独立内存预览，便于本地验收，保持与学习区实验分支隔离。

牧场 Max 更新为四足短圆脸、奶油卷毛与眼镜造型，剪毛后显示短绒。每5次有效喂养长1份待剪羊毛，按北京时间每天最多剪1份，多余待剪量保留；当天再次剪取提示「Max 被薅秃了，明天再来吧。」商城新增7磁元、限购1根的永久橡胶棒，剪下的羊毛每份可摩擦换2电元，棒持续保留；羊毛仅存于牧场，交易记入余额快照账本。
