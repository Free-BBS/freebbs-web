# FreeBBS 审核规则库与来源

版本：`freebbs-policy-2026-10-09-v3`。本轮来源核查日期：2026-10-09（各来源保留各自核查日期）。适用于讨论区的隔离测试。

规则数据位于 `backend/moderation-policy-library.json`，共 30 个条目：28 条禁止项（`kind=prohibition`）和 2 条独立关怀提示（`kind=support`）。禁止项覆盖 11 个实际风险类别，包括 `political_compliance`；原来的 `other` 与 `sexual_minors` 仅供历史显示，不是当前风险类别。心理支持是独立的 `supportPriority`，不是“心理疾病违规”分类。本文与 JSON 同属版本控制；修改条件、例外或处置含义时必须更新版本及回归样例。

## 禁止项与关怀提示目录

负责人规则库中的禁止清单显示 28 条禁止项，关怀提示独立展示。禁止项的 `positiveExample` 表示进入本条禁止范围核查的例子，`negativeExample` 表示“不因本条禁止”的例子。对于 `human_review`，前者只是需要核实的疑似情形，不能凭示例直接认定违规或违法，也不能自动拒绝；不因本条禁止也不表示已通过其他规则。关怀条目的两个例子分别说明“需要这种关怀”和“不需要按这种关怀处理”，不具有禁止含义。所有示例均为编造，不含可识别真实身份或危险方法。

工作台中的例子用于说明条款适用情形；自动测试应另编实际发帖语气的虚构样例，并独立确认预期结果。“虚构测试”等说明文字和负责人核实提示属于例子的背景说明，整段复制给模型会改变引用与创作语境。

## v3 本轮调整与边界

- 隐私-004 改为所有年龄均适用的敏感个人信息保护，涵盖可识别医疗健康、生物识别、金融账户、行踪轨迹等资料；日常讨论不再单列“未满十四周岁个人信息”。这没有修改法律的年龄门槛；帖子提及第三方儿童时，相关保护要求仍须另行核实，不能因注册用户年龄较大而宣称不存在该情形。
- 旧“未成年保护-001”从当前清单退役，保留旧编号与历史含义；新“性剥削-001”覆盖所有年龄。新增“性招揽-001”和“性暗示-001”，与“色情-001”共同覆盖用户确认的限制范围。“sexual_minors”不再进入当前类别选择或模型输出；历史记录仍能阅读。
- 色情、性招揽、性暗示挑逗及性剥削不因成年、自称自愿或不收费而豁免本站规则。性暗示属于需要结合语境核实的社区限制，不据此断言已经构成违法色情。普通恋爱交友、正常性健康知识、反性骚扰求助及必要新闻和学术引用保留。
- 政治内容从 3 条细化为 9 条。国家秘密由政治内容-004单独核实；旧政治内容-002中的宗教问题转由政治内容-006/007处理，宪法基本原则由政治内容-009处理。编号不重用为无关含义；历史快照不被新标题覆盖。
- 政治条款均保留人工核查，不能单凭政治标签升级为机器高风险或自动拒绝。民族、宗教、人物名称、政策批评和学术讨论不构成独立触发条件；国家秘密、组织法律性质、英烈身份及具体行为不得由模型臆定。明显的人身威胁等独立风险仍按对应条目处理。
- 不新增笼统的“政务谣言”类别。明确捏造与待核实事实分别使用既有虚假信息规则，未见官方报道不等于已证伪。

## 全局原则与旧版本记录

正常表达保护、普通心理求助、引用语境、受害者保护及提示注入隔离写入全局 `principles`，适用于每一次审核，不再与禁止项混排。正常批评不需要命中一条“允许规则”才能通过。比如“我认为这项申请政策不公平，希望公布标准并接受申诉”应按正常表达保护；恶意伪造证据不因此豁免。

原 `EXP-001`、`MEN-001`、`SYS-001`、`GEN-001` 不再是可返回编号。存在具体潜在伤害但没有适用禁止项、关键语境不足时，模型在 `uncertainties` 说明缺失事实，由本地程序建议人工核查，不生成兜底违规类别。模型不熟悉主题或无法独立核实一切，并不构成核查理由。

v2 曾把 22 个旧条目映射为中文编号；v3 对隐私、性相关和政治条款作了上述调整，旧记录继续使用当时的快照与版本。`legacyRuleIdMap` 及模块导出的 `LEGACY_RULE_ID_MAP` 仅用于历史显示：PRI→隐私、HAR→骚扰、THR→威胁、HAT→仇恨、SEX-001→未成年保护-001、SEX-002→色情-001、VIO→暴力、FRA→诈骗、ILL→违法交易、MIS→虚假信息、POL→政治内容、MEN-004→自伤教唆-001、MEN-005→危险诊疗-001、MEN-002/003→关怀-001/002。保留的组内序号不变，特别映射以 JSON 为准。

历史审计保留当时的版本、编号和依据，不通过映射重写为新版结论。`getPolicyRule` 只接受当前中文编号；机器使用旧编号必须重新审核，不能借历史显示映射绕过当前校验。旧规则卡中的“其他”“未成年人性风险”及退役条目仍可作为历史文字呈现，不进入新版选择项。旧版反馈和测试样例须按 v3 重新复核；仅替换版本字符串不能迁移预期答案。

## 两项独立判断

机器对内容提出风险意见，本地程序根据规则条件形成动作建议。`kind=support` 且 `supportOnly=true` 的关怀-001/002 不能加入违规类别；例如“无内容违规 + urgent”是合法组合，关怀-002 仍可因保护性复核建议暂缓公开。普通关怀不需要扣分或禁言，也不产生医疗诊断或政治倾向档案。

政治相关疑点必须指出具体行为和适用条款。仅有敏感名称、机构、历史事件、不同意见或批评情绪不构成触发条件。人物身份、信息密级、事实真假和组织法律性质不能由模型臆定。独立的暴力威胁、骚扰或隐私风险仍适用相应规则，不能靠表达保护原则豁免。

模型只可返回已知规则编号及输入中真实存在的证据。来源标题、链接、条号由本地库补全；匹配条款是候选依据，仍要检查例外。解释不能虚构上下文、年龄、授权、违法罪名或额外分类。图片没有实际审核完成，不能用文字结论批准图片或整个帖子。

## 与 PolicyAgent 展示稿的衔接

采用结构化规则、证据与依据并列、受约束的处置建议、人工改判审计和回归样例的思路。初版规则数量有限，完整提供适用条件和例外，不引入 Chroma，也不声称已经复现展示稿的检索系统或实验成绩。不能把“检索到法律条款”当成违规证明，也不能把模型自报置信度视为经过校准的准确率。

人工反馈只有在获得所需授权并去除真实隐私后，才能整理为明确标注的回归样例。应保留允许表达、求助、占位符、语义反转、引用和提示注入等反例；只验证 JSON 能解析不足以证明规则有效。新规则至少需要检查漏报、误报、无依据的额外分类、证据是否对应输入和关怀是否被误当处罚。
