# FreeBBS 审核规则库与来源

版本：`freebbs-policy-2026-10-08-v1`。来源核查日期：2026-10-08。适用于讨论区的隔离测试。

规则数据位于 `backend/moderation-policy-library.json`，共 26 张规则卡，覆盖原有 12 类风险并增加 `political_compliance`。心理支持是独立的 `supportPriority`，不是新的“心理疾病违规”分类。本文与 JSON 同属版本控制；修改条件、例外或处置含义时必须更新版本及回归样例。

## 规则卡目录

页面统一使用“适用本规则的示例”和“不适用本规则的示例”。它们描述是否符合这一条规则，不等同于“违规”和“安全”：例如 EXP-001 的适用示例是应受保护的正常批评，不适用示例是不能用表达保护规则豁免的恶意伪造证据。是否需要其他处理仍应结合其他规则判断。所有例子均为编造，不带可识别真实身份或危险方法。

规则编号是本站内部标识，由主题缩写和组内序号组成。`EXP-001` 中，`EXP` 取自 Expression（表达），`001` 表示表达保护组的第 1 条规则。编号用于查找、引用和审计，不是法律条号、风险等级或处罚编号；法律条号另列于来源字段。此次调整仅澄清界面措辞，规则编号、适用条件、示例归属与规则版本不变。

## 两项独立判断

机器对内容提出风险意见，本地程序根据规则条件形成动作建议。`supportOnly=true` 的 MEN-001/002/003 不能加入违规类别；例如“无内容违规 + urgent”是合法组合，MEN-003 仍可因保护性复核建议暂缓公开。普通关怀不需要扣分或禁言，也不产生医疗诊断或政治倾向档案。

政治相关疑点必须指出具体行为和适用条款。仅有敏感名称、机构、历史事件、不同意见或批评情绪不构成触发条件。人物身份、信息密级、事实真假和组织法律性质不能由模型臆定。独立的暴力威胁、骚扰或隐私风险仍适用相应规则，不能靠保护表达卡覆盖。

模型只可返回已知规则编号及输入中真实存在的证据。来源标题、链接、条号由本地库补全；匹配条款是候选依据，仍要检查例外。解释不能虚构上下文、年龄、授权、违法罪名或额外分类。图片没有实际审核完成，不能用文字结论批准图片或整个帖子。

## 与 PolicyAgent 展示稿的衔接

采用结构化规则、证据与依据并列、受约束的处置建议、人工改判审计和回归样例的思路。初版规则数量有限，完整提供适用条件和例外，不引入 Chroma，也不声称已经复现展示稿的检索系统或实验成绩。不能把“检索到法律条款”当成违规证明，也不能把模型自报置信度视为经过校准的准确率。

人工反馈只有在获得所需授权并去除真实隐私后，才能整理为明确标注的回归样例。应保留允许表达、求助、占位符、语义反转、引用和提示注入等反例；只验证 JSON 能解析不足以证明规则有效。新规则至少需要检查漏报、误报、无依据的额外分类、证据是否对应输入和关怀是否被误当处罚。

## 真实用户启用前仍需完成的治理工作

本库已经核对所列官方来源并形成可测试条件，但没有因此取得个案法律审查或危机处置能力认证。需要由平台负责人明确最终社区条款和申诉渠道，复核政治相关边界，并请熟悉心理危机支持的人员核对值守、接单、升级和现实求助流程。未建立相应响应能力前，不向用户承诺实时救援。

外部 API 所需数据应按必要性和适用处理依据单独评估。本人同意不是帖子提及的第三方的同意；姓名替换后仍可能通过经历、病历或宿舍别称识别个人。个保法第二十一条的委托处理与第二十三条的向其他处理者提供应按实际关系判断，不能混用或笼统宣称每次调用都须相同形式的同意。与身份关联的医疗健康信息和未满十四周岁信息需专门措施。[个保法依据](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

日常审核材料的一个月保留目标不能替代所有法定留存。网络暴力处置记录与合法证据保全需另行确定；个人信息保护影响评估报告和处理情况记录，个保法第五十六条规定至少保存三年。该期限也不表示每份帖子原文都应保存三年。供应商留存另按已核实合同和设置处理，不能承诺跟随本站自动一个月删除。[网络暴力记录依据](https://www.cac.gov.cn/2024-06/14/c_1720043894161555.htm)、[个保法留存依据](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

官方来源或社区规则变更时，更新来源、版本、卡片条件和例外，先跑固定虚构样例，再人工复核边界；不得由模型在运行时自行修改政策库。
