# 清华校内连接器：实现状态与验证方法

## 当前结论

截至 2026 年 8 月 1 日，FREE BBS 已具备以下能力：

| 能力                                 | 状态                   | 可复核证据                                                         |
| ------------------------------------ | ---------------------- | ------------------------------------------------------------------ |
| 清华公开通知页抓取与解析             | 已实时验证             | 固定公开 URL 的 HTTP 状态、响应字节数、SHA-256、解析版本和通知摘要 |
| `learn.tsinghua.edu.cn` 认证边界探测 | 已实时验证             | 不带凭据请求首页，记录登录边界，不跟随跳转                         |
| `info.tsinghua.edu.cn` 认证边界探测  | 已实时验证             | 不带凭据请求首页，记录登录边界，不跟随跳转                         |
| 网络学堂课程、公告、三类作业解析代码 | 已实现，合成样例已验证 | `backend/tsinghua-learn-connector.test.js`                         |
| 网络学堂真实账号同步                 | 尚未验证               | 等待校方批准的 SSO / 服务端授权传输                                |
| 信息门户私有数据同步                 | 尚未实现               | 当前只有认证边界探测                                               |

“解析代码已实现”不等于“已经取得某位同学的私有数据”。工作台 UI 会明确显示这两种状态。

## 一分钟复核

要求 Node.js 版本满足仓库 `package.json` 中的约束，并已安装依赖。

### 1. 运行安全边界和解析合同测试

```bash
npm run test:tsinghua-connectors
```

这组测试使用本地合成响应，不访问个人账号，验证：

- 只允许 `learn.tsinghua.edu.cn` 的固定只读接口和正确 HTTP 方法；
- 拒绝任意主机、任意路径、查询参数和自动跳转；
- 识别统一认证跳转、HTTP 200 登录页、超时、429 和上游异常；
- 限制单次请求数、响应大小、课程数、并发数和请求频率；
- 不把密码、Cookie 值、原始响应或活动 HTML 写入快照；
- 解析课程、公告和未交/已交/已批作业，按上海时区生成截止时间；
- 作业状态重叠时优先采用“已批改 > 已提交 > 未提交”，避免产生过期待办；
- 上游结构变化时返回明确失败或部分成功，不伪装成空数据成功。

### 2. 运行真实联网证据探测

```bash
npm run probe:public-source
```

正常输出应同时包含：

- `publicSource.network` 为 `live`，并带有状态码、`contentSha256` 和解析条目；
- `portals[*].network` 为 `live`；
- 网络学堂和信息门户当前返回的认证边界分类；
- `credentialsSent: false`、`cookiesSent: false`、`redirectFollowed: false`。

该命令只访问固定白名单地址，不登录清华，不访问通知详情，也不抓取任何个人数据。公开通知条目可与输出中的 `source.url` 官方原页面逐项核对。

### 3. 在页面中查看

启动前后端并登录 FREE BBS 后，进入：

```text
http://127.0.0.1:3000/workbench
```

点击“运行连通性与公开解析自检”。页面会分开显示公开样本证据、两个校内系统的实时认证边界、私有解析模块状态，以及“真实账号同步未验证”。

## 网络学堂解析核心

入口文件：`backend/tsinghua-learn-connector.js`。

同步函数 `syncTsinghuaLearn()` 只接受由服务端注入的 `authorizedFetch`。它不接受浏览器提交的密码、Cookie、目标 URL 或用户 ID。当前固定访问当前学期、课程列表、课程公告和三类作业。

输出是供工作台后续写入层使用的规范化快照，包括课程、通知、作业、待确认重要事项、部分失败和无敏感值的响应证据。重要事项保持 `draft`，不能未经用户确认直接写入日程。

## 真实统一认证接入仍缺什么

目前仓库没有校方分配的 SSO 客户端配置、回调地址或受批准的会话代理，因此没有实现“点击连接清华 → 完成统一认证 → 同步个人数据”的生产链路，也不应伪造该链路。

获得正式接入条件后，推荐流程为：

1. 已登录 FREE BBS 的用户点击“连接网络学堂”；
2. 后端生成短有效期、一次性、绑定当前用户和来源的 `state`；
3. 浏览器跳转到校方统一身份认证页面；
4. 校方回调 FREE BBS 后端，后端校验并一次性消费 `state`；
5. 授权令牌或会话仅在服务端加密保存，前端 URL 和日志中不出现凭据；
6. 服务端按用户和来源执行 single-flight 同步，再将规范化数据幂等写入工作台；
7. 用户可以查看授权范围、最后同步时间、主动解绑和撤销授权。

如果正式 API 暂不可用而必须使用浏览器自动化，应将它放在隔离的 connector worker 中：每个用户独立浏览器配置目录，只让用户在清华页面输入密码，会话不导出到 FREE BBS 前端或 Agent 服务。该方案仍需完成校方许可、安全评审和账号级实测。

## 安全边界

- `freebbs-agent` 只消费已经规范化且获授权的数据，不接触清华密码、Cookie 或票据；
- 所有上游目标使用精确 HTTPS 白名单，不提供任意 URL 抓取接口；
- 请求要求手动处理跳转，登录跳转立即转换为 `authorization_required`；
- 响应正文有流式大小限制，单次同步有总时限、请求预算、课程上限、并发上限和最小间隔；
- 响应 Cookie 只记录“是否出现”的布尔证据，不保存值；
- 错误、日志和 API 响应不得包含 `ticket`、`state`、Cookie、令牌或原始私有页面；
- 用户修改过的待办和日程，后续同步不得无痕覆盖。

## 下一阶段验收

真实账号链路只有在以下条件全部满足后才能标记为“已验证”：

- 校方批准的授权方式和回调配置可用；
- 测试账号明确授权；
- 至少完成课程、公告和三类作业各一条真实数据核对；
- 真实同步不会跨用户、重复写入或覆盖用户修改；
- 退出登录、会话过期、429、超时和结构变化均有可理解的降级结果；
- 日志、数据库和浏览器开发者工具中均未泄露密码、Cookie 或票据。
