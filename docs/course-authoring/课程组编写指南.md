# FREE BBS 课程组编写指南

本指南对应 V4.2 模板包，帮助课程组把一份课程资料整理为可阅读、可练习、可反馈的知识点稿件。模板与当前改版代码配套，正式上线前仍需完成部署、教学审核与网页回读。

每个知识点只编写一份正文。学生的四个自述起点（第一次学、不甚熟悉、能独立做题、完整掌握）与三个目标（理解知识、练习解题、探索研究）复用同一份正文和题目，系统调整推荐入口与步骤，不要求编写十二份教材或十二套题。“完整掌握”是学生自述，不是平台测量得到的能力等级。

## 一、一个知识点最少交什么

复制[知识点模板](templates/知识点.md)，保留三个二级分区：基本信息、知识背景与应用、知识点正文。其余内容用三级及以下标题。

| 内容       | 最小可交付要求                                                                               | 对应网页                         |
| ---------- | -------------------------------------------------------------------------------------------- | -------------------------------- |
| 基本信息   | 正确名称、稳定ID、所属实际章名、类型与层级、难度与重要程度、建议时长、同意公开署名的参与同学 | 学习概览、章节目录               |
| 概览       | 首段不超过150字符，说明本节学什么、解决什么问题                                              | 进入知识点时的学习概览           |
| 知识起源   | 说明为什么需要这个知识、原有方法遇到什么问题；历史叙述有出处                                 | 正文前可收起的知识起源           |
| 正文       | 关键概念、必要条件、方法或推导、一个能说明问题的例子、主要依据；可以精简，但不能省掉适用边界 | 所有人共用的官方正文             |
| 练习与思考 | 保留这一小节，提供与目标相符的任务及反馈依据，不统一规定题数                                 | 形成性练习；有评分扩展时生成题卡 |
| 来源与署名 | 核对教材版本、页码或链接、题目及图片授权、编写与复核责任                                     | 公开依据与提交记录               |

没有可靠历史资料时，可以从现实问题和方法限制解释知识起源，不必强行写人物故事。难度（1–5）与重要程度（1–5）是知识点概览字段，不自动决定每道题的难度。

学习页的正文、资源、题目、继续、笔记、共建是工具入口，不是六份课件或六个上传分区。私人高亮、下划线与评注依托同一份正文和原文位置保存，不改变官方文字；课程组不收集或上传学生的私人笔记和答案。

## 二、概览、起源和正文不要写成三遍讲义

三者回答不同问题：

| 部分     | 回答的问题                               | 写作边界                                         |
| -------- | ---------------------------------------- | ------------------------------------------------ |
| 概览     | “这一节值得我看什么？”                   | 说清内容与用途，避免列满公式、历史和所有学习步骤 |
| 知识起源 | “为什么要引入这个知识？”                 | 说明问题、动机与意义，不用重复全部推导           |
| 正文     | “它具体是什么，什么时候成立，怎么使用？” | 定义、条件、推导、例题和结果检查写在这里         |

例如“卷积与拉普拉斯变换”：概览可以说明它把时域卷积联系到变换域乘积；起源解释直接积分较繁琐时为什么需要变换方法；正文再给出卷积定理、收敛域条件和零状态响应的计算与核验。完整样例见[SS-02-01](examples/知识点/SS-02-01.md)。样例是格式稿，保持 `draft`，不能未经教学复核直接发布。

正文先保证一条完整、可靠的基本解释链，再补充边界、替代方法或延伸问题。新手可顺着例子阅读，熟悉者可直接核对条件或做题，查阅者与科研探索者也可直接看关系和依据；不要求所有人依次阅读、做题、拿星。

## 三、难度与用途是两条独立维度

### 三档难度怎样估计

以下是课程组的工作判据，不是实测题目参数、布鲁姆认知等级或学生能力定级。先写清假设的前置知识、提示多少及解题步骤，再估计难度；不要只按题目长度、题型或“看起来高级”分档。

| 难度字段         | 编写时可参考的负担                                                   | 适合怎样的反馈                   |
| ---------------- | -------------------------------------------------------------------- | -------------------------------- |
| `basic` 基础     | 在明确条件下识别一个关键概念、直接运用已说明的方法，步骤和提示较充分 | 检查定义、符号与基本条件是否理解 |
| `standard` 标准  | 在常见情境中独立选择方法，处理多个条件或步骤，并核对结果             | 定位漏条件、步骤衔接与计算问题   |
| `challenge` 挑战 | 较少提示，需整合多个知识、审视边界、比较方法或处理较不熟悉的情境     | 检查推理依据、适用边界与方法选择 |

这些负担可能重叠，不能仅凭认知动作就断定难度。一个证明题可以是熟悉的基础任务，一个单选题也可能需要复杂判断。难度可省略；不确定时先保留未分层，比虚构“已校准”更可靠。后续若依据真实数据调整，需另行记录样本、方法和适用范围。

### 三种用途怎样安排

| 用途字段           | 主要目的                                             | 是否进入正式自测与授星分母                      |
| ------------------ | ---------------------------------------------------- | ----------------------------------------------- |
| `practice` 练习    | 在学习过程中尝试、获得反馈、订正理解                 | 否；练习正确不替代正式作答                      |
| `selftest` 自测    | 按事先确定的目标与规则形成正式作答证据               | 只有有效、已审核的 `published` 块中该类题才进入 |
| `exploration` 探索 | 提出问题、比较方法、建立联系或检验想法，可为开放任务 | 否；不自动授正式自测星                          |

难度不决定用途：基础题可以是正式自测，挑战题也可以是练习或可选探索。同样，探索不一定必须很难或没有明确答案。不要把需要所有学生完成的题标成“可选探索”，也不要为了让探索显得重要而混入正式分母。

## 四、每道题要让学生知道检查什么、错在哪里

写好题干，再复制[评分扩展模板](templates/自测题-评分扩展.md)。不用自动判分的普通 Markdown 题仍可保留为练习。

每题核对以下内容：

- 目标：用可观察的行为写清检查什么，如“解释收敛域的必要性”“独立核验积分范围”，不只写“全面掌握”。对应 `learningObjective`；它会公开显示，不放标准答案。
- 题干：写全条件、求解对象、单位约定、可用资料及必要图示，不依赖未上传附件。
- 解析：在 `explanation` 中说明正确答案、关键依据和成立条件，不只给一个选项或结果。
- 误区：在 `misconceptions` 中指出具体遗漏或错误推理，以及如何检查；不要给学生贴能力标签。
- 评分：客观题明确答案或容差；主观题的 `rubric` 写分项、部分分规则及可接受的等价论证。`maxScore` 与 `passScore` 先由课程组确定。
- 来源：记录真实出处或“课程组自编”，确认授权；题号与正文保持一致。

单选和多选按完整匹配判分，多选漏选、多选不给部分分；数值题只接受有限标量，容差必须明确。简答、计算过程和证明由有权限的课程负责人复核，提交后显示待复核，不让Max自动认定正式通过。

评分扩展中的参考答案、详细评分依据、解析与误区在作答后由服务器返回。普通 Markdown 练习原有的折叠参考解答仍可主动查看；这种练习适合形成性反馈，不是监考、闭卷考试或答案保密机制。不要据此宣称学生在无提示条件下独立掌握。

## 五、正式自测要先确定完整集合

先列出本知识点必须检查的核心目标，再选有代表性的题，而不是把所有练习都改成正式题。覆盖目标、避免重复并控制复核工作量，比凑题数更重要。

当前正式通过按每道正式题的通过标准核对，不是靠高分题抵消未通过题。自测页显示当前发布的全部 `selftest` 题；练习难度筛选、自述起点和当前目标都不能减少这个分母。正式主观题尚待复核时，全集不能声称已通过。可选探索、练习、AI临时题不进入正式证据。

例如样例 SS-02-01 在真实审核并有效发布后，可构成为：Q01基础练习，Q02基础自测，Q03和Q04标准自测，Q05挑战自测，Q06可选探索。正式集合为Q02–Q05，共4题，包括Q05的人工复核；不是选了基础难度就只做Q02。原样例仍是 `draft`，此处解释设计，不是授权将演示题改成正式课程。

若挑战题不适合成为本节的必做门槛，课程组应在审核阶段将其安排为练习或探索，而不是发布后对不同学生悄悄过滤。没有正式题时可以先使用正文和练习，不制造正式通过或星标。评分扩展的1–40题是技术边界，不是目标题数，也不要求凑齐三档难度和四种题型。

改正文、题干、用途、答案、解析或评分时，保留旧稿并更新对应版本。旧作答仍是历史记录，不自动充当新版通过；移除正式题或改成探索，也不能把旧证据拼成新版完整通过。已经取得的星保留可追溯的历史来源，不靠教材更新悄悄撤回。

## 六、章节与跨章关系怎样交

每章使用[0级章节模板](templates/章节-0级节点.md)，填写实际章名、两至四个可检验的章目标、真实知识点清单及各点在本章的作用。0级是章概览，不是普通知识点的重复讲义。

章节整体网络图使用已发布的普通知识点位置及章内关系；不要再维护一份与正式地图矛盾的线网。全包另交[布局表](templates/布局.md)与[关系表](templates/关系.md)，新建节点提供坐标，更新已有位置须明确确认。

关系可以跨章，但限于同一课程的真实节点。当前上传类型只支持 `ordered`（历史学习顺序）和 `related`（补充关联）；教学含义与成立条件仍写在交付材料里，不把这两类自动当成已验证的前置关系。六类学术关系尚未迁移，不自行添加新类型。

课程入口聚焦单个知识点时显示全课程内的直接一跳关系，可包含跨章节点，不递归展开二跳。0级正文中的网络图则展示本章整体，两者用途不同。当前离线关系表只收录1级到1级连接；不要用0级连到所有子点代替章归属，也不根据子点关系推断章关系。

## 七、先做好必须项，再逐步增强

| 阶段       | 必须做到                                                                                            | 推荐增强或可选内容                                         |
| ---------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 初稿可交付 | 三分区与稳定ID；准确概览、问题起源、统一正文和练习/思考；来源、授权与署名；保持未审核评分为 `draft` | 补充例题、易混淆点与替代解释；按实际目标估计题目难度       |
| 课程组复核 | 核对知识条件、解答与评分；明确每题用途；有正式题时检查完整集合与主观复核负担；核对章名、节点和关系  | 试读后精简表达，记录题目估计依据，完善跨章联系             |
| 准备发布   | 离线检查通过；已有更新先回读revision；有权限人员按已审核稿上传；上传后回读与页面核验                | 增加评分题卡、可选探索及更多图示，不为齐套而凑题           |
| 后续迭代   | 保留版本与责任记录，修正已核实问题，不用学生私人数据覆盖稿件                                        | 根据实际反馈修改解释与误区；有可靠测量依据后再讨论难度校准 |

正文与练习先可用，不必等所有拓展写完才交稿。正式自测和对应授星证据只有在来源、审核、版本和评分规则有效后才成立；上传成功本身不会替学生产生通过证据。

## 八、谁写、谁审、谁上传

编写同学负责稿件、题目、解析、误区、依据和关系说明；课程负责人或指定复核者负责教学准确性、评分规则、用途及公开署名。发布人员负责使用现有工具导出、回读revision、上传和核验网页；权限由管理员明确分配，教师身份不会自动获得课程上传或题目复核权限。同一人可以承担多个角色，但提交记录要区分责任。

填写[课程提交说明](templates/课程提交说明.md)，记录本轮修改、审核结论、复核人和旧稿归档位置。`draft` / `published` 是评分扩展状态，不是节点上传接口的同名草稿字段；没有教学审核结论，不改成 `published`。离线工具只验证格式，不替课程组确认知识和答案。

当前正文保存到课程节点后即进入可见内容，没有独立的整篇草稿开关；评分扩展保持 `draft` 也不会隐藏正文。未审核稿先在本地整理，不要上传到正式课程节点作为临时草稿。

在包目录运行 `node tools/检查课程包.cjs "课程包"` 检查结构、编号、章节、布局、关系与可选评分；正常提交不用 `--allow-demo` 绕过示例保护。单节点检查、导出与权限配置详见[README](README.md)。

已安装课程上传Skill并安全配置凭据的发布人员，可以先执行这条只读回读命令（在该Skill目录中）：

```sh
python scripts/freebbs_course_upload.py get-node signals SS-02-01
```

它读取《信号与系统》的SS-02-01当前节点，不上传或修改内容。更新前核对返回的名称、概览、三个正文分区和 `revision`，在现稿上合并修改；revision是并发修改校验值，不是题目版本号。上传后再次运行同一命令，确认实际保存结果，再打开网页检查公式、起源、署名、题卡、章图与跨章关联。收到409或写入超时时先回读核对，不强制覆盖或盲目重传。
