# 通过通知查看内容处理结果

2026 年 10 月 13 日。此调整先用于台式机测试环境，正式网站仍按“隐私政策完成后再上线审核 Agent”的顺序推进。

## 作者看到的流程

讨论区取消独立的“我的提交”入口及个人送审列表。发帖与评论共用以下原则：

| 处理情况                 | 作者提示                                                                 | 负责人处理                                   |
| ------------------------ | ------------------------------------------------------------------------ | -------------------------------------------- |
| 内容交给自动审核         | 提交处显示正在处理；短时间内通过则显示已发布，不另发成功通知             | 自动审核继续处理                             |
| 自动审核通过             | 不给作者新增通知                                                         | 保留负责人复核提醒；含图内容保留图片复核任务 |
| 确实进入人工处理         | 一条“内容正在等待处理”的站内通知，可打开单条详情                         | 进入人工队列；政治与心理话题继续显示专门提示 |
| 等待后人工通过           | 原等待通知更新为“已发布”并指向已发布内容；保持已读状态，不新增未读或邮件 | 保留既有处理记录                             |
| 人工未通过或已发布后撤回 | 站内通知引导作者查看详情、处理说明及联系渠道                             | 由负责人作出最终决定                         |

仅在机器队列中等待不等于已经转人工，不据此发送人工等待通知。模型判断需要拦截时仍先交给负责人，不将模型输出直接当成人工最终拒绝。

自动审核已暂停时，新提交直接进入人工处理并通知双方。暂停前已排队的任务继续保持等待机器处理，恢复后再处理；它们不会仅因暂停就发送转人工通知。提交处仍提供单条详情链接，负责人也可以在待审核队列中查看和处理。

作者同时担任负责人时，仍可能收到负责人职责相关的提醒。“通过不通知”指普通作者通知，不取消负责人的复核职责。

## 单条详情与历史链接

- 作者通知打开 `/moderation?mine=1&id=...` 的“内容处理详情”。正常通过后更新的通知直接指向已发布内容。
- 旧的带提交编号链接继续可用；不带编号的个人页引导用户从通知打开详情。
- 页面只读取该条内容；后台继续校验作者或负责人权限，普通用户不能读取其他人的稿件和私有图片。
- 作者页面不展示负责人队列、规则清单、模型诊断或管理控件；未通过或撤回可查看负责人说明并通过 `feedback@free-bbs.cn` 提出异议。
- 材料到期后明确提示“相关材料已到期”。这不会将正常发布的帖子和评论一并删除。
- 通知不携带正文、姓名、风险引用等内容；具体材料通过登录后的受限详情查看。

## 台式机验收

使用一个普通账号发帖、另一个负责人账号处理；不要只用同一个管理员账号测试作者通知。

1. 普通账号的讨论区没有“我的提交”和“审核工作台”；负责人仍能进入审核工作台。
2. 提交一条普通文字建议：短时间内自动通过时提交处显示已发布，普通账号不新增成功通知。
3. 提交一条虚构的需人工核查内容：机器处理期间不弹人工通知，进入人工队列后收到一次等待提醒。重复刷新不会重复通知。
4. 将等待通知标记已读，由负责人通过：原通知变为“已发布”，链接可打开帖子或评论，未读数不增加。
5. 用另一条需人工核查的帖子测试拒绝：作者收到未通过提醒，详情显示说明和联系入口。评论也测试一次。
6. 发布一条虚构含图内容后，由负责人撤回：作者收到撤回提醒，公开内容无法继续访问，受限详情保留处理说明。
7. 使用普通账号打开另一个用户的详情链接应被拒绝；作者页不出现负责人控件。
8. 保持通知面板打开，让负责人处理等待内容：下一次通知刷新可显示更新后的文字，无须产生新的未读记录。

本次不更换文字、图片模型，不改变关键词和整句语义判断规则，不新增数据库迁移或数据清理周期。更新工具会在台式机应用前备份、暂停自动处理，更新后由负责人验收并恢复自动审核。

## 开发验证

- `test:moderation-policy`：450 项通过，0 失败、0 跳过；涵盖通知、提交提示、页面权限及原有审核规则回归。
- `scripts/test-mysql-isolated.js --moderation-only`：独立临时 MySQL 中 73 项通过，0 失败、0 跳过；验证发布、通知读状态、幂等、评论、撤回、暂停、审核记录与到期处理。测试服务器仅开放专用本地管道，未使用台式机或正式数据库。
- 浏览器：桌面与手机、明暗主题的 20 种作者详情组合通过，另验证无编号旧入口和无权读取他人详情的情况。使用虚构本地接口，未调用模型。
- 更新助手通过 PowerShell 5.1 的 46 项模拟检查。代码与更新包验证不能替代台式机更新后的实际账号验收；最终包的提交与 SHA-256 见包内清单和相应校验记录。
