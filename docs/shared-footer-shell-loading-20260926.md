# 统一页脚与加载稳定性复查

## 本轮调整

- 常规整页统一为四个页脚链接：关于 FREE BBS、FREE BBS 工作人员名单、清华大学电子系、电子系学生科协；工作组和备案号在下一行居中
- 共用 `page-shell.js` 的服务端模板补全缺失页脚，保留知识点编辑器、工作台弹窗等内部操作 footer，不处理独立电路嵌入页
- 页脚上边距 12px、内边距 10px / 8px，两行之间没有横线；电脑端外层底部留白压缩为 8px
- 顶栏在所有电脑宽度隐藏昵称，保留头像作为账号入口，其余控件右对齐
- 左下角“前往发展端”为图标和文字一起居中的轻量按钮
- 三种资产不再各自显示按钮外观，整个资产区域是同一个说明入口；热力、分隔空白也可点击，支持 Enter / Space 和弹窗关闭后的焦点恢复
- 手机端继续使用原有导航、资产布局及全高聊天输入区；页脚的四链接按窄屏折行

## 卡顿排查和处理

本地 Chrome 使用 4 倍 CPU 降速采样，原版问问 Max / 设置的首个内容帧曾处于未应用主题或字号的状态；后续初始化会引起重新排版。另有全站桌面内容入场动画 360ms，以及后续区块 35ms / 70ms 延迟。

本次处理：

1. 原有 typography 模块提前到 body 开头，只执行一次，在内容绘制前读取保存的字号、字体和明暗设置，不写入用户偏好
2. 移除整页进场位移淡入，以及跨页视图过渡；保留按钮、主题切换、牧场等有意义的互动
3. 搜索框首次测量延到下一动画帧，让桌面顶栏先完成挂载，避免先测量旧布局再立即搬移的额外工作
4. 页脚在服务端输出，不等待客户端脚本加载后再插入

修复后采样的问问 Max、设置、实验室首帧均已使用保存的明暗和字号设置，未再触发入场动画。仍存在账号会话恢复和数据加载引起的小幅内容变化，不能据此宣称所有网络、设备上的加载耗时为零，也未对线上服务的接口耗时做结论。
