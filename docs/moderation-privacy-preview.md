# 本地脱敏预览

这是本地检查隐私替换效果的步骤。现有人工审核、负责人权限和 90 天证据期限继续有效。此预览操作本身不调用模型；独立的 [无问芯穹文字试审](moderation-ai-test.md) 可在本机测试环境手动调用。没有自动放行、图片 OCR 或图片遮挡。

## 使用

负责人在审核工作台打开一条待审核帖子或评论，在人工决定区域下方点击“生成本地脱敏预览”。预览同时处理标题和正文，保留原稿；可在“补充需要隐藏的信息”中每行输入一项遗漏的信息，再生成新预览。修改补充信息会立即清除旧预览。

替换来源包括当前稿件中命中的站内姓名、学号、邮箱，常见联系方式和编号规则，以及负责人补充的信息。相同信息尽可能使用一致的占位符。Markdown 按纯文本显示，已识别的链接地址替换为占位符；不展开或渲染 Markdown，因此不会因为去掉排版标记而拼接出新的姓名。图片仍需在原工作台中人工检查，预览明确提示图片内信息未处理。不会访问任何正文链接或读取图片文件。

当前增加有限的自然自我介绍姓名规则（如“我是李星云”“我叫……”）和宿舍楼栋加房号规则；同一姓名跨标题与正文尽量保持一致占位，新增 `counts.address` 地址计数。“我是李星云，2025010000，紫荆一号楼629A，大家来找我玩！”会变成“我是【姓名_1】,【学号_1】,【地址_1】,大家来找我玩!”。普通教室、只有楼栋的路线描述等保持可读。这是规则扩展，并非通用中文姓名或地址识别模型。

预览中的文本仍可能包含未知姓名、昵称、地址、非标准或变形的身份信息；规则也可能误替换普通文字。`externalReady` 固定为 `false`，预览成功不是安全外发证明，不产生任何通过或拒绝决定。目录列本身的特殊字符规范化差异也可能造成漏检。

## 数据与权限

- `POST /api/moderation/submissions/:id/privacy-preview` 仅接受 `expectedVersion` 和可选的 `extraTerms`（最多 50 项，每项最多 128 字符）。原稿只能由服务器读取；客户端不能提供替代正文、用户资料或图片地址。
- 每次重新校验当前负责人资格、待审状态、版本、证据期限。在同一短事务中锁负责人记录与稿件，避免权限撤销或人工处理的竞态；生成后再次按数据库时间检查到期。
- 目录查询只选择与稿件有关的 `full_name/student_id/email`。超过 500 个匹配用户时拒绝生成；不返回目录原值、身份映射或其他账号字段。
- 只有负责人可以调用。普通作者以及未列入负责人库的管理员不能调用；查看“我的提交”也不会显示操作入口。
- 响应使用 `Cache-Control: private, no-store`。原稿、补充词和占位映射不写入应用日志；预览不另存数据库、文件或浏览器存储。切换稿件、切换账号或退出页面后移除页面中的预览；迟到响应不会恢复它。
- 没有新增表、迁移、依赖或配置，也不读取 API Key。正常发表内容和审核证据不会因预览而改变或延长保留期限。

## 验收

在隔离测试电脑中用合成信息建立待审稿，检查姓名、学号、邮箱、手机号的替换，检查普通意见和批评仍保留；补充一个未命中的词后重新生成；含图片稿应明确显示图片尚未处理。随后通过或驳回稿件，确认原有流程正常。不要为了测试收集或外发真实敏感信息。

代码测试覆盖替换与重叠、同值占位、目录字段白名单、权限和版本、到期、错误不泄漏、补充词变化、账号切换及原有审核回归。真实浏览器使用实际前端和脱敏模块、合成 API 数据，验证桌面/手机和浅色/深色布局及无外部请求。MySQL 专项由 `node scripts/test-mysql-isolated.js --moderation-only` 纳入人工审核和隐私两套测试，使用新建的禁用 TCP 的隔离实例，要求两套均执行且不跳过。

首次预览版本的本机验证为相关测试 105 项、MySQL 专项 19 项通过，桌面/手机、浅色/深色 4 个场景通过并检查截图；测试电脑已确认可用，同时反馈自然姓名和宿舍地址漏检。本轮扩展与文字试审一并验收，详见试审说明。对实体编码、未闭合 Markdown 和新增规则的超长输入均保留有界或硬超时检查，预览不使用完整 Markdown 解析器。

## 下一阶段

文字试审已复用系统设置的一致快照，不把密钥传到浏览器，也不改变日常聊天模型。虚构内容的试审用于验证接口与效果，不代表真实用户内容已具备完整的自动外发条件。后续继续完成自由文本识别评测、图片本地处理、专用机器队列与异常转人工。短文本 p95 3–5 秒仍是实测目标，本预览不能证明该指标或合规判定准确率。
