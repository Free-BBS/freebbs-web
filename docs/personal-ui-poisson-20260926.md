## 羊毛：以有效喂养次数为时间轴

每次成功喂养增加独立的 Poisson(0.2) 份羊毛。连续 n 次喂养的总新增量服从 Poisson(0.2n)，长期平均每 5 条鱼约 1 份；不是“第五次必得”，也不是随机过程保底。一次约 18.13% 的概率至少长出一份，约 1.75% 的概率长出两份或更多。

分布定义与均值参见 [NIST 泊松分布说明](https://www.itl.nist.gov/div898/handbook/eda/section3/eda366j.htm)。这里的“时间”是成功喂养次数，不是自然时间；离线等待不会产出羊毛。

- 服务端加密随机源，客户端不能指定随机数或产量
- 在账户锁和已有事务中结算；请求成功后保存回执，同一请求重试不会重抽
- 喂养失败不消耗鱼、不改余额；库存溢出拒绝整笔操作，事务错误整体回滚
- 已有待剪及已剪羊毛全部保留；旧 `feed_progress` 保留为 0–4 兼容计数，不再作为奖励门槛或展示进度条，不需要改数据库表
- 每个北京时间自然日最多剪一份；每份羊毛摩擦收入 2 电元、橡胶棒 7 磁元且永久可用、鱼骨及饱腹规则保持不变
- 羊毛不进入仓库；牧场、商城的小鱼 / Max 说明和新手导引同步解释新规则

## 本地验证

`npm run preview:personal` 默认只监听 `127.0.0.1:3133`，所有资料、对话、资产均为演示，操作只影响内存，不连接线上、真实 AI 或数据库。

`npm run test:personal-ui` 验证随机分布、账户事务、幂等、每日上限和入口。

`npm run test:personal-ui:browser` 使用 `PUPPETEER_MODULE` 与 `CHROME_PATH` 指定本机测试运行时，覆盖主题、字体、字号、桌面及手机视口、断点来回切换和真实 DOM 交互。
