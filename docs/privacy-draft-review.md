# FreeBBS 隐私政策第一版审阅说明

2026 年 10 月 13 日。本说明供 FreeBBS 工作组审阅，不作为面向同学的政策正文。

第一版已按运营方确认的邮箱、名单来源、外部模型摘要及管理员导出方案编写。政策目标包括待上线的审核 Agent 和导出改进，因此需要先实现相应功能再让承诺生效；本轮仅保存文档，没有发布政策、推送 main 或启用正式审核。

## 阅读顺序

1. [隐私政策草案](privacy-policy-draft.md)：优先看名单来源、AI 处理、管理员访问、保存删除和权利请求是否符合运营意图。
2. [个人信息收集与使用清单](privacy-data-inventory-draft.md)：核对各功能的数据、访问范围和保存安排。
3. [外部服务清单](privacy-external-services-draft.md)：核对实际接收方和仍缺的供应商信息。

三份文件均为 v0.1 内部审阅稿。保留了实际缺口，不是只需填生效日期就可上线的文件。

## 已采用的决定

- 草案运营名称暂用“FreeBBS 工作组”；实际承担个人信息处理责任的主体仍需在正式发布前明确。
- 隐私联系渠道采用 `feedback@free-bbs.cn`；用户要求先按此使用，有变化再更新，不再重复询问是否选择此邮箱。实际收信验收、值守及响应流程属于上线准备。
- 注册名单由相关老师或院系提供，用于注册资格核对。没有推定提供方已经完成对同学的告知或取得同意。
- 无问芯穹正文摘要采用用户确认的原文，详细范围放入站内清单，并链接官方政策。
- 所有管理员保留必要调查中的 AI 对话导出资格，新增用户/会话/时间筛选、必填理由、服务器审计，与审核 Agent 同批上线。
- 审核证据保留 30 天，正常发布内容、元数据、备份及供应商记录分别处理。

## 下一轮需要决定的保留与删除方案

下表是供选择的运营方案，不是已经批准的期限，也不是对现有数据库执行清理的指令。

| 类别 | 建议方案 | 实现或核对要求 |
| --- | --- | --- |
| 账号及私人学习记录 | 在账号服务期间按功能保存，支持本人申请删除和注销；不以毕业为由默认立即删号 | 先定义注销与公开作品保留的关系，覆盖主库、发展库及文件 |
| AI 对话 | 优先提供按会话删除及申请清除能力，再决定是否采用固定到期期限；不先承诺永久保留或全部 30 天删除 | 包含消息内图片、文件引用和单独文件；历史使用目的结束时要有清理路径 |
| Max 完成文档 | 保留于用户使用该文件的必要期间，建立主动删除及不再被使用文件的清理方案 | 选择具体期限前先核对引用与重新分析需求，避免删文件后对话链接失效 |
| 未注册白名单 | 按院系或课程的邀请周期维护；邀请结束时清理不再需要的信息 | 具体提供方、周期、已占用资格记录与退出后是否可重注册需确定 |
| 问卷及活动资料 | 由活动说明约定结束后保留时间，只留必要汇总或处理记录 | 已有活动逐项核查组织方；不将组织内部记录默认公开 |
| 调查导出副本 | 调查及有关异议处理结束后 30 天内清理工作副本，可作为首版提案 | 仅为建议；依法保留的证据另行限定范围、期限和访问，审计不随正文副本一起删 |
| 导出操作审计 | 单独制定期限，只留操作者、理由、范围、数量、时间与结果，避免复制全文 | 与安全日志、调查证据、影响评估分别分类，不能直接套用某个统一法定期限 |
| 一般恢复备份 | 可先评估 30 天滚动窗口是否满足恢复需要，再确认实际策略 | 仅为建议；不能直接删除既有备份，先确认主库与附件的恢复和长期档案需求 |
| 隐私请求处理 | 首版采用邮箱人工受理；建议收到请求后 3 个工作日内确认接收，原则上在身份与必要信息齐备后 15 个工作日内反馈处理结果 | 时间为拟议服务目标，不是法定统一期限，也未获用户确认；复杂请求及时说明进度 |

相关网络日志有不少于六个月的法定要求，不能将其误用为保存所有对话全文的依据。影响评估记录的适用保留要求也与调查导出正文不同。[《网络安全法》第二十三条](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)、[《个人信息保护法》第五十五、五十六条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 名单来源的后续核对

“来自老师或院系”已确定；后续只补充具体提供方、实际字段、提供和更新方式、邀请范围，以及提供名单时适用的告知和合法处理依据。不需要传送完整学生名单供本次审阅。

名单可能在同学注册前已被导入，因此注册页上的确认不能追溯替代此前处理的依据。需要给被列入名单的人一个可查阅的说明和纠错、退出或删除请求途径，并限定名单管理人员。是否属于委托、共同处理或独立提供，要依据院系与工作组的实际安排，不能凭组织名称推定。[《个人信息保护法》第十三、十七、二十至二十三条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 尚不能写成确定承诺的内容

- 尚未落实的导出筛选、理由与服务器审计，以及全站政策版本和撤回流程。
- 未核实的全站统一加密、所有数据均在境内、所有资料仅本人可见、删除后所有副本立即消失。
- 无问 API 的固定保存天数、不用于训练和与本站同步删除。
- 校内授权接口的正式许可、所有 Info 或生成图片渠道都与主模型渠道相同。
- 邮箱已完成收信测试、既有用户已接受新政策或老师已代表学生同意全部数据处理。

## 从审阅稿到上线

1. 核对功能实际启用情况，补全主机、邮件、外部资源、模型及校内服务清单和存储地点。
2. 确定保留与受理方案，完成相应权限、删除、备份和导出功能；记录适用的数据处理约定及影响评估。
3. 建立公开政策入口、版本记录和适用场景的确认及撤回路径；已有用户的确认不能由系统自动补写。
4. 台式机用虚构数据检查上传前提示、拒绝与撤回、普通用户和管理权限、导出范围及审计、到期与删除效果。
5. 移除内部审阅标记和未决项目，填写正式版本与生效日期；政策及配套保护生效后，再按计划开启审核 Agent。

工程任务继续在[实施清单](privacy-decisions-20261012.md)跟踪；供应商询问提纲见[核对记录](privacy-verification-20261013.md#需要供应商明确的问题)。
