# 无问芯穹文字试审

人工审核工作台提供负责人手动调用的文字审核建议、本地姓名和宿舍地址识别。融合版新增版本化规则、证据解释与审计反馈，见[规则审核工作台](moderation-policy-workbench.md)。用户已授权将自己编造的测试内容发送给无问芯穹；页面默认使用本地脱敏文字，也可明确选择“虚构原文（仅测试）”。正常批评、投诉、学术讨论、引用及求助需要结合语境判断，不能仅靠敏感词定性。结果不是法律结论，也不会直接决定发布或处罚。

## 开启与配置

- 原有 `DISCUSSION_MODERATION_ENABLED=true` 继续有效；新增 `DISCUSSION_MODERATION_AI_TEST_ENABLED=true` 才显示试审入口，默认关闭。
- 还要求 `API_HOST` 与 `PUBLIC_WEB_URL` 都指向回环地址。例如测试电脑使用 `127.0.0.1` 与 `http://127.0.0.1:3000`。公开部署不能通过这两个测试开关直接启用当前实验入口。
- 读取当前测试网站自己的系统模型设置（`app_settings`、`system_secret_settings`）和服务器加密密钥。正式网站可以调用不代表测试库已配置；不会连接生产库或复制生产密钥。
- 管理员在测试网站“系统设置 → 模型与密钥”（`/system-settings/model`）查看配置状态并在页面内保存 API Key。API Key 不写进浏览器响应、聊天记录或更新包；服务器需要已有的有效 `SETTINGS_ENCRYPTION_KEY` 才能保存和解密。若提示加密配置缺失，应单独检查测试配置，不覆盖已有加密密钥。
- API Base URL、默认模型由系统配置管理。当前适配器只接受 `https://cloud.infini-ai.com/maas/v1`（允许尾部斜杠）。默认使用网站当前模型；可用 `DISCUSSION_MODERATION_AI_MODEL` 为试审指定单独的默认模型。负责人可在试审页按次选择型号，不改变聊天模型或其他负责人的选择。未配置时明确提示渠道配置问题。
- 无新增软件依赖。融合版新增 `068_moderation_policy_audit.sql` 的三张审计表，后端启动时幂等初始化。更新前备份测试数据库；不修改现有模型密钥或渠道配置。

## 使用与边界

负责人打开待审稿，在“无问芯穹试审（文字）”中选择输入方式，点击“调用无问芯穹试审”。只有手动点击才请求供应商。默认模式在服务端重新生成脱敏文本，补充隐私词只在本机参与替换；虚构原文模式直接使用服务端保存的标题和正文，补充词不会附加到外部请求。预览的 `externalReady:false` 仍表示规则不能证明完整脱敏，测试开关不改变这一能力声明。

“试审模型”列表复用 Max 的 `backend/ai-models.js` / `ai-model-catalog.json`，以部署的审核默认模型作为初始选项。没有另维护一份前端型号名单，也不挂载 Max 的图像收集或浏览器偏好控制器。选择只保留在当前待审详情中，每次请求显式携带该型号；切换型号会清除旧结果，正在返回的旧型号结果也会失效。初次加载或重新加载目录不会调用供应商；目录未就绪时禁用试审，可手动刷新目录后再选。

列表表示网站维护的候选型号，不代表当前 API 账号已验证全部型号，也不证明它们都能在 15 秒内给出有效审核 JSON。尤其固定思考的型号仍需实际测试。此轮不增加思考强度选择；带视觉能力的型号也只接收文字，不会因此发送图片。

展示三类文字判断：“未发现风险”“需要人工复核”“高风险”，以及分类、中文条目编号、原文证据、适用解释、不确定项、模型和耗时。当前 v3 的 28 条禁止项、11 类风险见[规则库](moderation-policy-sources.md)。两条心理关怀提示独立显示，不把正常求助当成违规。程序另行生成“建议通过／暂留人工复核／建议拦截”，这些都不会代替负责人点击通过或驳回。

切换稿件、账号、输入模式或模型会清除当前试审结果；已成功保存的历史通过独立面板查看。新结果必须保存到数据库才返回成功。历史与人工纠错继承原稿到期时间，最多保留至原稿创建后 30 天，不因后续试审延期。旧版页面内结果无法追溯补存。

含图片稿件可以测试文字部分，但请求不含图片、图片地址或像素，只携带有图标记。页面明确提示图片尚未机器审核；图片继续由人工检查。试审不替代通过/驳回，不产生自动发布、封禁或处罚，也不创建持久机器任务、额外通知或自动重试。

## 请求、校验与异常

- `GET /api/moderation/ai-models` 仅供已启用试审的当前负责人，返回 `defaultModel`、仅含 `id/label` 的 `models` 和 `settingsRevision`，响应禁止缓存。仅读取不含解密密钥的设置视图，不请求供应商；读完目录后再次验证负责人资格。
- `POST /api/moderation/submissions/:id/ai-test` 只接受 `expectedVersion`、`inputMode`、可选 `extraTerms` 和 `model`。身份来自登录认证；正文由服务器读取。省略型号保持原默认行为；指定型号须属于同次设置快照的可信目录。不存在的型号返回 400，不请求供应商；客户端不能提交地址、密钥、思考强度或图片覆盖项。
- 每次请求前后都验证负责人资格、待审状态、版本、证据有效期和内容摘要。读取快照的短事务在网络请求前结束；模型等待期间不锁住人工决定。人工已处理、权限撤销或证据到期后，迟到模型结果被丢弃。
- 一次请求读取一份模型设置快照，无静态密钥回退。选定型号、渠道凭据和设置版本保持一致，互不修改全局设置。业务材料只包含标题、正文、模式、脱敏类型计数及有图标记；不附加账号资料、用户目录、身份映射、补充词列表或图片资源。
- 固定 HTTPS 出口，拒绝重定向。供应商请求及响应体读取共用 15 秒超时，实际响应字节最多 64 KiB；融合版为规则证据将输出上限提高到 2200 tokens。每名负责人最多 1 个、单进程最多 2 个并发请求。
- 严格校验 JSON、固定字段、正常结束标记、规则与风险类别的对应关系、证据是否确实出现在本次发送的标题或正文中、关怀级别与规则的一致性。截断、拒答、工具调用、仅推理内容、错误结构均作为失败；不修复半段 JSON、不执行模型指令、不拿推理文本冒充结果。页面按纯文本显示理由。证据存在并不证明规则适用正确，语义仍需人工复核。
- 模型必须使用当前版本的中文条目编号。正常批评、普通求助不需要返回一条“允许规则”；只说明具体待核实事项而没有足够依据指向禁止项时，可以返回无风险类别的人工复核建议，但必须给出不确定项。关怀提示仍不能被当成违规类别。
- 400 为输入问题，403/409 为权限或稿件失效，429 为正在试审；503 为配置不完整，502 为模型/网络或结果无效，504 为超时。供应商原始错误、原稿与密钥不返回。已发起请求的 502/504 经再次权限、版本、到期校验并保存后，响应附带独立的 `reviewResult`，`assessment:null`，固定保留人工审核。完整 JSON 中可识别的风险等级、已知类别、当前规则编号和关怀等级可以作为未核实提示显示；不保存失败模型的理由、引文、未知标签或原始响应。失败后只能由负责人再次点击重试。

模型参数根据无问官方 [结构化输出](https://docs.infini-ai.com/gen-studio/api/text-generation/tutorial-structured-output.html) 与 [GLM thinking 参数](https://docs.infini-ai.com/gen-studio/api/text-generation/tutorial-reasoning/glm.html) 等型号说明核对。已确认型号使用相应结构和推理参数；未知型号使用 JSON 对象请求并做同样的本地严格校验，不猜测型号家族能力，也不在失败后自动改参数再次计费。型号可用性和最终兼容性仍需以测试账号的实际请求验证。

MiniMax M2.7 按 [官方说明](https://docs.infini-ai.com/gen-studio/api/text-generation/tutorial-reasoning/minimax.html) 使用 `reasoning_split:true`，将推理放在独立字段；审核结果仍只接受最终 JSON，不解析或回传推理字段。

Kimi K2.6 曾在测试账号返回 HTTP 400，诊断信息指向 `response_format/json_schema/schema` 无效。因此该精确型号改用 `response_format:{type:'json_object'}`，不在 `response_format` 中传递审核 schema；返回结果仍须通过完全相同的本地校验。输出约定 v2 为 JSON 对象模式在系统提示词尾部明确提供同源完整 schema，帮助模型遵守字段结构。GLM 等其他型号保持各自请求格式。不增加自动重试，也不能据旧诊断推断具体哪个 schema 关键字不兼容。实际输出效果仍需重新验证。

## 配置排查

“模型与密钥”保存成功只表示密钥写入了测试库，不会修改渠道地址。若原隔离配置仍为 `http://127.0.0.1:9/v1`，试审会在本机返回“审核模型渠道尚未正确配置”，尚未向供应商发送请求。需把测试配置的 `LLM_BASE_URL` 改为上述无问地址并重启后端。数据库已有 `llm_base_url/llm_model` 时优先于环境默认；文件配置正确但仍失败时，应只检查有效设置的 `configured/baseUrl/model/revision`，不要输出密钥、登录 token 或完整配置。

## v3 规则更新

当前规则版本为 `freebbs-policy-2026-10-09-v3`。政治条款细化为 9 条，性相关限制不以年龄为前提，旧 `未成年保护-001` / `sexual_minors` 仅保留历史显示、不能作为当前模型输出。当前类别共 11 个；未知或退役编号、类别仍按无效结果处理，不能用历史别名自动转成新判断。当前库由后端启动时读取，更新后需要重启。

## 验证与下一步

当前提示约定与安全错误诊断见[输出约定 v2](moderation-contract-v2.md)，[v1 文档](moderation-contract-v1.md)保留历史依据。规则版本不变，输出约定单独记录版本；明确类别集合必须完全对应所选禁止规则、纯关怀独立于违规。v2 补充 JSON 对象模式的完整结构提示、人工复核规则和关怀分级边界，并记录固定字段缺失及额外字段数量。批测错误详情提供安全诊断，网页试审错误消息仍保持固定文本；离线测试不证明实际模型稳定性。

旧版 Kimi 兼容修复和模型选择已由测试电脑操作者确认可用。融合版测试覆盖两种输入模式、GLM/Kimi 格式、无自动重试、非法规则或证据、矛盾标签、迟到结果、审计保存失败以及原有人工流程。测试使用合成响应，不以通过单元测试证明真实模型准确率。

融合版通过相关单元、服务/路由、页面和 MySQL 8.4.11 隔离专项检查，包括迁移重复执行、外键级联、重启后读取、撤权、并发幂等、人工纠错、导出与到期清理。未运行完整项目 CI，未使用真实供应商密钥调用 API。可复现命令见[工作台说明](moderation-policy-workbench.md)。

实际 MS Edge 浏览器使用真实脱敏模块、实际页面和合成接口，验证桌面/手机、浅色/深色、两种输入模式、GLM-5.1/Kimi K2.6 两种选择共 16 个场景，并检查各尺寸和主题截图。示例姓名、学号、完整宿舍地址正确替换；文字建议、模型理由纯文本显示、图片未审提示、模型/输入变更清除和账号切换隐藏均通过。目录刷新、失败重试和迟到目录响应另有页面测试覆盖。没有向外部供应商发送请求，也没有自动发布。

测试电脑更新后，先用虚构稿件分别试审两种模式，记录模型、耗时与合理性；检查规则编号与逐字证据、正常意见保护、心理关怀分级和人工通过/驳回。再保存一条人工改判并改写成虚构样例，导出后先预览，再明确执行回归脚本。规则提示比旧版长，之前单次 3–4 秒不能代表新版 p95；3–5 秒仍为首轮目标。图片 OCR/遮挡、自动队列、真实信息外发告知和上线策略属于后续工作。
