# 财务同步系统部署与备份

系统提供两个入口：`/development/finance/budget` 查看权限范围内的总预算，
`/development/finance/claims` 查看相关报销、代发及到账进度。它记录校内流程的进展，
不会替用户操作学校财务系统或发送代发邮件。

## 使用与授权

学习端与发展端共用人员、组织岗位和代表队关系，在管理员端“人员与组织”维护。
财务模块直接读取这些有效岗位，不再单独任命经费总负责人，也不维护第二套人员授权。
总预算表中的“预算目录”仅维护预算分类，不能给账号授权。

| 身份                             | 查看范围             | 可办理的事项                                                   |
| -------------------------------- | -------------------- | -------------------------------------------------------------- |
| 最高管理员、团委书记、团委辅导员 | 全部                 | 编辑批准预算、维护目录、导入预算、审核与备用提交记录           |
| 组织负责人                       | 本组织               | 只读预算和已提交款项，不附带审批权                             |
| 部门负责人                       | 指定部门或单支代表队 | 新建申请，修改本人草稿或退回记录，提交、撤回、确认本人申请到账 |
| 组织经费负责人                   | 本组织               | 记录报销已提交校财务                                           |
| 其他负责辅导员                   | 原有分管部门         | 查看进度，最终审核权仍由团委书记、团委辅导员承担               |

六个财务工作口为团委、学生会、科协、媒体中心、体育+代表队、BBS。
学生会负责人、财务负责人可看学生会各中心；体育中心负责人、主任额外可看全部代表队。
代表队来自既有代表队目录，使用实际 teamId 绑定；队长只能看本队，名称相同不会赋权。
科协经费负责人沿用“科协办公室副主席”。岗位撤销、停用、过期立即影响后续请求。
学习端管理员、发展端管理员可分别授权；普通管理员身份本身不赋予全系财务权。
发展端人员设置中，两端管理员及团委书记、团委辅导员、学生发展辅导员的全局任命由最高管理员维护，
普通发展端管理员只能维护其他组织岗位，不能通过给自己勾选辅导员获得额外权限。

预算由财务最终审核人按学年、部门、项目编号录入或修改。一个项目对应一个总额度池，
例如多笔购买均归入 `2-1-1`，无需逐条预算内容匹配；报销、代发各有独立额度，不自动互相挪用。
支持 Excel 模板及现有预算表导入：先预览映射、额度变化与逐行问题，确认后按学年、部门、项目编号更新。
未导入的项目、已有报销和到账记录保留；重复确认不会重复累加，错误分类必须映射后才能导入。
原始 Excel 不被修改，当前不提供回写。

部门先完成真实校财务上传或代发邮件，再在 BBS 保存申请并提交系内审批。
申请填写购买内容、数量、金额、收款人及学号、材料清单、外部流程凭据和日期；无需上传材料。
辅导员审核通过后自动进入校内审批。到账只由原提交负责人确认。草稿、退回、撤回不占用额度；
系内审批、校内审批、已到账各占一个互斥金额桶，剩余为批准额度减去这三个桶。
超支保留负余额并预警，不把代发额度自动抵给报销。预算页不显示收款人学号。

## 生产配置

在运行发展端 API 的进程环境中设置：

```dotenv
FINANCE_DATA_DIR=/var/lib/freebbs-development/finance
```

最高管理员初始 UID 存于 `packages/contracts/src/platform-authority.json`，当前为
`u_48370eb1aba453c7`。必须经过正常登录验证身份；不能靠请求参数、显示名称或前端标志获得权限。
首次登录自动具备双端管理和全部财务权限，无需先由其他人任命。普通管理员不能修改或停用这个账号的最高权限。
部署配置 `PLATFORM_ROOT_ADMIN_UIDS` 可增加根账号，不会移除明确任命的默认账号。
团委书记、团委辅导员自动具备双端管理及全系财务最终审核权；学生发展辅导员自动双端管理，财务仍按分管部门。
身份预览不能进入财务。旧 `finance.chief` 身份与财务目录中的历史 grants 不再产生权限。

生产是否配置财务存储只由私有目录配置决定；
没有获授财务身份的用户看不到财务内容。目录未配置时，生产财务功能保持关闭。
演示账号同样按共享岗位检查权限，不按账号名称绕过权限。

`FINANCE_DATA_DIR` 必须是独立、持久、非公开的绝对路径，不能位于 `uploads`、`public`、
`static`、网站构建目录或任何静态服务器映射内，也不能复用 `COLLECTIONS_UPLOAD_DIR`。
主站集成方式会公开服务上传目录，因此不能将财务 JSON 存入主站上传目录。
检查符号链接解析后的真实路径，并确认 nginx、Express 和文件下载接口都未公开此目录。

独立 systemd 部署可使用上面的默认目录；现有 API 服务允许写入
`/var/lib/freebbs-development`。首次部署创建目录并赋予运行帐号权限：

```sh
sudo install -d -o freebbs-development -g freebbs-development -m 0700 \
  /var/lib/freebbs-development/finance
```

主站集成部署须把同一个目录环境变量传给主站后端，并让后端运行帐号拥有目录。
不要将目录加入主站 `uploads` 的公开映射。独立 Docker Compose 已配置 `finance-data`
持久卷和运行帐号权限。容器重新创建后仍保留财务记录；财务身份通过系统设置维护。

## 完整备份

预算、目录和报销进度存放在财务目录中；人员岗位保存在共享数据库。现有 SQL 备份任务只备份数据库，不能代替文件快照。
备份时停止所有发展端写入进程，完成 SQL 导出后再创建包含财务目录的快照：

```sh
sh scripts/backup.sh /srv/freebbs-backups/development.sql
node scripts/data-snapshot.mjs create \
  --sql /srv/freebbs-backups/development.sql \
  --collections /var/lib/freebbs-development/collections \
  --finance /var/lib/freebbs-development/finance \
  --output /srv/freebbs-backups/development-complete-snapshot \
  --confirm DEVELOPMENT_WRITES_STOPPED
node scripts/data-snapshot.mjs verify \
  --source /srv/freebbs-backups/development-complete-snapshot
```

实际使用了独立素材或设置目录时，一并传入 `--festival`、`--sports`、`--settings`。
使用尚不存在的快照目标目录。脚本会校验每个文件的 SHA-256，并拒绝尚有写入锁、临时文件、
符号链接或财务目录与素材目录重叠的快照。旧快照仍可校验，但没有 `finance` 根的旧快照不包含财务数据。
组织岗位随发展端数据库备份；根账号配置、私有目录等运行配置另行保存在受保护的部署配置备份中。

## 恢复检查

先校验，再恢复到新的暂存目录：

```sh
node scripts/data-snapshot.mjs stage \
  --source /srv/freebbs-backups/development-complete-snapshot \
  --output /srv/freebbs-backups/development-restore-staging
```

暂存操作不会导入数据库或覆盖在线文件。停写后，由运维人员核对 SQL 和 `finance` 目录属于同一快照，
恢复到对应持久目录并保持私有权限，再启动服务。检查最高管理员、辅导员、组织负责人及普通学生的可见范围，
核对系内审批、校内审批、到账和剩余额度，确认未向未授权身份返回记录或学号。
