# 班级人员名单 API

该接口管理班级名单，不授予账号身份，也不修改旧活动中的参与人文字。名单与不可变版本快照存入既有组织组独立存储的 `organization-group/` 工作区记录，使用同一个文件锁和原子提交；无需另建角色或配置新存储目录。

所有路径以 `/api/development/v1/organization-group` 开头。响应均为 `{ "data": ..., "requestId": "..." }`，使用 `Cache-Control: private, no-store`，必须登录。

## 读取与维护

`GET /rosters/:classId`：班级必须已在工作区配置。团支书只能读取 `submitClasses(state, user)` 中的班级；既有 `viewsAll` 授权可查看全部已配置班级。返回：

```json
{
  "classId": "wu55",
  "revision": 1,
  "members": [
    { "id": "roster-member-001", "displayName": "同学甲" },
    { "id": "roster-member-002", "displayName": "同学甲", "studentId": "2026000002" }
  ],
  "updatedAt": "2026-11-15T12:00:00.000Z",
  "canEdit": true,
  "canImport": false
}
```

尚未保存的班级返回 `revision: 0`、空 `members`、`updatedAt: null`。同名成员保留不同 ID；不能用姓名作为去重键。学号不是必填字段。

`PUT /rosters/:classId` 完整替换该班当前名单，可增删或改名：

```json
{
  "revision": 1,
  "members": [
    { "id": "roster-member-001", "displayName": "同学甲" },
    { "displayName": "新加入同学" }
  ]
}
```

新成员可省略 `id`，服务端生成 UUID；编辑既有成员时必须保留 GET 得到的 ID。省略 ID 表示新记录，不按姓名猜测同一人。ID 绑定原班级，不能跨班复用；转班时应在新班级创建新记录，旧版本仍保留。可省略 `studentId`，空字符串也会被省略；每份名单中 ID 和非空学号不能重复。每班最多 2000 条，姓名最多 120 字符、学号最多 100 字符，不能包含控制字符。

普通团支书只能维护当前允许填报的班级；既有 `manages` 或 `canGrantClassSecretaries` 授权可维护全部班级。全局只读辅导员不因此获得名单写权限。所有预览身份禁止写入。写入排队取得工作区锁后再次认证并检查当前授权、班级配置及版本。版本冲突返回 `409 revision_conflict`，不会覆盖数据；前端应保留本地编辑，提示重新读取并由用户确认。

## 管理者 JSON 批量导入

`POST /rosters/import` 仅上述管理者/组织组授权可用：

```json
{
  "batches": [
    { "classId": "wu55", "revision": 0, "members": [{ "displayName": "同学甲" }] },
    { "classId": "wu54", "revision": 2, "members": [] }
  ]
}
```

返回 `{ "items": [班级名单DTO, ...] }`。这会替换指定班级的当前名单；空数组清空该班。每个班必须配置、每个班版本必须相符；一次不能重复班级或复用其他班成员 ID。整个批次先检查后在一个工作区事务中提交，任一失败均不修改任何班。一次最多 100 班、20000 条成员，另受 API 请求体大小限制。

## Excel 模板、预览与确认

组织组台账的“班级名单”页向现有管理者和有团支书授权管理权限的组织组同学提供 Excel 导入；原有团支书在活动填报中的名单选择与逐班增删功能保留。导入本身不创建账号、授权身份或修改历史活动记录。

1. `GET /rosters/import/template` 下载真实 `.xlsx` 模板，包括“班级名单”和当前“班级对照”工作表。首行为“班级、姓名、学号”，学号选填，模板学号列采用文本格式以保留前导零。
2. `POST /rosters/import/preview` 上传 `multipart/form-data`，文件字段名 `file`，可选字段 `mode` 只接受 `append` 或 `replace`（默认 `append`）；字段与文件先后顺序均可。接口先校验当前导入权限再接收文件，解析后再次认证。预览不保存名单或文件。
3. 预览返回 `OrganizationGroupRosterExcelPreview`：`mode`、`sheetName`、`rowCount`、`warnings`、逐班 `classes`（版本、前后人数、新增、改名、移除、保留人数），以及仅含有变化班级的 `batches`。用户核对并勾选确认后，将 `{ batches }` 原样提交给现有 `POST /rosters/import`；它在工作区事务中重新认证并核对每班版本。任一班版本变化返回 409，前端保留预览与文件，等待用户主动重新预览、再次确认，不自动覆盖或重试写入。

增量模式保留旧成员，只增加新成员。同一班级的非空学号与已有人员相同且姓名相同时跳过，姓名不同则拒绝，需先核对文件或主动切换替换模式。替换模式仅使文件涉及班级的名单以文件为准，其他班级不变；按同一班学号保留 ID，允许明确预览的改名，移除文件未列出的旧成员。无学号行始终视为独立新成员，不按姓名合并；替换时无学号旧成员会移除并建立新 ID，预览有显著提示。文件内同名人员分别保留，重复非空学号拒绝。空文件不能清空班级，逐班清空仍使用原有维护接口。

班级按已配置 `id` 或 `label` 精确匹配；名称重名或名称与另一班 ID 冲突时须填写唯一 ID，不模糊猜测或自动创建班级。读取名为“班级名单”的可见工作表；没有该名字时只接受单工作表文件。“班级对照”仅作参考，其他有数据的工作表会要求合并后重传，避免漏导。支持“班级/班级ID/班级名称”“姓名”“学号/学号（选填）”列名；必需班级与姓名，空行忽略。学号可为安全的非负整数或文本；超出整数精度、公式、缓存公式结果、超链接及其他对象值均拒绝，公式不执行、外部内容不加载。

上传最多 8 MiB，复用现有财务导入的有界 OOXML 检查（适配名单错误码/文案）：先核对 ZIP 中央目录、路径、重复条目、实际解压大小及 XML 范围，再交给 ExcelJS。单条目最大 10 MiB、总解压最大 40 MiB，不接收宏、加密或不支持的压缩结构。名单表最多 4999 条数据和 20 列，每班导入后最多 2000 人，最多 100 班；确认批次不超过 20000 人及 1 MiB JSON，超过时要求拆分文件。原始工作簿仅在受限内存中解析，不落盘，不在审计中记录姓名或学号。

模板、预览及最终确认都需要现行导入权限；普通同学和仅负责本班的团支书不能通过导入接口读取全班名单，所有预览身份禁止导入。返回使用 `private, no-store`。名单变更仍追加不可变历史快照，既有活动保留当时填写的姓名。

`GET /rosters/:classId/history` 使用与名单读取相同的当前班级权限，返回 `{ "classId": "wu55", "items": [{ "revision": 1, "members": [...], "updatedAt": "..." }] }`，包括当前已提交版本。每次成功写入追加新快照；后续改名、删人不会重写旧快照或旧活动记录。未授权用户不能读取名单、历史或学号，工作区 DTO 不包含这些名单。
