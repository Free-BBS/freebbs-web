# 个人成长档案与小程序联调

成长档案 Web 页面位于 `/development/growth`。登录用户通过 `GET /api/development/v1/growth/summary` 读取自己的统计；服务端从认证结果取得 UID，不接受客户端指定其他人的 UID。响应包含总次数、各组织领域次数、成就称号及活动足迹。

当前数据来自发展端活动报名：只统计未取消报名，且活动状态为 `finished`、`archived`，或已过结束时间的 `published` 活动。系统还没有签到或到场核验，因此页面将这些数字明确标作“已结束的活动报名”，不能当作实际到场次数。领域按活动所属组织归类，并不是活动主题分类。称号规则目前为 1 次、5 次报名经历和 3 个不同领域；全部由服务端根据同一份数据计算。

小程序即使尚未发布，也可以在开发阶段联调接口和数据映射。要接入其活动经历，需要明确小程序代码或 API 地址、活动与报名数据结构、唯一用户标识与主站 UID 的映射方式，以及取消报名、实际到场和重复记录的处理规则。先在测试环境用测试账号联调；有可核验的到场记录后，再把“报名次数”和“实际参与次数”分开显示。未建立身份映射前，不应把小程序提交的任意 UID 当作可信用户身份。
