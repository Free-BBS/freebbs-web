# 信息与咨询统一信息流改造设计

日期：2026-09-24

## 目标

将发展端“信息与咨询”升级为统一的信息发布与反馈中心。页面借鉴主站讨论区的信息层级、紧凑卡片和详情讨论体验，同时保留发展端现有的公告发布、咨询提交、分诊、处理和状态流转能力。

改造后的页面需要同时满足以下目标：

- 官方部门能够发布、编辑、置顶和归档信息。
- 同学能够自行选择提交公开反馈或私密咨询。
- 公开反馈允许其他同学回复、补充和点赞。
- 私密咨询只允许提交者和有权限的负责人查看与回复。
- 官方信息、公开反馈和用户自己的私密咨询出现在同一信息流中，通过视觉标签和访问控制区分。
- 桌面端和移动端均保持卡片规整、信息密度适中且无横向溢出。

## 页面结构

“信息与咨询”使用统一信息流作为默认入口。

页面顶部是一块简洁页头，包含标题、用途说明和两个主要操作：

- “提交反馈”：所有已登录用户可见。
- “发布信息”：仅具备公告创建权限的用户可见。

页头下方提供筛选项：

- 全部
- 官方发布
- 公开反馈
- 我的咨询
- 处理中
- 已解决

桌面端主体由信息流和窄辅助栏组成。信息流承载所有可见内容；辅助栏展示当前用户的反馈状态概览，以及授权处理人员可见的待处理数量。移动端将辅助栏内容折叠到信息流顶部。

发布和编辑操作使用抽屉或对话框，避免表单长期占据页面空间。点击信息流卡片进入独立详情页，详情页展示完整正文、互动记录和处理状态。

## 信息流卡片

所有卡片共享相同的基础尺寸、间距、圆角和文字层级，避免不同类型形成互不相关的视觉模块。

### 官方发布

- 显示“官方发布”标签、发布部门、发布时间和正文摘要。
- 使用金棕色细边、局部底色或左侧强调线突出身份，不使用大面积高饱和背景。
- 支持点赞与回复。
- 授权人员可置顶、编辑、发布和归档。

### 公开反馈

- 显示反馈分类、提交者、处理状态、摘要、点赞数、回复数和更新时间。
- 其他已登录用户可以点赞和回复。
- 提交者发布的后续内容标记为“补充说明”。

### 私密咨询

- 与公开反馈使用相同的基础卡片结构。
- 显示锁形图标和“仅你与负责人可见”说明。
- 不显示公开互动统计。
- 只有提交者、具备相应范围处理权限的负责人和平台超级管理员可以读取与回复。

## 提交与可见性

提交反馈时，用户先选择可见性：

- 公开反馈：其他同学可以查看、点赞和回复。
- 私密咨询：仅提交者和授权负责人可以查看与回复。

随后填写分类、标题和正文。选择公开反馈时，界面明确提示内容会对其他同学可见。

公开反馈尚未产生回复时，提交者可以修改可见性。产生回复后不允许直接改为私密，避免已经公开的讨论突然消失。私密咨询改为公开需要提交者明确确认。

## 互动与状态

公开反馈和官方发布支持点赞与回复。回复允许一层嵌套，避免形成难以阅读的深层评论树。

反馈状态沿用现有业务流程：

1. 待受理
2. 处理中
3. 已解决
4. 已关闭

状态使用小型标签表达。状态变化在详情页形成简短记录，包括操作时间和操作身份。负责人回复使用“官方回复”或部门身份标签。

## 数据模型

保留现有公告和咨询实体，新增统一读取层，不把发展端业务直接绑定到主站讨论区的数据表。

### 咨询可见性

咨询记录增加 `visibility` 字段，取值为 `public` 或 `private`。已有咨询迁移后默认设置为 `private`。

### 回复

新增信息回复实体，至少包含：

- 目标类型：公告或咨询
- 目标 ID
- 作者 UID
- 父回复 ID，可为空且只允许一层嵌套
- 类型：普通回复或补充说明
- 正文
- 创建时间和更新时间

补充说明只能由咨询提交者创建。

### 点赞

新增信息点赞实体，以目标类型、目标 ID 和用户 UID 组成唯一约束。重复操作切换点赞状态，不增加重复记录。

### 统一信息流

新增统一信息流读取接口，将公告和咨询投影为带类型字段的联合结果。接口负责：

- 根据当前用户过滤不可见的私密咨询。
- 按置顶、更新时间和创建时间排序。
- 返回互动统计、当前用户是否已点赞以及必要的处理状态。
- 支持类型、状态和“仅我的”筛选。

## 权限

公告创建、发布、编辑和归档继续使用现有公告权限。

反馈分诊、负责人分配、官方回复和状态流转继续使用现有咨询处理权限，并对记录范围执行后端校验。

访问规则如下：

- 官方发布：所有允许访问发展端的用户可读。
- 公开反馈：所有允许访问发展端的用户可读；已登录用户可点赞和回复。
- 私密咨询：提交者、具备记录范围处理权限的负责人和平台超级管理员可读。
- 前端隐藏按钮只用于界面表达，所有读取和写入权限均由 API 再次校验。

## 前端组件边界

将当前信息页面拆分为职责清晰的组件：

- `InformationHubPage`：加载统一信息流并协调筛选、分页和状态。
- `InformationHubHeader`：标题、状态概览和主要操作。
- `InformationFeedFilters`：类型、状态和“仅我的”筛选。
- `InformationFeedCard`：统一渲染官方发布、公开反馈和私密咨询。
- `InformationComposer`：创建公告或提交反馈的抽屉。
- `InformationDetailPage`：正文、互动、状态记录和管理操作。
- `InformationReplyThread`：回复、补充说明和一层嵌套回复。

现有公告、咨询、分诊和提案路由保留兼容入口。默认 `/information` 跳转或渲染统一信息流；旧入口仍可用于聚焦管理任务。

## 错误与并发处理

- 点赞使用即时界面反馈；请求失败时回滚并显示短错误提示。
- 发布、回复、负责人分配和状态变更等待服务器确认后再更新界面。
- 状态冲突返回服务器当前状态，前端重新加载对应记录并提示用户。
- 信息流加载失败时保留筛选条件，提供明确的重新加载操作。
- 私密记录权限变化后，后端返回拒绝访问，前端移除缓存中的对应记录。

## 视觉方向

视觉语言借鉴主站讨论区：

- 使用紧凑、规整的列表卡片代替松散的大块表单。
- 卡片采用轻边框、克制阴影和清晰的标题、摘要、元信息层级。
- 官方身份使用金棕色点缀；公开反馈使用中性表面；私密咨询使用锁形标识和低饱和提示。
- 悬停只提升边框和阴影，不使用大面积高饱和颜色。
- 明亮和暗色模式使用同一结构，通过主题变量调整表面、文字和边框。

## 测试与验收

自动测试覆盖：

- 统一信息流排序、筛选和分页。
- 旧咨询迁移后的默认私密可见性。
- 公开反馈、私密咨询和官方发布的读取权限。
- 回复、补充说明、一层嵌套限制和点赞唯一性。
- 公告和反馈原有编辑、发布、分诊及状态流转能力。
- 点赞失败回滚、状态冲突和加载失败恢复。
- 桌面与移动导航、卡片布局、抽屉和详情页无横向溢出。

验收时应确认：普通用户无法通过直接 API 请求读取他人的私密咨询；公开反馈可以正常回复和点赞；官方信息在统一信息流中易于辨认；移动端完成提交、筛选、回复和处理操作时无需横向滚动。
