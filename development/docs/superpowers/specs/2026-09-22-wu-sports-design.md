# 「無体育」模块设计

**日期：** 2026-09-22
**状态：** 已确认

## 目标

将现有“体育代表队”升级为“無体育”模块。模块首页首先展示高亮的“马杯立刻看”，随后展示原有体育代表队。比赛栏目提供按日期横向切换的时间线；代表队详情页提供由本队队长维护的图文风采页面。

## 信息架构

- 侧栏入口名称改为“無体育”，沿用现有体育图标、路由和访问范围。
- “無体育”首页首屏为高亮的“马杯立刻看”入口，并展示当天赛事摘要。
- 原有体育代表队卡片整体下移，行为保持不变。
- “马杯立刻看”进入独立赛程页。
- 每个代表队详情页保留基本介绍、训练信息、成员和签到，并新增“代表队风采”。

## 马杯立刻看

赛程页顶部为可左右滑动的日期选择条，默认定位今天。选中日期下方显示一根纵向时间轴，比赛卡片沿时间轴左右交错排列；窄屏改为单侧排列。比赛状态根据开始、结束时间自动计算为“即将开始”“进行中”“已结束”，正在进行的卡片和时间点使用模块强调色。

比赛包含：名称、封面图、开始时间、结束时间、地点、可选直播链接、可选回放链接、创建人和更新时间。封面可选，缺省时展示统一赛事占位图。直播和回放链接在新窗口打开，并使用安全的外链属性。

所有体育中心部员、部长和负责人均可创建比赛。普通部员只能修改和删除自己创建的比赛；体育中心部长、负责人和平台管理员可以管理全部比赛。所有已登录的发展端用户均可查看赛程。

## 代表队风采

每支代表队只有一份当前风采页面。页面正文以 Markdown 保存，编辑器提供标题、粗体、引用、列表、链接、分隔线、图片上传与图片说明工具，并提供实时预览，使用者不需要直接掌握 Markdown。

渲染复用主站课程模块的 Markdown 与 KaTeX 思路，但本期不支持完整 LaTeX 文档编译。服务端限制正文长度，图片仅接受 JPEG、PNG、WebP，并校验真实文件类型和大小。渲染前过滤危险 HTML、脚本、事件属性和不安全 URL。

拥有对应 `sports_team` 范围 `sports.team_captain` 标签的队长只能维护本队风采；体育中心部长、负责人和平台管理员可以代为维护。其他用户只能查看。

## 数据与接口

- 新增 `sports_matches`，记录赛事字段、创建人和作用域。
- 新增 `sports_team_showcases`，以 `team_id` 唯一约束保存当前正文及更新人。
- 新增赛事封面与风采图片的受控媒体存储；媒体接口要求登录并校验文件元数据。
- 赛事列表接口按日期范围查询；比赛状态仅在响应层按服务器时间推导，不持久化易过期状态。
- 所有写接口同时执行服务端权限校验、字段校验和审计记录。

## 视觉与交互

保持发展端与主站一致的明暗主题、圆角、边框和字体。栏目入口采用较鲜明的体育强调色，但仍使用现有设计变量。日期条支持鼠标滚轮、触控滑动和键盘焦点；时间线、编辑器和按钮满足窄屏使用。

### 视觉精修补充（已确认）

- 精致程度与主站一致，减少装饰数量，所有卡片使用统一边框、圆角、间距和字体层级。
- “马杯立刻看”首发卡片加入原创的单色运动象形人物，不使用奥运会官方图形或标志。
- 日期选择使用独立卡片；纵向时间线的每场比赛独占一行并左右交替，禁止同一行挤放多场比赛。
- 比赛上传按比赛信息、时间地点、媒体内容分组，封面上传区提供即时预览。
- 风采编辑器提供清晰工具栏、图片拖放区、编辑与预览区域；窄屏切换为单栏。
- 桌面、平板和手机宽度均不得产生页面级横向溢出；长标题、长地点和长链接必须安全换行或截断。

保存风采前在浏览器完成预览解析，服务端再次校验内容和图片引用。保存成功后更新预览；失败时保留未提交正文。赛事表单明确标注必填项，链接字段允许留空。

## 验证

- 契约、数据存储和迁移测试覆盖赛事与风采唯一性。
- 权限测试覆盖体育部员自有赛事、部长全量管理、队长队伍范围和越权拒绝。
- API 测试覆盖时间范围、文件类型、字段长度、URL 和错误响应。
- Web 测试覆盖日期滑动、状态计算、交错时间线、创建表单、风采编辑与只读视图。
- 运行类型检查、单元测试和相关 Playwright 流程，并人工检查明暗主题与移动端布局。
